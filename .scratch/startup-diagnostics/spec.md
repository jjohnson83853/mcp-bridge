## 2. REQUIREMENTS

**R1 — Surface unclassified startup failures with a typed, sanitized cause.** Exactly one startup-failure line per failing exit, zero on graceful shutdown; additive envelope change only; bounded static cause; the genuine unknown stays a distinct class.

- **R1.1 (→ AC1)** An otherwise-unclassified startup error — not a `config.Diagnostics`, not a publication failure, and not one of the pre-existing direct `startupFailure` classifications — is classified to a specific `error.code` naming the stage, plus a bounded `startup_stage` identifier, a bounded `startup_cause` enum value and a static sanitized remediation. The classification applies only to errors that belong to one of the four stage classes; an otherwise-unclassified error that belongs to none of them stays `internal_error` with neither key (R1.5, AC5) and is never given a stage-bearing code. The ticket item 1 `sanitized cause summary` is exactly these two bounded fields: the class-level static `error.remediation` (naming the stage's failure class) and the optional closed-enum `startup_cause` (§4.3); the cause text itself is never serialized. Raw runtime error text is never serialized. Only the four stage classes (`snapshot_recovery`, `catalog_loop_start`, `catalog_loop_drain`, `listener_serve`) emit `startup_stage` and `startup_cause`; the six established codes (`state_directory`, `jwks_cache`, `embedding_provider`, `tool_surface`, `listener_bind`, `catalog_loop`) remain byte-identical and stage-less — their records omit both the `startup_stage` and the `startup_cause` key. The pre-existing non-`startup_failed` codes are not startup-failure classifications and are unchanged: `snapshot_unavailable` is the code of the `startup_snapshot_rejected` degraded warning (serve.go:72; `wiring.go:486-492`) and `cli_usage` is the code of the separate `cli_usage_failed` CLI event (`cliUsageFailure`, startup_failure.go:81-88; main.go:41/:45); neither appears in a `startup_failed` line. `internal_error` remains the `startup_failed` code for every genuinely unknown startup error.
- **R1.2 (→ AC2)** Known stage paths: quarantined snapshot recovery (`storage.ErrSnapshotUnrecoverable`, serve.go:164-166), catalog loop start (`loop.Start`, including admission/persist refusal), catalog loop drain (drain-budget expiry), listener serve (`serveListener` non-nil, non-`http.ErrServerClosed`). Snapshot recovery plus at least two other stages produce distinct codes in tests; catalog loop start and listener serve are proven by full-path `serve` tests (real `runContext` exits), not constructor-only units; the listener proof uses a seam whose override closes the named listener and returns the synthetic error immediately, so nothing waits on readiness of the failing listener (§4.7).
- **R1.3 (→ AC3)** `schema_version` stays 1; the only new envelope fields are optional `startup_stage` and optional `startup_cause` (both `omitempty`); the field union grows 130→132 in lockstep (`envelopeFieldNames`, `docs/logging-contract.md`, `internal/observe/log_test.go`, and the `config_envelope_test.go:168` count pin); existing constructors emit byte-identical records (neither key present). Four operator-visible classifications are added, all documented in contract + changelog (§7 lists the operator actions for all four): (1) `snapshot_recovery` — quarantined-unrecoverable startup exits (`storage.ErrSnapshotUnrecoverable`, serve.go:164-166 → `snapshotRecoveryFailure`, per AD1), which reclassifies `state_directory`→`snapshot_recovery`; (2) `catalog_loop_start` — every `loop.Start` error that is neither a publication failure (`service.ErrPublicationFailed`, loop.go:165) nor a configuration diagnostic (`*config.Diagnostics`, returned at loop.go:137-140 and intercepted by serve.go:405-409 before the classifier, so `runContext` reports it as `config_validation_failed`), i.e. the admission/persist refusal at loop.go:157-161, not only the disabled-quarantine admission/persist path, which reclassifies `internal_error`→`catalog_loop_start` (the current pin: snapshot_recovery_test.go:472); (3) `catalog_loop_drain` — drain-budget expiry, the synthetic error at serve.go:397, which reclassifies `internal_error`→`catalog_loop_drain`; (4) `listener_serve` — `serveListener` returning a non-nil error that is not `http.ErrServerClosed` (serve.go:352, :414-421), which reclassifies `internal_error`→`listener_serve`. Reclassifications (1) and (2) are the two previously documented compatibility changes; (3) and (4) are the two additional classifications this revision enumerates so the inventory is complete. `state_directory` is not repurposed — it keeps its meaning for `storage.Open` failures (serve.go:154-156); `internal_error` remains the code for every genuinely unknown startup error.
- **R1.4 (→ AC4)** No secret resolved from a secret reference, no bearer token, and no raw cause text ever appears in the emitted line; tests assert this using a secret fixture loaded from a test config, not a literal inside a cause. `resource.path` (the configured state directory) and `resource.listener`/`resource.address` (the configured listener name and listen address) are configured non-secret fields, emitted verbatim for `snapshot_recovery`/`listener_serve`; the guarantee covers secret references and bearer tokens, not configured non-secret values; a real failing startup path is exercised too: a config whose `bearer_tokens` resolve from an env secret sentinel, a corrupt snapshot with quarantine disabled, and a full `runContext` exit 1 must emit exactly one `startup_failed` line whose stderr contains neither the sentinel nor raw cause text; `startup_stage` and `startup_cause` are closed enums and never carry cause text.
- **R1.5 (→ AC5)** A genuinely unknown error still emits `internal_error` (`report this failure; no specific class matched`) with neither the `startup_stage` nor the `startup_cause` key; it is never silently mapped to a named stage. The raw non-unrecoverable `recoveryErr` return (serve.go:167; unreachable in practice — recovery.go:77-79 yields a non-unrecoverable error only for a nil/closed store, excluded by serve.go:154-156) stays unclassified and keeps `internal_error`.
- **R1.6 (→ AC6)** Graceful shutdown (context cancellation; clean `loop.Start` returns nil, loop.go:190; `ErrServerClosed` listeners, serve.go:414-421) exits 0 with no `startup_failed` line: stage wrapping is nil-preserving.

**Non-goals (owner-deferred):** last-known-good fallback; strict-mode `config_loaded`; secret-resolution changes; serialization redesign; deployment changes; retries/fallback/reload behavior changes; new dependencies; new event names. `config.Diagnostics`, `publication_failed` (`startup_publication_failed`), and every other existing code (`jwks_cache`, `embedding_provider`, `tool_surface`, `catalog_loop`, `listener_bind`, `internal_error`, `state_directory`) behaves exactly as today except the four documented classifications above (reclassifications `state_directory`→`snapshot_recovery` and `internal_error`→`catalog_loop_start` for the two previously documented paths, plus `internal_error`→`catalog_loop_drain` and `internal_error`→`listener_serve`); `snapshot_unavailable` (the `startup_snapshot_rejected` warning code, serve.go:72) and `cli_usage` (the `cli_usage_failed` CLI event code, startup_failure.go:81-88) are not `startup_failed` classifications and are unchanged.

## 4. DESIGN

### 4.1 Classification flow
`serve` wraps each unclassified source error in a `*startupStageError` carrier (fields `stage, listener, address string`, `cause error`; `Error()` → `cause.Error()`; `Unwrap() []error{cause}`):
- serve.go:339 — `loopErr <- carryStartupStage(loop.Start(ctx), startupStageCatalogLoopStart, "", "")`.
- serve.go:341-353 — the listener loop's anonymous struct (:341-344) and the goroutine parameter type (:348-351) gain `name` and `address` fields, and the two positional struct literals (:345-346) are updated to named fields: `{name: "inbound", server: inboundServer, listener: inboundListener, address: settings.HTTPListen}` and `{name: "operations", server: operationsServer, listener: operationsListener, address: settings.OperationsListen}`; :352 becomes `listenerErr <- carryStartupStage(serveListenerFn(running.server, running.listener), startupStageListenerServe, running.name, running.address)`.
- serve.go:397 — `firstError(failure, carryStartupStage(errors.New("the catalog loop did not drain"), startupStageCatalogLoopDrain, "", ""))`.
- serve.go:393-398 — the drain re-read passes already-wrapped values through `firstError` (nil-safe, unchanged).

`startupFailureForError` scope (startup_failure.go) — the classifier covers THREE carrier stages only; `snapshot_recovery` is not a carrier stage:
1. `errors.Is(err, service.ErrPublicationFailed)` → `startupPublicationFailure()` (unchanged; no stage).
2. `errors.As(err, &stageErr)` → closed switch on `stageErr.stage`: `catalog_loop_start` → `catalogLoopStartFailure()`; `catalog_loop_drain` → `catalogLoopDrainFailure()`; `listener_serve` → `listenerServeFailure(stageErr.listener, stageErr.address)`; any other value → `fallbackStartupFailure()` (defensive; never invents a code).
3. else `fallbackStartupFailure()`.

`snapshot_recovery` never reaches the classifier: AD1 returns a `startupFailure` value directly at serve.go:165 (the quarantined-unrecoverable `ErrSnapshotUnrecoverable` route, the only reachable snapshot-recovery failure path), so main.go:57-60's `errors.As(err, &failure)` recognizes it with no carrier and no classifier involvement; a test author must not add a `snapshot_recovery` carrier — the switch has no such case and it would fall through to `fallbackStartupFailure()`. The `*config.Diagnostics` assertion is `errors.As` on the carrier inside `serve` (serve.go:405-409), not a classifier result: a carrier wrapping a `*config.Diagnostics` unwraps to it, so serve.go:405-409 wins before :409 unchanged, and `startupFailureForError` is never asked to classify it. `firstError` keeps the first (already stage-carried) error. serve.go:154-156, `jwksCacheFailure`, `embeddingProviderFailure`, `toolSurfaceFailure`, `catalogLoopFailure`, `listenerBindFailure` are unchanged direct `startupFailure` returns recognized by main.

Bounded `startup_cause` derivation (revision 7) — a second closed enum, set on the same `startupFailure` value and emitted only when non-empty: `snapshot_recovery` → `snapshot_unrecoverable` (static, set by the direct-return constructor); `catalog_loop_drain` → `drain_budget_exceeded` and `listener_serve` → `listener_serve_failed` (static, set by the classifier's closed switch); `catalog_loop_start` → `admission_persist_failed` when `errors.Is(err, storage.ErrCorrupt)` (the untrusted-snapshot persist refusal chain at reload.go:728 → store.go:313-325) and `generic_loop_start` otherwise. The documented domain also lists `publication_wrap_failed`, which the classifier never emits: a carrier whose chain matches `service.ErrPublicationFailed` is intercepted by branch 1 and reported as `publication_failed` with no stage and no cause, so that value stays documented-but-intercepted and is pinned by a classifier assertion. No cause value is derived from error text.

### 4.2 Nil-preserving wrap (CR1 #5)
`carryStartupStage(err error, stage, listener, address string) error` returns `nil` when `err == nil`, else `&startupStageError{…}`. Verified consequences: clean `loop.Start` shutdown (loop.go:190 returns nil) sends nil; `serveListener`'s `ErrServerClosed`→nil (serve.go:414-421) sends nil; `firstError` ignores nil; `failure == nil` → `serve` returns nil → `runContext` exits 0 with no line.

### 4.7 Listener full-path seam (revision 7)
`serveListenerFn` (AD2) is overridden by `TestStartupListenerServeFailureClassified` with defer-restore. The override compares `listener.Addr().String()` with the configured inbound address and, for that named listener only, executes `_ = listener.Close()` and returns the synthetic non-`ErrServerClosed` error immediately; the other listener's call runs the real `serveListener` and serves normally. No pre-serve readiness or block gate exists: nothing waits on the failing listener, and its closed address is refused immediately.

Deterministic sequence: (i) build the config with `writeBridgeConfig` on `freeAddress` ports; (ii) start `runContext` in a goroutine with a buffered result channel; (iii) bounded-wait with `waitFor` (serve_test.go:484-494) until the served listener's readiness probe stops succeeding — the drain's `server.Close`/`Shutdown` (serve.go:383-384) closes both servers, so this observation follows the select (serve.go:357-363) consuming `listenerErr`; (iv) bounded-wait on the result channel with `time.After(20 * time.Second)` — the drain's 10s `shutdownTimeout` budget (serve.go:29) bounds the wait because the loop is never cancelled; (v) assert exit 1, exactly one `startup_failed` line, `error.code`/`startup_stage` `listener_serve`, `startup_cause` `listener_serve_failed`, `resource{listener,address}` equal to the configured named listener, and the emitted row equal to `loggingContractClassRow(document, "startup_failed", "listener_serve")`. The test never cancels the run context: cancelling before the select consumes `listenerErr` would let the select take `ctx.Done` and return nil (serve.go:405-409), so the exit wait replaces the race.
