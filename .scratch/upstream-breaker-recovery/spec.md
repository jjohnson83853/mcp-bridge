# Upstream Breaker Recovery — Discovery-Probe Close Path (SpecDD, feature `upstream-breaker-recovery`)

## 1. STATUS
Spec ID `upstream-breaker-recovery`, revision r5. State: **DRAFT** (ready for staged review; no execution authorization). Objective: give a latched-open per-server circuit breaker a reachable, execution-free close path through the existing discovery leg, so a returned upstream clears without a process restart and without replaying any unadmitted tool call. Evidence scope: incident `incident-2026-11-14.md`, ticket `issues/01-breaker-discovery-probe-recovery.md`, backlog findings 8–10. ## 2. REQUIREMENTS
<!-- specdd:requirements:start -->
**R1 (core).** A latched-open per-server breaker (opened by `RecordFailure` reaching `threshold`) MUST regain a reachable close path through the non-executing discovery leg, with no process restart and with zero replay of unadmitted tool executions. `BeginProbe()` is today the only close path and has zero production callers; this requirement adds its first caller.

**R2 (probe admission and completion).** `Dedicated.Discover` MUST claim the single half-open probe via `ServerClient.BeginProbe()` before it acquires a session or lists tools, exactly when the breaker is open, `openDuration` has elapsed since `openedAt`, and no probe is active. It MUST complete the claim exactly once: discovery returning nil error → `complete(true)`; any discovery error (initialize/tools_list/status/malformed/timeout/cancellation) → `complete(false)`. Completion MUST be installed with `defer` (set-once) so it fires on every return path and during panic unwinding. When the breaker is closed, cooldown has not elapsed, or a probe is already active, `BeginProbe` denies the claim and `Discover` performs ordinary discovery with **no** breaker mutation.

**R3 (strictly non-probing tool path).** `AdmitCall` and `CallTool` MUST NOT claim, complete, or replay a probe. While the breaker is open or half-open they reject with `backend_unavailable` / execution state `not_started`, dispatch zero upstream calls, and never re-execute the previously-failed call.

**R4 (unchanged session acquisition).** The probe MUST reuse `Discover`'s existing acquisition verbatim: `stateless:true` (default) opens a fresh ephemeral connection per probe (`client.Connect` + `defer session.Close()`); `stateless:false` reuses the runtime's cached session from `sessionFor`. No eviction, reconnect, or new session policy is introduced.

**R5 (both discovery legs).** Periodic refresh and SIGHUP/reload invoke the same `in.deps.Discover` → `upstreamRegistry.discover` → `client.Discover`, so both legs may recover a latched breaker; recovery is not tied to one trigger.

**R6 (single probe, ownership precedence, safe overlap).** At most one probe is in flight per server, enforced by the discovery wrapper's **own single-flight probe ownership** and NOT by the breaker's `probeActive` alone — because a concurrent failure writer (`RecordFailure` for authentication, or a threshold-reaching transport/malformed/deadline failure, from a previously admitted tool call or `GetPrompt` request) clears `probeActive`/`halfOpen` mid-probe. `BeginProbe` MUST be invoked only by the current owner while it holds ownership; a concurrent `Discover` that cannot acquire ownership runs ordinary discovery and mutates no breaker state. Concurrent failure writers may restart the breaker mid-probe but MUST NOT transfer probe ownership. The owner's single deferred completion is applied last and is authoritative for the transition (success → close; failure → restart cooldown); because at most one probe ever exists, no completion can clear a *different* probe's reservation. Tool calls MUST remain rejected (`backend_unavailable`/`not_started`) for the entire duration of any active probe, including while an owner probe is in flight after a mid-probe failure. A cancelled/deadline-truncated probe completes as failure exactly once and leaves no probe reserved.

**R7 (existing telemetry only).** Observability MUST reuse existing signals: a failed probe already emits the per-server `upstream_discovery_failed` record captured from the `*observe.Logger` the discovery actually uses; a successful probe is evidenced by the existing refresh/`backend_complete` records and the existing `bridge_catalog_refresh_total` series. No new log event, metric, label, or envelope field is added.

**R8 (stateful limitation = separate scope).** The cached-session wedge under `stateless:false` (`sessionFor` never evicts on transport failure) is documented and explicitly out of scope; it is backlog ticket 2 ("Evict the cached upstream session on transport failure"). It MUST NOT be silently fixed or widened here.

**Non-goals.** No session eviction/reconnect (ticket 2); no refresh-failure attribution fields (ticket 3); no read-only pin expansion (ticket 4); no new configuration setting; no change to breaker threshold/`openDuration` defaults or to `RecordFailure`/`RecordSuccess`/`AdmitCall`/`BeginProbe` logic in `runtime.go`; no change to `DiscoverPrompts`, prompt routing, or the closed observe vocabulary; no tool-call-as-probe and no execution replay.

### [AUTO-DECISION] entries (for coordinator persistence)
- **AD1 — probe ownership in `Dedicated.Discover`.** `BeginProbe` is already the breaker's single-probe primitive; `Discover` is the sole non-executing leg reached by both refresh and reload; wiring/refresh code stays unchanged. Consequence: probe accounting lives in one file; `DiscoverPrompts` is deliberately excluded.

The deferred block MUST (a) invoke the completion callback, then (b) release probe ownership — in that order — so that no later `Discover` can acquire ownership and be clobbered by this completion.

- **AD6 — probe wraps the whole `Discover` body**, including the stateless `closed` guard; a closed runtime's claim completes `false` (harmless).

- **AD8 — Dedicated-local single-flight probe ownership (C1 repair).** Because `RecordFailure` clears the breaker's `probeActive` mid-probe and `BeginProbe`'s completion writes breaker state unconditionally, the breaker cannot by itself guarantee one in-flight probe. `Dedicated` therefore holds its own `probeMu sync.Mutex` + `probeInFlight bool`: a `Discover` acquires ownership before calling `BeginProbe`, only the owner calls `BeginProbe`, and ownership is released only after the deferred completion. ## 4. DESIGN
<!-- specdd:design:start -->
**Approach.** Add the first production caller of `BeginProbe` inside `Dedicated.Discover`, as a thin admission/ownership/completion wrapper around the existing discovery body; change nothing else in the breaker or session machinery.

**Component and contract (`internal/upstream/dedicated.go` only).**
1. Add two fields to `Dedicated`: `probeMu sync.Mutex` and `probeInFlight bool` (guarding single-flight probe ownership; a dedicated mutex, never held while calling into `ServerClient`).
2. Extract the current `Discover` body (`dedicated.go:71-149` as of r5) into an unexported method with the same behavior and signature: `func (d *Dedicated) discover(ctx context.Context) ([]core.ToolDefinition, error)`. It keeps the HTTP-status context value, stateless `closed` guard + fresh `client.Connect` + `defer session.Close()`, stateful `sessionFor`, handshake detection, paginated `ListTools`, deterministic sort, and every `reportDiscoveryFailure` return.
3. Replace `Discover` with the ownership+probe wrapper, in this order:
   - **Acquire ownership:** lock `probeMu`; if `probeInFlight` is true, unlock and `return d.discover(ctx)` (plain discovery, no breaker mutation); else set `probeInFlight = true` and unlock.
   - **Claim:** `complete, err := d.client.BeginProbe()`; if `err != nil` (closed breaker, cooldown not elapsed, or — unreachable while ownership is held — probe already active), lock `probeMu`, set `probeInFlight = false`, unlock, and `return d.discover(ctx)` with no breaker mutation.
   - **Run + complete:** `success := false`; `defer func() { complete(success); d.releaseProbeOwnership() }()`; `defs, derr := d.discover(ctx)`; `success = derr == nil`; `return defs, derr`. The `defer` form is **normative** (AD2): the guarded `complete` runs on every return path and during panic unwinding, so `probeActive`/`halfOpen` are never stranded by a panic, and ownership is released only *after* the completion applies.
   Completion is invoked at most once by construction. No breaker field is ever read directly by the wrapper; the closed/cooldown/active conditions remain owned by `ServerClient`.

**Invariants.**
- (I1) A probe is claimed only when `BeginProbe` grants it; the wrapper never inspects breaker fields directly, so closed/cooldown/active conditions are owned by `ServerClient`.
- (I2) `err == nil` iff a complete, deterministic catalog was produced; a partial/malformed/cancelled discovery is a failed probe (conservative).
- (I3) The tool path never touches `BeginProbe`; `AdmitCall` continues to reject while `halfOpen` or open.
- (I4) **Single in-flight probe (ownership).** At most one `Discover` holds probe ownership at a time (`probeInFlight`), and only the owner invokes `BeginProbe`; therefore at most one granted probe exists per server. Non-owners run plain discovery and mutate no breaker state. Precondition: one `Dedicated` per `*ServerClient`, and `Discover` is the only `BeginProbe` caller.
- (I5) **Ownership survives breaker-state invalidation.** A mid-probe `RecordFailure` (auth or threshold) clears the breaker's `probeActive`/`halfOpen` and sets `openedAt = now`, but does not transfer ownership; the owner remains the sole holder and the sole writer of the probe transition.
- (I6) **No stale completion exists.** Because ≤1 probe exists (I4), a completion can never clear a *different* probe's reservation; there is no stale completion to reconcile.
- (I7) **Release ordering.** Ownership is released only after the completion callback returns (AD2), so no new ownership can interleave before this completion applies.
- (I8) **Precedence (stale-completion vs newer-failure).** Newer failure writers may restart/re-open the breaker during a probe; the in-flight owner's single completion is applied last (it runs after any such failure) and authoritatively sets the final state: success → close (`failures=0, openedAt=zero`), failure → restart cooldown (`openedAt=now`). No second probe exists that could be clobbered.
- (I9) **Admission-closed invariant (source-anchored).** Every `RecordFailure` branch that clears `probeActive` also sets `openedAt=now` (`runtime.go:266-283`), and during a granted probe `openedAt` is non-zero (BeginProbe requires it and does not clear it). Hence `AdmitCall` rejects throughout any active probe, including the owner's flight after a mid-probe failure; admission can only (re)open via a probe `complete(true)`, uniquified by I4.
- (I10) `Discover` for a closed breaker is byte-for-byte behavior-preserving versus today (it simply calls `discover`).
- (I11) Completion is a `defer`-installed set-once closure; it fires exactly once on normal return and on panic unwind, never twice.
- (I12) **Assembly-publication precondition is a harness property, not a production invariant.** In production the runtime always holds a published assembly (startup or reload) before the loop's refresh passes run, so `buildRefresh` always adopts `held.Client` (`reload.go:580-582`); the AC5/AC10 harness must reproduce that precondition explicitly (see §5/§6) because a bare `NewRefresher` over an unpublished runtime aborts at `reload.go:587` before `Discover` and still counts a pass (`refresh.go:276`). The harness MUST publish through **`AdmitStartup`** (buildStartup, contact-free, `reload.go:502,616`), never `Reload` (`buildReload` runs `deps.Discover` `reload.go:618` and fails on discovery error `:625`), and MUST complete the publication and the metrics pre-warm **before** latching the breaker — because both the (avoided) `Reload` publication and any healthy discovery pass run the real `d.Discover`, so ordering them after the latch would consume the latched probe.

**Sequence (happy path, stateless).** tool calls fail `threshold` times → `openedAt=now`, breaker open → `AdmitCall` rejects (AC4) → time passes `openDuration` → refresh/reload calls `Discover` → ownership acquired → `BeginProbe` grants → fresh `Connect`+`ListTools` succeed → `complete(true)` → `failures=0`, `openedAt` zero, `halfOpen=false` → ownership released → `AdmitCall` admits (AC1/AC2/AC6).

**Sequence (C1 interleaving, competing failure — normative).** With the breaker open and P1 an active owner probe: (1) an outstanding previously-admitted call/prompt fails → `RecordFailure` sets `openedAt=now2`, clears `probeActive`/`halfOpen` (breaker still rejects; I9); (2) after `openDuration` a second `Discover` (P2) enters → I4 denies ownership → P2 runs plain discovery, mutating no breaker state; (3) P1 completes → its single completion is applied (I8); ownership released; the breaker state is exactly P1's outcome. Under the defective pre-r3 design, step (2) would have granted P2 and step (3) would have cleared P2's reservation while P2 was active — the exact violation R6/I4/I6 now forbid. AC8 asserts this deterministically.

**Failure path.** Probe claimed → `discover` errors (network/status/timeout/cancel) → `reportDiscoveryFailure` emits the existing `upstream_discovery_failed` record (AC10) → `complete(false)` → `openedAt=now`, `halfOpen=false`, `failures` unchanged → ownership released → breaker still rejects (AC3); next claim only after another `openDuration`.

**Compatibility/security/failure behavior.** No public API, config, wire, or storage change. Probe paths carry the existing `RefreshTimeout` context; cancellation/deadline completes as failure (AC9). No credentials, tokens, or payloads are logged (existing envelopes unchanged).

**Alternatives rejected (meaningful trade-offs only).** (a) Probe claimed in `refresh.go`/wiring: would duplicate the admission condition and miss the reload leg. (b) Lazy admission check inside `AdmitCall`: would admit/replay an execution, violating R3. (c) Evicting the cached session or opening a fresh session in the probe under stateful mode: ticket-2 scope, silently widening this feature.
