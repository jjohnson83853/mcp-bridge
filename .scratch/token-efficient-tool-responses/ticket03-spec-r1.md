## 2. REQUIREMENTS

**R1 (no implicit search fanout — A1).** A successful `search_tools` call MUST NOT change the calling session's projection, the cross-session registry union, or any subsequent `tools/list` traversal: zero tool names may appear in a later `tools/list` solely because they matched the query. The compact search response (tool_name, one-line bounded description, score) and its ranking/top_k semantics from ticket 02 are preserved byte-for-byte in shape.

**R2 (explicit bounded exposure request — A2).** A new built-in tool `expose_tools` is the ONLY mechanism that adds an unpinned tool declaration to a session's projection. Contract:
- Input schema (JSON Schema draft 2020-12, `additionalProperties: false`, required `tool_names`):
  - `tool_names`: array, `minItems: 1`, `maxItems: 8`, `uniqueItems: true`, items `string` with pattern `PublicToolNamePattern` (`^(t_[a-z2-7]{52}|[a-z][a-z0-9-]{0,31}__[a-zA-Z0-9_-]{1,94})$`).
  - `catalog_revision`: optional string, pattern `^$|^[a-f0-9]{64}$` (same semantics as `describe_tool`: empty/absent defaults to the accepted revision; a mismatched non-empty value is rejected).
- Per-request bound N = 8 (constant `MaxExposeToolsPerRequest`). No cumulative per-session cap (documented non-goal).
- Deterministic outcomes: (a) valid set of 1..8 catalog names → success; requested names become declared in the requesting session's `tools/list` and directly callable; (b) count 0 or > 8, duplicate names, or a name not matching the pattern → `invalid_arguments` rejection, projection unchanged; (c) any well-formed name not in the accepted catalog → `unknown_tool` rejection of the WHOLE request (atomic; no partial exposure); (d) no published catalog → `backend_unavailable`; (e) stale `catalog_revision`, retired/reused owner epoch, or non-live owner → `catalog_changed`; (f) publisher-owner request (no session credential) → `catalog_changed` admission rejection; (g) repeat exposure of already-exposed or pinned names → idempotent success, no registry change signal, projection state unchanged.
- Success payload: structured content `{"exposed": [...names newly added by this request, sorted...], "declared": [...all requested names visible post-call, sorted...], "catalog_revision": "<accepted revision>"}`. Errors reuse the existing tool-result error envelope (`code`/`message`/`execution_state`, mirroring `describe_tool`).

**R3 (pins unchanged — A3).** Configured pins keep appearing exactly as today in publisher and session projections (names, descriptors, effective metadata views). `expose_tools` on a pinned name is a successful no-op; pins are never demoted by exposure.

**R4 (direct-call eligibility unchanged — A4).** Direct invocation (`tools/call` by projected name) of a tool that was never pinned and never explicitly exposed is rejected exactly as today (middleware `invalidExposureRequest` path for projected-but-invisible names; SDK unknown-tool path for names never in the union) and dispatches no upstream call. The generic `call_tool` multiplexer and `retrieve_result` paging are untouched.

**R5 (session isolation — A5).** Tools exposed via `expose_tools` appear only in the requesting session's projection. Other sessions' `tools/list` results and their direct-call eligibility are unchanged. Cross-session registry union membership affects middleware admission gating only, never another session's list.

**R6 (revision/epoch/owner invariants preserved — A6).** Catalog revision changes still invalidate projections; surviving interests rebase across publications exactly as today. `expose_tools` re-validates live owner, accepted generation, registry reference, target identity and descriptor validity inside the existing `commitDiscovery` transaction. No ownership, epoch or catalog check is weakened or removed.

**R7 (describe never auto-exposes).** `describe_tool` returns stored schema/metadata only; it MUST NOT commit its target to the session projection. Its `ReadOnlyHint: true` annotation becomes truthful. Callers needing direct-call eligibility must call `expose_tools`.

**R8 (automated coverage — A7).** Automated tests cover: no-implicit-exposure after search, explicit exposure success, exposure bound rejection, pin preservation, and cross-session isolation (A1–A5, AC9).

**Non-goals.** No change to compact search response shape, ranking, scoring, `top_k` bounds (ticket 02, closed at f32e8e06); no change to pin configuration semantics, `call_tool`, `retrieve_result` paging, cursor/epoch binding, or inbound session admission; no cumulative exposure cap; no persistent exposure state (projections remain in-memory per process); no new observability stack.

## 3. EVIDENCE AND UNCERTAINTY

**VERIFIED (read-only inspection, this session):**
- `internal/service/tools.go:479-524` — `searchTools` validates owner (`directRequestOwner`, `discoveryOwnerValid`) and response revision, then `commitDiscovery(owner, assembly, targets)` commits ALL returned targets before delivering the compact response.
- `internal/service/tools.go:536-578` — `searchDiscoveryTargets` validates each hit's binding/pin state against the accepted catalog; sole caller is `searchTools`.
- `internal/service/tools.go:580-678` — `describeTool` returns stored schemas AND `commitDiscovery` of its single target; descriptor at `tools.go:150-159` already declares `ReadOnlyHint: true`.
- `internal/service/projection.go:383-470` — `commitDiscovery` is a transactional staged reconciliation: validates live owner/generation, merges interests, `preparePinProjection` merges interests with pin-backed descriptors, `stageProjectionReconciliation`, registry delta apply; publisher owner commits are a no-op (`projection.go:399-401`).
- `internal/service/session_exposure.go:61-105` — `requiresExposure` routes `tools/list`, `search_tools`/`describe_tool` (admission only) and projected direct names; `ownerToolListPage` binds cursors to epoch/generation.
- `internal/service/inbound.go:481-484,527-535,581-599` — caller epoch stripped, session credential binding verified, retained server epoch stamped into the exposure-epoch header.
- `internal/catalog/schema.go:7-10` — built-in names `search_tools`, `describe_tool`, `call_tool`, `retrieve_result`; exact schemas live here.
- `internal/service/tools.go:103-110` — `searchBounds` (effective 3/4 per refinement); `internal/search/search.go:52` — `CodeInvalidArguments = "invalid_arguments"`.
- `internal/service/progressive_discovery_test.go:244-355` — `TestProgressiveMetadataDiscoveryCommit` currently REQUIRES search to expose tools (`:288-296` interests assertion, `:333` registry-change signal, `:360-368` post-discovery listing/direct calls); these are invalidated by R1 and must be rewritten.

**[AUTO-DECISION] AD1 — mechanism: new built-in tool `expose_tools`.** A parameter on `search_tools` reintroduces fanout (bounded only by N) and keeps match-sets mutating state; a `describe_tool` option overloads a read-only inspection surface and perpetuates accidental mutation (and its descriptor claims `ReadOnlyHint: true`). A dedicated built-in matches the existing pattern (name const in `internal/catalog/schema.go` + descriptor in `renderBuiltinDescriptors` + `requiresExposure` routing) and preserves callable-name exposure semantics: explicit caller action → declaration in session projection → direct invocation. Consequence: every `tools/list` gains one built-in descriptor; cursor paging unaffected (cursors bind to epoch/generation, not tool count).

**[AUTO-DECISION] AD2 — bound N=8 per request, no cumulative cap.** Rationale: 2× the search `top_k` maximum (4) covers the union of two full-result searches in the recommended flow; cumulative eviction would need LRU semantics with no ticket requirement. Consequence: a session may accumulate exposed declarations across requests; each addition is individually explicit — this satisfies the ticket's anti-fanout invariant.

**[AUTO-DECISION] AD3 — describe default: no exposure.** Issue note delegates the decision to this design; current unconditional mutation cannot remain accidental. `commitDiscovery` is removed from `describeTool`. Consequence: flows relying on describe-to-expose must call `expose_tools`; `call_tool` remains available without exposure.

**[AUTO-DECISION] AD4 — pins untouched; search returns identities only.** `commitDiscovery` is retained in the codebase and becomes the sole transaction behind `expose_tools` (plus its publisher no-op). No projection code path changes beyond call sites.

**[AUTO-DECISION] AD5 — exposure requires a live `projectionSession` owner.** `discoveryOwnerValid` accepts publisher kind (needed by search/describe admission); `exposeTools` additionally rejects non-session owners with `catalog_changed`. Rationale: session-less publisher exposure would mutate shared registry state without a bound owner. Consequence: publisher flows rely on pins only.

**UNKNOWN/blockers:** none blocking. `[INFERENCE]` (bounded, non-blocking): `internal/service/discovery_paging_test.go` and `builtin_guidance_test.go` may assert the built-in descriptor count/list — implementer greps for `builtinTools`/`renderBuiltinDescriptors` callers and updates counts 4→5; production paths are fully identified above.

## 4. DESIGN

Selected approach: smallest sufficient change — remove the two implicit `commitDiscovery` call sites, add one built-in tool that reuses the existing `commitDiscovery` transaction verbatim. No projection, coordinator, cursor or inbound changes.

**Interfaces/data contracts:**
- `internal/catalog/schema.go`: add `ToolExposeTools = "expose_tools"` and `MaxExposeToolsPerRequest = 8` to the existing const blocks; add `func ExposeToolsInputSchema() map[string]any` returning the R2 schema, reusing `PublicToolNamePattern` and `ToolInputCatalogRevisionPattern`.
- `internal/service/tools.go`:
  - `renderBuiltinDescriptors`: append a fifth descriptor `{Name: catalog.ToolExposeTools, Description: <guidance: search results are NOT exposed automatically; use expose_tools to declare up to 8 discovered tools into this session's tools list; pinned tools are already declared>, InputSchema: catalog.ExposeToolsInputSchema(), Annotations: &mcp.ToolAnnotations{ReadOnlyHint: false, DestructiveHint: boolPtr(false), IdempotentHint: true, OpenWorldHint: boolPtr(false)}}`.
  - `registerBuiltinTools`: `case catalog.ToolExposeTools: server.AddTool(descriptor, t.exposeTools)`.
  - `searchTools`: delete the `searchDiscoveryTargets` call and the `commitDiscovery` block (`tools.go:507-519` region); keep decode, assembly-nil, owner, and response-revision checks unchanged.
  - delete `searchDiscoveryTargets` (`tools.go:536-578`) after migrating any test callers (grep; none expected in production).
  - `describeTool`: delete the `commitDiscovery` block and `target` construction (`tools.go:655-664` region); keep everything else.
  - new `type exposeToolsWire struct { ToolNames []string `json:"tool_names"`; CatalogRevision string `json:"catalog_revision"` }` and `func (t *ToolSurface) exposeTools(ctx context.Context, req *mcp.CallToolRequest) (*mcp.CallToolResult, error)`. Admission order mirrors `describeTool` (`tools.go:580-678`): (1) `decodeStrict` → `invalid_arguments`; (2) assembly nil → `backend_unavailable`; (3) optional `catalog_revision` validation with `logAdmissionFailure(..., "expose_tools", ...)` → `catalog_changed`; (4) `directRequestOwner` + `discoveryOwnerValid` → `catalog_changed`; (5) `owner.kind != projectionSession` → `catalog_changed` (AD5); (6) shape: `len==0 || len>MaxExposeToolsPerRequest || duplicate || pattern mismatch` → `invalid_arguments` (projection untouched); (7) `resolveBinding(assembly.catalog, name)` for every name; first miss → `unknown_tool` "no such tool in the published catalog", atomic; (8) build `map[logicalToolTarget]struct{}` and call `t.commitDiscovery(owner, assembly, targets)`; `errAcceptedGenerationMismatch` → `catalog_changed`; (9) success payload per R2 (`exposed` = requested targets absent from `previous.interests` and pin set, computed pre-commit; `declared` = all requested public names; `catalog_revision`), wrapped in `t.boundedCallToolResult(req, result, "")`, plus `contributeOperation` + `mcp_complete` log entry copied from `describeTool`'s success path with `Operation: "expose_tools"`.
- `internal/service/session_exposure.go` `requiresExposure`: add `case catalog.ToolExposeTools: return true, false, ""` alongside the search/describe built-ins.
- Pinned names are detected via `assembly.PinnedNames()` for the `exposed`/`declared` distinction; pinned/exposed repeats rely on `commitDiscovery`'s `sameProjection` short-circuit (`projection.go:437-440`) for idempotence.

**Compatibility:** one additional built-in descriptor per `tools/list` (observable, intended); union membership gained by session A's exposure makes A's name middleware-visible globally but only callable/listable by A (existing per-owner projection gating, `session_exposure.go:75-79`). **Security:** all admission checks retained; atomic rejection prevents partial exposure; no client-controlled free text in error messages beyond existing bounded patterns; no secrets logged. **Failure behavior:** `commitDiscovery` is transactional (staged reconciliation + barrier re-check), so a rejected expose leaves projection state and the SDK registry untouched.

**W09E risk matrix (anchored):** Lifecycle — interests/projections are per-process in-memory, created at session bootstrap (`inbound.go:581-599` epoch stamping), invalidated on revision change, cleared on restart; expose joins the existing rebasing path (`projection.go:367-406`). Shared state — `commitDiscovery` already serializes writers via `publicationMu` + barrier re-check (`projection.go:385-460`); a competing publication during expose yields `errAcceptedGenerationMismatch` → deterministic `catalog_changed`, walked through both orderings. Contract — R→AC map below is 1:1 with ticket bullets and A1–A7; verification commands are noncontradictory (no-fanout assertions and exposure assertions target different handlers). Authority — no owner stop, approval, or access boundary changes; no R/AC/T id is removed. Observability — section 7. Repair closure — the root invariant (only explicit, bounded, caller-selected actions mutate projections) is repaired at both commit sites (search + describe), not just the search sentence; fixtures at `progressive_discovery_test.go:244-355` are rewritten to the new invariant.

## 8. RELEASE AND RECOVERY

- Deployment: single-binary release; no configuration or migration steps. Built-in descriptor set changes on start; projections rebuild per process.
- Order: no sequencing constraints; sessions created before/after upgrade reconcile through the existing rebasing path. Surviving pre-upgrade interests rebase across publications exactly as today (R6).
- Rollback: revert the feature commit on main and redeploy; no persistent state to migrate (projections, interests and union are in-memory per process; restart clears them). A session that used `expose_tools` under the new binary and reverts loses direct-call eligibility for exposed (unpinned) tools — same behavior as a process restart today; pins restore automatically.
- Irreversible steps: none.
