## 2. REQUIREMENTS
- R1 (scope): Exactly two allowlisted operations: (a) server `portainer`, upstream tool name `EndpointList`; (b) server `portainer`, upstream tool name `docker_proxy`, discriminator `path == "/containers/json"` (exact). Proxmox/OPNsense EXCLUDED (conditional unmet). Does not weaken AC1–AC7.
- R2 (default projection + disclosure): When no explicit projection request is present and an entry matches, the bridge replaces the upstream list payload with the entry's default projection and discloses it in every delivery path — on BOTH invocation surfaces. On the call_tool built-in the disclosure is the outer envelope's `projection` member; on the direct/pinned path it is the bridge-owned reserved member `mcp_bridge_projection` on the result's StructuredContent (exact carrier in section 4, C4b). The response never presents projected objects as the upstream's full shape; no unprojected upstream object may remain in any carrier when the disclosure says applied.
- R3 (full opt-in): `projection.full` on the call_tool built-in returns unprojected objects, still ceiling-bounded. The direct/pinned path has no bridge-level projection argument; its opt-out is the same tool invoked through the call_tool built-in with `projection.full` — the full result is always reachable (AC2).
- R4 (custom selection + precedence + admission validation): A field selection overrides the default projection, copies raw upstream top-level item keys verbatim, and rejects unknown fields deterministically — post-dispatch, payload-relative, AFTER shape confirmation, and only against a NON-EMPTY list; an EMPTY list cannot establish unknown-ness, so fields mode on an empty list is ACCEPTED with an empty projected list and disclosure (N1 rule). Admission validation (pre-dispatch, fixed messages): `full` and `fields` together → invalid_arguments; wire→request mapping (N9): a PRESENT `fields` member — even an empty array — is a fields request subject to the bounds (so `fields: []` is a deterministic pre-dispatch rejection); only an ABSENT or NULL `projection` key means no request; `projection: {}` and `{"full": false}` without a fields member are treated as absent; `full: true` with a fields member is the full+fields conflict; any other shape is invalid_arguments. Bounds: `fields` = 1–16 unique strings, each 1–64 characters from `[A-Za-z0-9_]`, AND the whole fields array's ENCODED width (sum of escapedJSONLength over names + array punctuation) ≤ 512 bytes (`projectionFieldsMaxEncodedBytes`) — the binding constraint is the delivery arithmetic: measured(envelope with the maximal disclosure + upstream_code reserve) + retainedEnvelopeHeadroom(6) ≤ PreviewCeilingBytes(1536), keeping the preview/terminal body non-empty (N2). The MAXIMAL LEGAL REQUEST is the largest fields array satisfying BOTH bounds simultaneously (computed by T2/T3 from the cap, never assumed); unknown-field rejection requires a non-empty list whose items all lack a requested field.
- R5 (allowlist discipline): Explicit identities (server id + raw tool name + discriminator), never patterns; each entry justified by captured schema/payload evidence; unrelated Docker paths never projected, labeled `not_allowlisted` (N3).
- R6 (safe degradation): Upstream tool errors, empty lists, carrier failures (non-list payloads, unparseable wrappers, non-mirrorable structuredContent, non-object items), and default-mode AGGREGATE all-default-fields-missing must not silently drop fields: the bridge applies the projection faithfully (disclosed) or passes the full upstream payload through unchanged with a disclosed, logged, counted skip reason. Aggregate predicate (N10): the skip fires only when EVERY item of the list misses ALL default/requested fields; an item missing SOME fields projects its present members (AC6(e)). Carrier failures skip in both modes; empty list + `fields` is ACCEPTED (disclosed); non-empty list + a requested field absent from every item is a deterministic REJECTION. A reserved-key collision on the direct path skips rather than overwriting upstream data. Skip/reject events registered in the closed `eventMessage` vocabulary. No partial payloads masquerading as complete projections.
- R7 (non-interference): Non-allowlisted tools byte-identical to today when no effective request is sent — on both invocation paths, including the direct path (no reserved member, no disclosure, unchanged sizes); disclosure joins sizing maps only when actually present (N2).
- Non-goals (unchanged): no Proxmox/OPNsense; no new config surface; no bridge-side JMESPath; no new paging mechanism; no numeric performance AC; no projection of search_tools/describe_tool results; no change to session-projection semantics.
