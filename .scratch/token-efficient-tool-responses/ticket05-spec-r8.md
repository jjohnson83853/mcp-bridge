## 4. DESIGN
Selected approach (unchanged in kind): pure field-projection engine in NEW package-private `internal/service/field_projection.go`, invoked from TWO call sites — `callTool` at the decodeUpstreamResult call site (tools.go:1000) and `boundDirectExecution.call` (direct_execution.go:30) between its decode (:53) and result construction (:60-64) — in both cases before `t.boundedCallToolResult` (direct call site :65).
- Single-transformed-result rule (F1/R6-2, both paths): APPLY → one transformed result feeds every downstream derivation (multiplexer: the WHOLE `upstream_result` member re-marshaled + returned result + envelope disclosure; direct path: returned result's Content + rewritten payload-bearing structuredContent member + reserved-member disclosure); SKIP/pass-through → original bytes/value flow unchanged.
- NORMATIVE DISCLOSURE SCHEMA (R6-1/R7-4, both carriers): `{v:1, applied, entry, mode, fields, reason?}`, reason required iff applied=false; `fields` = applied projection's field list, `[]` when nothing applied/selected; `v` fixed 1; reason ∈ the closed 12-value enum.
- NORMATIVE D-TABLE (F-B, 21 rows, per-row outcome/reason/channel; P = payload member on the row's path, M = render metadata from the out-of-band threaded decision whenever a preview/page/terminal render occurs (F-D budget permitting; default bounds: always for legal requests), L = one log record, C = counter with outcome ∈ {applied, skipped, rejected}):
