## 2. REQUIREMENTS

**R1 — Compact index hits (AC1, AC2, AC7).** Each `search_tools` result row contains exactly the fields `tool_name`, `description`, `score` — nothing else. `tool_name` is the existing effective wire name (internal/service/tools.go:987–1003). `description` is bounded and one-line by construction, in two deterministic steps applied to the stored description at the wire choke point only (stored/embedded descriptions are never modified):
1. **Normalization (one-line, F1 mechanism):** every maximal run of one or more characters from the whitespace-control class W = {U+0020} ∪ {Unicode category Cc: U+0000–U+001F (CR, LF, TAB, other C0), U+007F–U+009F (DEL, C1)} is replaced by a single space `" "`; leading/trailing spaces are then trimmed. After this step the emitted description can never contain a control character or a line break.
2. **Bounding:** the JSON-encoded byte length of the normalized string (bytes it contributes to a marshaled JSON string body, excluding delimiting quotes) never exceeds 36. If the normalized description fits 36 encoded bytes it passes through unchanged with no marker. Otherwise truncation takes the longest rune-boundary-aligned prefix of the normalized string whose encoded length fits 36 − 3 bytes reserved for the marker, then appends the visible marker `…` (U+2026, 3 encoded bytes) exactly when any suffix was dropped; multi-byte UTF-8 sequences are never split; identical input yields byte-identical output. Quote/backslash/HTML-escape content inside the description passes through `json.Marshal` escaping unchanged (its wire cost is accounted in §4).

No schema content (`input_schema`/`output_schema` or any other schema-derived data) appears in any hit. `describe_tool` remains the only response path returning stored input/output schemas (unchanged; tools.go:507-538 and projection.go:367-430 keep consuming internal identity, never the pruned wire fields).

**R2 — Small enforced limits (AC3).** Bridge-level compact-index caps `IndexTopKDefault=3` and `IndexTopKMax=4` (compile-time constants in internal/search, not operator config). Effective default = min(operator `default_top_k`, 3); effective caller-visible maximum = min(operator `max_top_k`, 4); additionally the effective default is clamped down to the effective maximum, so `EffectiveBounds()` always returns a coherent pair with default ≤ maximum for any operator settings (F4 fix; no-op for valid configs where d ≤ m). Operator bounds stay 1..50 (internal/config/bounds.go:86 unchanged); existing configs (config.example.yaml:45-47, config.mcp-grafana-stack.yaml:30-32 setting 10/50) remain valid and effective 3/4. Operator knobs can only lower the effective values. A request with `top_k` above the effective maximum is rejected by the existing strict path (`internal/search/search.go:150-171`, error `invalid_arguments` "top_k is outside the configured bounds") — never silently clamped. The advertised input schema's `top_k.default`/`maximum` (internal/catalog/schema.go:35-56) must equal the enforced effective values per surface and satisfy default ≤ maximum (F4 schema-consistency), so the caller-visible maximum is small and coherent everywhere the tool is listed.

**R3 — Root envelope and preserved mechanics (AC4, AC6).** Unchanged from r1: root keeps `catalog_revision`, `mode`, `degraded_reasons` (tools.go:1008-1034); adds `match_count` — the number of ranked matching results before count clipping (= length of the fused pre-TopK population, search.go:421-433) — and `truncated` (`true`) at the root only when the matched population exceeds the returned result count; both fields absent when nothing was clipped (absence ⟺ `match_count == len(results)` and no truncation). Ranking order and scores, `query`/`servers` filters, degradation reporting, catalog-revision mismatch behavior, strict decoding and the error taxonomy are unchanged except for the pruned hit fields and the R2 admission cap that AC3 mandates. `searchDiscoveryTargets` (tools.go:507-538) and `commitDiscovery` (projection.go:367-430) continue to consume the internal `search.Response` identity fields (ToolName/Server/UpstreamName/CatalogRevision/Pinned), never the pruned wire payload.

**R4 — Byte target and test matrix (AC5, AC8).** Documented response-size target: any `search_tools` response is at most 2048 bytes as measured by the established domain `len(json.Marshal(*mcp.CallToolResult))` (internal/service/result_measure.go:9-14), which includes BOTH the structured payload and its duplicated text-block copy with the outer marshal's re-escaping of every `"`/`\\` inside the text (F2 term; see §4 arithmetic with margin ≥47 under hard bounds). **R5 — Documentation (ticket Notes; AC9).** README.md and the live `search_tools` tool guidance (tools.go:96-105, builtin_guidance_test.go:15-83) document: the compact hit field set; the removals of per-hit `server`, `upstream_name`, `pinned`, `availability` (pinned inventory remains in the dynamic direct-first guidance sentence); the additions `match_count`/`truncated`; the effective default 3 / caller-visible maximum 4 and the clamp semantics over operator `default_top_k`/`max_top_k` (including the degenerate-config coherence rule of R2); the 36-encoded-byte description budget with the `…` marker and one-line normalization; the ≤2048-byte target; that `describe_tool` is the only schema path; AND the two-way rollback tolerance sentence (F6): after a rollback clients must tolerate both directions — added root `match_count`/`truncated` disappear and pruned per-hit `server`/`upstream_name`/`pinned`/`availability` return. ## 4. DESIGN

**Selected approach:** unchanged from r1 — minimal projection change; search engine authoritative; service layer compacts at the single wire choke point (`searchPayload`); bounds enforced once in internal/search and mirrored into the advertised schema; no new abstractions.

**Components and contracts:**

3. internal/service — `NewToolSurface` computes and stores `searchTopKDefault`/`searchTopKMax` once via `cfg.Search.EffectiveBounds()`; `renderBuiltinDescriptors(resolvedPins []core.ResolvedPin, topKDefault, topKMax int)`; `prepareProjection`/`preparePinProjection` gain the two bounds parameters; call sites (tools.go:213, projection.go:417, projection.go:943, session_exposure.go:217) pass the stored values. `searchPayload` emits hits `{"description": bounded, "score": score, "tool_name": effectiveWireName(...)}` (alphabetical key order preserved) and, only when `response.MatchCount > len(response.Results)`, root `"match_count"` and `"truncated": true`. New unexported consts `searchDescriptionMaxBytes = 36`, `searchDescriptionMarkerBytes = 3`, marker `…`, and two helpers beside `searchPayload` (AD3 order): `normalizeSearchDescription` (W-runs → single space, trim; rune-based, deterministic) and `boundSearchDescription` (encoded-length measure; pass-through unmarked when ≤36; else longest rune-aligned prefix fitting 33 encoded bytes + `…`; never splits UTF-8 or a JSON escape unit — cutting at source-rune boundaries always yields a valid encoding). 4. **Byte arithmetic (AC5 feasibility — corrected for F2, hard bounds only):** envelope = 4 hits (effective max), 64-char wire names, 36-encoded-byte descriptions (incl. marker) in the escape-maximal form, worst-case float64 score ≤24 chars (hard shortest-round-trip max, e.g. `-1.7976931348623157e+308`), `mode:"keyword"` + one 26-char reason (`embed_provider_unavailable`; the degradation switch is exclusive — one reason max; `hybrid_partial` co-occurs with no reason, so the degraded+keyword root stays worst), clipped with 5-digit `match_count` (matched population ≤ catalog size ≤ operator `max_tools_total` ≤ 20000, bounds.go:88):

- hit = 42 overhead + 64 name + 36 description + 24 score = 166; payload = 202 + 4×166 + 3 commas = **869**.
- text copy = payload + 58 structural-quote escapes (18 root + 4×10 per-hit quotes, each `"` → `\"`) + D, where D = description escape inflation: every encoded description byte inflates ≤ +1 in the outer copy (plain UTF-8: 0; `\"`/`\\`/`\n`: 2 bytes → 4, ratio 1; `\u003c`/control: 6 → 7, ratio 1/6; the `…` marker: 3 raw bytes, delta 0) ⇒ D ≤ 36 per hit ⇒ D ≤ 144 (F2's previously omitted term).
