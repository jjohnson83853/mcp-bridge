## 2. REQUIREMENTS
- R1 (scope): Exactly the two observed operations are allowlisted: (a) server `portainer`, upstream tool name `EndpointList`; (b) server `portainer`, upstream tool name `docker_proxy`, discriminator `path == "/containers/json"` (exact string match). Proxmox/OPNsense EXCLUDED (conditional unmet: schemas/payload fields not captured). Does not weaken AC1–AC7 (entry ACs defined over included fixtures; AC4 strengthened). Later inclusion is optional scope under a new owner decision, not a task.
- R2 (default projection + disclosure): When no explicit projection request is present and an allowlist entry matches, the bridge replaces the upstream list payload with the entry's default projection and discloses it — applied flag, fields, entry ID — in every delivery path of that response. The response never presents projected objects as the upstream's full shape, and no unprojected upstream object may remain in any carrier (text or structured) when the disclosure says applied.
- R3 (full opt-in): `projection.full` returns the upstream's unprojected objects unchanged, still subject to ticket 01's ceiling, retention and paging. Not an unbounded escape hatch.
- R4 (custom selection + precedence + admission validation): A field selection overrides the default projection, selects raw upstream top-level item keys copied verbatim, and rejects unknown fields deterministically. Unknown-field validation is post-dispatch, payload-relative, AFTER shape confirmation, and requires a NON-EMPTY list: a requested field is unknown iff it appears in no item of a non-empty returned list; an EMPTY list cannot establish unknown-ness, so fields mode on an empty list is ACCEPTED with an empty projected list and disclosure (one rule, stated here, in AC3/AC6(c), the D-table, and the T1/T2 oracles — no count of items yields two outcomes). Admission validation (pre-dispatch, fixed payload-free messages): `full` and `fields` together → invalid_arguments; `fields` = 1–16 unique strings, each 1–64 characters from `[A-Za-z0-9_]` (JSON-safe alphabet, so encoded width equals raw width — N2); violations of type/count/uniqueness/alphabet/length are deterministic pre-dispatch invalid_arguments rejections. Wire→request mapping (N7): `projection` absent, null, an empty object, or an object with neither `full:true` nor a non-empty `fields` (including explicit `full:false` alone) is treated as ABSENT — non-allowlisted calls stay byte-identical, allowlisted calls take the default mode; `full:false` WITH `fields` is a fields request; any other shape is invalid_arguments.
- R5 (allowlist discipline): Explicit identities (server id + upstream raw tool name + operation discriminator), never patterns. Each entry justified by captured stored schema and payload evidence. Unrelated Docker API paths are never projected and are labeled `not_allowlisted` (N3).
- R6 (safe degradation): Upstream tool errors, empty lists, carrier failures (non-list payloads, unparseable wrappers, non-mirrorable structuredContent, non-object items), and default-mode items missing ALL default fields must not silently drop fields: the bridge applies the projection faithfully (disclosed) or passes the full upstream payload through unchanged with a disclosed, logged, counted skip reason. A projection may be applied only when every carrier of the list document can be re-derived consistently. Explicit split (N1 + empty-list rule): carrier failures and default-mode all-default-fields-missing → SKIP/pass-through; empty list + `fields` → ACCEPTED (disclosed); non-empty list + a requested field absent from every item → deterministic REJECTION. Skip/reject events must be registered in the closed `eventMessage` vocabulary. No partial payloads masquerading as complete projections.
- R7 (non-interference): Non-allowlisted tools — similarly named tools on other servers, the same proxy tool on other paths — behave byte-identically to today when no explicit effective projection request is sent: no `projection` key, no counter, no log, unchanged page splits (the disclosure joins service sizing maps ONLY when a disclosure is actually present, N2).
- Non-goals (unchanged): no Proxmox/OPNsense entries; no new config surface; no bridge-side JMESPath; no new paging mechanism; no numeric performance AC; no projection of search_tools/describe_tool results; no change to session-projection semantics (field projection ≠ session projection in code and docs).
