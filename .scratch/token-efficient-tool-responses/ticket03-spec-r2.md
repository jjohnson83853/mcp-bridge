## 2. REQUIREMENTS

**R1 (no implicit search fanout — A1).** A successful `search_tools` call MUST NOT change the calling session's projection, the cross-session registry union, or any subsequent `tools/list` traversal: zero tool names may appear in a later `tools/list` solely because they matched the query. The compact search response (tool_name, one-line bounded description, score) and its ranking/top_k semantics from ticket 02 are preserved byte-for-byte in shape.

**R2 (explicit bounded exposure request — A2).** A new built-in tool `expose_tools` is the ONLY mechanism that adds an unpinned tool declaration to a session's projection. Contract:
- Input schema (JSON Schema draft 2020-12, `additionalProperties: false`, required `tool_names`):
  - `tool_names`: array, `minItems: 1`, `maxItems: 8`, `uniqueItems: true`, items `string` with pattern `PublicToolNamePattern` (`^(t_[a-z2-7]{52}|[a-z][a-z0-9-]{0,31}__[a-zA-Z0-9_-]{1,94})$`).
  - `catalog_revision`: optional string, pattern `^$|^[a-f0-9]{64}$` (same semantics as `describe_tool`: empty/absent defaults to the accepted revision).
- Per-request bound N = 8 (constant `MaxExposeToolsPerRequest`). No cumulative per-session cap (documented non-goal).
- Wire-name normalization: every value in `exposed`/`declared` is `effectiveWireName(serverID, rawName)` (`internal/service/tools.go:1005-1007`) of the resolved target — the semantic `<server>__<tool>` name when it is a valid identifier of at most 64 characters, otherwise the deterministic `t_` + unpadded base32 SHA-256 fallback. A requested `t_…` alias normalizes to its target's effective wire name (no alias spelling leaks into the payload).
- Deterministic outcomes: (a) valid set of 1..8 accepted-catalog names → success; requested names become declared in the requesting session's `tools/list` and directly callable; (b) count 0 or > 8, duplicate names, a name not matching `PublicToolNamePattern`, or a non-empty `catalog_revision` that is not a valid 64-character hexadecimal digest → `invalid_arguments` rejection, projection unchanged; (c) any well-formed name not in the accepted catalog → `unknown_tool` rejection of the WHOLE request (atomic; no partial exposure); (d) no published catalog → `backend_unavailable`; (e) a well-formed `catalog_revision` that does not equal the accepted revision → `catalog_changed` tool-result rejection; (e2) a retired/reused owner epoch or a non-live owner → JSON-RPC `-32600` `invalid exposure request` from the exposure middleware (`admitExposureRequest`, `session_exposure.go:104-131,175-177`) before the handler runs — this surface is a protocol error, not a tool result; (f) publisher-owner request (no session credential) → `catalog_changed` admission rejection; (g) repeat exposure of already-exposed names → idempotent success, no SDK registry change signal, projection state unchanged; exposure of pinned names is a literal no-op per R3.
- Success payload: structured content `{"exposed": [...effectiveWireName per target newly added by this request, sorted...], "declared": [...effectiveWireName per requested name, sorted...], "catalog_revision": "<accepted revision>"}`. Errors reuse the existing tool-result error envelope (`code`/`message`/`execution_state`, mirroring `describe_tool`).

**R3 (pins unchanged, no-op literal — A3).** Configured pins keep appearing exactly as today in publisher and session projections (names, descriptors, effective metadata views). `expose_tools` on a pinned name never invokes `commitDiscovery`: no interest merge, no generation bump, no descriptor/union/registry change, no registry change signal. Pins are never demoted by exposure.

**R4 (direct-call eligibility unchanged — A4).** Direct invocation (`tools/call` by projected name) of a tool that was never pinned and never explicitly exposed is rejected exactly as today (middleware `invalidExposureRequest` path for projected-but-invisible names; SDK unknown-tool path for names never in the union) and dispatches no upstream call. The generic `call_tool` multiplexer and `retrieve_result` paging are untouched.

**R5 (session isolation — A5).** Tools exposed via `expose_tools` appear only in the requesting session's projection. Other sessions' `tools/list` results and their direct-call eligibility are unchanged. Cross-session registry union membership affects middleware admission gating only, never another session's list.

**R6 (revision/epoch/owner invariants preserved — A6).** Catalog revision changes still invalidate projections; surviving interests rebase across publications exactly as today. `expose_tools` re-validates live owner, accepted generation, registry reference, target identity and descriptor validity inside the existing `commitDiscovery` transaction. No ownership, epoch or catalog check is weakened or removed.

**R7 (describe never auto-exposes).** `describe_tool` returns stored schema/metadata only; it MUST NOT commit its target to the session projection. Its `ReadOnlyHint: true` annotation becomes truthful. Callers needing direct-call eligibility must call `expose_tools`.

**R8 (automated coverage — A7).** Automated tests cover: no-implicit-exposure after search, explicit exposure success, exposure bound rejection, pin preservation, and cross-session isolation (A1–A5, AC9).

**Non-goals.** No change to compact search response shape, ranking, scoring, `top_k` bounds (ticket 02, closed at f32e8e06); no change to pin configuration semantics, `call_tool`, `retrieve_result` paging, cursor/epoch binding, or inbound session admission; no cumulative exposure cap; no persistent exposure state (projections remain in-memory per process); no new observability stack.

## 4. DESIGN

Selected approach (unchanged from r1): smallest sufficient change — remove the two implicit `commitDiscovery` call sites, add one built-in tool that reuses the existing `commitDiscovery` transaction verbatim, plus the CR1-8 pinned pre-filter and CR1-1 wire-name payload definition. No projection, coordinator, cursor or inbound changes.

**Interfaces/data contracts:**
- `internal/catalog/schema.go`: add `ToolExposeTools = "expose_tools"` and `MaxExposeToolsPerRequest = 8` to the existing const blocks; add `func ExposeToolsInputSchema() map[string]any` returning the R2 schema, reusing `PublicToolNamePattern` and `ToolInputCatalogRevisionPattern`.
- `internal/service/tools.go`:
  - `renderBuiltinDescriptors`: append a fifth descriptor `{Name: catalog.ToolExposeTools, Description: <guidance: search results are NOT exposed automatically; use expose_tools to declare up to 8 discovered tools into this session's tools list; pinned tools are already declared>, InputSchema: catalog.ExposeToolsInputSchema(), Annotations: &mcp.ToolAnnotations{ReadOnlyHint: false, DestructiveHint: boolPtr(false), IdempotentHint: true, OpenWorldHint: false}}` (annotation row mirrors README.md).
  - `registerBuiltinTools`: `case catalog.ToolExposeTools: server.AddTool(descriptor, t.exposeTools)`.
  - `searchTools`: delete the `searchDiscoveryTargets` call and the `commitDiscovery` block (`tools.go:507-519` region); keep decode, assembly-nil, owner, and response-revision checks unchanged. Delete `searchDiscoveryTargets` (`tools.go:536-578`) after migrating any test callers (grep; none expected in production).
  - `describeTool`: delete the `commitDiscovery` block and `target` construction (`tools.go:663-670` region); keep everything else, including the `:599-610` revision validation.
  - new `type exposeToolsWire struct { ToolNames []string `json:"tool_names"`; CatalogRevision string `json:"catalog_revision"` }` and `func (t *ToolSurface) exposeTools(ctx context.Context, req *mcp.CallToolRequest) (*mcp.CallToolResult, error)`. Admission order mirrors `describeTool`: (1) `decodeStrict` → `invalid_arguments`; (2) assembly nil → `backend_unavailable`; (3) `catalog_revision`: empty → accepted revision; non-empty failing `isValidCatalogRevision` → `logAdmissionFailure(..., "expose_tools", "invalid_arguments")` + `invalid_arguments` "catalog_revision is not a valid 64-character hexadecimal digest"; well-formed mismatched → `logAdmissionFailure(..., "expose_tools", "catalog_changed")` + `catalog_changed` (CR1-7); (4) `directRequestOwner` + `discoveryOwnerValid` → `catalog_changed`; (5) `owner.kind != projectionSession` → `catalog_changed` (AD5 backstop; the middleware already rejects these with `-32600`); (6) shape: `len==0 || len>MaxExposeToolsPerRequest || duplicate || !PublicToolNamePattern.MatchString(name)` → `invalid_arguments`, projection untouched; (7) `resolveBinding(assembly.catalog, name)` for every name; first miss → `unknown_tool` "no such tool in the published catalog", atomic; (8) partition (AD6): `pinned := names in assembly.PinnedNames()`; `pending := rest` as `map[logicalToolTarget]struct{}`; (9) if `len(pending) > 0`: `t.commitDiscovery(owner, assembly, pending)`, `errAcceptedGenerationMismatch` → `catalog_changed`; if `len(pending) == 0`: skip `commitDiscovery` entirely — literal no-op, no interest merge, no generation bump, no registry delta (R3); (10) success payload per R2: `exposed` = sorted `effectiveWireName` of pending targets absent from `previous.interests` (computed pre-commit); `declared` = sorted `effectiveWireName` of ALL requested names, pinned or not (CR1-1); `catalog_revision`; wrapped in `t.boundedCallToolResult(req, result, "")`, plus `contributeOperation` + `mcp_complete` log entry copied from `describeTool`'s success path with `Operation: "expose_tools"`.
- `internal/service/session_exposure.go` `requiresExposure`: add `case catalog.ToolExposeTools: return true, false, ""` alongside the search/describe built-ins. Surface note (CR1-4): this routes `expose_tools` through `admitExposureRequest`, so retired/reused epochs and non-live owners fail at the middleware with JSON-RPC `-32600` `invalid exposure request` (`session_exposure.go:104-131,175-177`) and never reach the handler; only well-formed-but-stale `catalog_revision` values surface as the `catalog_changed` tool result from step 3.
- Pinned/exposed-repeat semantics: pinned requests never reach `commitDiscovery` (step 8-9); already-exposed repeats rely on `commitDiscovery`'s `sameProjection` short-circuit (`projection.go:437-440`) for idempotence with no registry change signal.

**Compatibility:** one additional built-in descriptor per `tools/list` (observable, intended); union membership gained by session A's exposure makes A's name middleware-visible globally but only callable/listable by A (existing per-owner projection gating, `session_exposure.go:75-79`). **Security:** all admission checks retained; atomic rejection prevents partial exposure; no client-controlled free text in error messages beyond existing bounded patterns; no secrets logged. **Failure behavior:** `commitDiscovery` is transactional (staged reconciliation + barrier re-check), so a rejected expose leaves projection state and the SDK registry untouched.

**W09E risk matrix (anchored):** Lifecycle — interests/projections are per-process in-memory, created at session bootstrap (`inbound.go:581-599` epoch stamping), invalidated on revision change, cleared on restart; expose joins the existing rebasing path (`projection.go:367-406`); counterexample walked: expose of a pinned name under a concurrent publication — pre-filter means no commit call, so no `errAcceptedGenerationMismatch` surface exists for that request, while the pending sub-request of a mixed request walks the barrier re-check (`projection.go:437-460`) both orderings. Shared state — `commitDiscovery` serializes writers via `publicationMu` + barrier re-check; competing publication during expose yields deterministic `catalog_changed`; the retired-epoch schedule is caught one layer earlier by `admitExposureRequest` (`-32600`). Contract — R→AC map below is 1:1 with ticket bullets and A1–A7 plus AC11 for R2's rejection cases; verification commands are noncontradictory (no-fanout assertions and exposure assertions target different handlers). Authority — no owner stop, approval, or access boundary changes; no R/AC/T id is removed; AC11 is the only added AC (listed by CR1-7). Observability — section 7. Repair closure — the root invariant (only explicit, bounded, caller-selected actions mutate projections) is repaired at both commit sites (search + describe) and across all invalidated fixtures: `progressive_discovery_test.go:20-365` and `:464-563`, plus the five enumerated built-in-count files.
