## 2. REQUIREMENTS
- R1 (scope): Exactly the two observed operations are allowlisted: (a) server `portainer`, upstream tool name `EndpointList`; (b) server `portainer`, upstream tool name `docker_proxy`, operation discriminator `path == "/containers/json"` (exact string match). Proxmox (`proxmox__get_containers`) and OPNsense (`opn_list_*`) entries are EXCLUDED (conditional unmet: their stored schemas and payload fields were not captured). This does not weaken AC1–AC7: the allowlisted-entry ACs are defined over the two included entries' fixtures, and AC4 is strengthened by more untouched tools. Later inclusion is optional scope under a new owner decision, not a task here.
- R2 (default projection + disclosure): When no explicit projection request is present and an allowlist entry matches, the bridge replaces the upstream list payload with the entry's default projection and states in the response that a projection was applied, which fields it used, and which entry matched — in every delivery path of that response (direct pass-through under the ceiling, paged preview, each `retrieve_result` page, and terminal records). The response must never present projected objects as the upstream's full shape, and no unprojected upstream object may remain anywhere in the delivered payload (text or structured) when a projection is disclosed as applied.
- R3 (full opt-in): A caller-requested full response returns the upstream's unprojected objects unchanged (bridge does not transform them), still subject to ticket 01's delivery ceiling, retention and paging. Not an unbounded escape hatch.
- R4 (custom selection + precedence + admission validation): A caller-supplied field selection overrides the default projection, selects raw upstream top-level item keys copied verbatim, and rejects unknown fields deterministically (no silently narrowed payload). Precedence: absent request → default (if entry matches); `projection.full: true` → no bridge projection; `projection.fields` → custom selection (allowlisted entries only). The projection request is validated at admission, before dispatch: `full` and `fields` together → invalid_arguments; `fields` must be 1–16 unique strings each ≤64 bytes — an empty `fields` array (present but empty), duplicates, >16 entries, oversized entries, or wrong types are deterministic pre-dispatch invalid_arguments rejections (absent vs empty are distinguished: a nil field list means no request). Unknown-field validation (payload-relative) happens after dispatch and only after the payload shape is confirmed to be the expected list of objects.
- R5 (allowlist discipline): Entries are explicit identities (server id + upstream raw tool name + operation discriminator), never name patterns, substrings or provider heuristics. Each entry is justified by its captured stored schema and captured payload evidence (section 3/4). Unrelated Docker API paths are never projected.
- R6 (safe degradation): Upstream tool errors, empty lists, non-list payloads, list items missing all requested/default fields, and upstream shape changes must not silently drop fields: the bridge either applies the projection faithfully (disclosed) or passes the full upstream payload through unchanged with a disclosed, logged, counted skip reason. A projection may be applied only when EVERY carrier of the list document (the text block carrying it, and `structuredContent` when it mirrors the wrapper shape) can be re-derived from the same projected list; otherwise the whole result passes through unmodified. Skip/reject signals must be registered events that actually reach the log lane (the closed `eventMessage` vocabulary drops unregistered event names at runtime). No partial payloads masquerading as complete projections.
- R7 (non-interference): Tools that are not allowlisted — including similarly named tools on other servers and the same proxy tool on other paths — behave byte-identically to today when no explicit projection request is sent; the outer envelope gains no `projection` key for them.
- Non-goals (unchanged): no Proxmox/OPNsense entries; no new config surface; no bridge-side JMESPath; no new paging/retention mechanism; no numeric performance AC; no projection of `search_tools`/`describe_tool` results; no change to session-projection (`projection.go`) semantics — the feature is field projection and must not be conflated with session projections in code or docs.

## 4. DESIGN
Selected approach (unchanged in kind, corrected in mechanics): pure field-projection engine in NEW package-private `internal/service/field_projection.go`, invoked from `callTool` after `decodeUpstreamResult` (tools.go:1119) and BEFORE both delivery sites (E11) and before `t.boundedCallToolResult`. Single-source-of-truth rule (F1): the engine consumes the decoded `mcp.CallToolResult` and, when it applies, returns ONE transformed result value; callTool then (i) re-marshals that SAME transformed value into the bytes used for `payload["upstream_result"]`, and (ii) builds the returned `mcp.CallToolResult` from the SAME transformed value. No site derives from stale raw envelope bytes; no carrier of the document may retain unprojected objects when the disclosure says applied.
- D-table (decision table, normative; resolves F5):
  | entryMatch | request | select | isError | outcome | disclosure |
  | none | absent | — | any | pass-through | none (byte-identical envelope, R7) |
  | none | full | — | any | pass-through | {applied:false, mode:full, entry:"not_allowlisted", reason:"full_requested"} + counter skipped |
  | none | fields | — | — | REJECT pre-dispatch | fixed invalid_arguments; log projection_rejected reason not_supported; counter rejected |
  | match | absent | false | false | APPLY default | {applied:true, mode:default, entry, fields} |
  | match | absent | false | true | pass-through unchanged | none (AC6(a), byte-identical) |
  | match | absent | true | false | SKIP pass-through | {applied:false, mode:default, entry, reason:upstream_select_present} + warn + counter skipped |
  | match | absent | true | true | pass-through unchanged | none (AC6(a)) |
  | match | full | any | any | pass-through | {applied:false, mode:full, entry, reason:full_requested} + counter skipped |
  | match | fields | false | false | dispatch → shape check → unknown-field validation → APPLY | {applied:true, mode:fields, entry, fields} |
  | match | fields | false | true | pass-through unchanged | {applied:false, mode:fields, entry, reason:upstream_error} + counter skipped |
  | match | fields | true | — | REJECT pre-dispatch | reason select_conflict; counter rejected |
  | match, shape broken | fields | false | false | SKIP pass-through | reason per F4 (never unknown-field rejection) + warn + counter skipped |
  | match, unknown fields | fields | false | false | REJECT post-dispatch | fixed invalid_arguments; log projection_rejected reason unknown_field_selection; counter rejected |
  Malformed request (any entry): pre-dispatch reject, reason malformed_request, counter rejected. Rejection disclosure rides the error result only via the log/counter (error results carry no projection key).
- C1 Allowlist table (unchanged in shape; defaults per amended AUTO-DECISION: endpoint entry Id, Name, Type; container entry Id, Name←Names[0], State, Image): exact identity matching only; entryID stable for disclosure (`portainer.EndpointList`, `portainer.docker_proxy /containers/json`); fixed literal `not_allowlisted` for non-matching entries in disclosures/counters.
- C2 Projection request: optional `projection` object in `CallToolInputSchema` + wire struct; admission validation per R4/F7; `upstreamSelectPresent` computed at admission from args (E3: `select` is an optional string member) and passed into the engine input.
- C3 Engine (corrected): input = decoded upstream result, entry match, request, selectPresent, isError; output = single transformed result (or the original) + decision {outcome, mode, entryID, fields, reason}. Unwrap rules per E2/E3/ASSUMPTIONS. Carrier completeness rule (F1/R6): the projection is applied only if (a) the first text block parses per the unwrap rules as a list of objects, AND (b) `structuredContent`, when present, mirrors the wrapper shape (`{"result": "<string>"}`) so it can be re-derived from the same projected list; if (b) fails, the WHOLE result passes through with reason `structured_content_not_mirrorable` — never a text-only partial projection. Reason enum (closed): full_requested, upstream_select_present, upstream_error, payload_unparseable, payload_shape_unexpected, item_shape_unexpected, structured_content_not_mirrorable; rejection reasons: malformed_request, not_supported, select_conflict, unknown_field_selection.
- C4 Disclosure (corrected): the outer envelope `projection` object as r1 (applied, entry, mode, fields, reason?) — and, when the result is over-ceiling, the SAME disclosure is carried on `resultEntry` and merged into preview/page/terminal metadata (E12), so every delivery path discloses. Envelope byte-compat rule unchanged (no key when nothing requested and no match).
- C5 Rejection path (corrected): knowable rejections (malformed request, not_supported, select_conflict) reject pre-dispatch at admission with the fixed payload-free invalid_arguments result; unknown_field_selection rejects post-dispatch with an execution state consistent with the completed upstream call. No caller value is ever echoed in a message or log (count only).
- C6 Composition with upstream `select` (corrected): governed by the D-table via `upstreamSelectPresent`; default mode never composes with a present `select`.
- C7 Observability hooks (corrected): `bridge_projection_total{server, tool, outcome}` with the F6 label rule (tool ∈ {EndpointList, docker_proxy, not_allowlisted}); log events `projection_skipped` (call_tool, warn/degraded) and `projection_rejected` (call_tool, warn/denied), both REGISTERED in `internal/observe/log.go` `eventMessage` (E10) and pinned in docs/logging-contract.md; fields `tool`/`server`/`count` + one new union field `projection_reason`. full_requested skips log nothing (intentional opt-out; disclosure + counter carry it); degradation skips log one warn record. - Compatibility/security/failure behavior (corrected): projection output never aliases input slices (retained bytes outlive the request); `fields` strings validated and bounded (≤64 bytes, ≤16, unique), never echoed; malformed JSON anywhere → full pass-through; sessions share only the immutable allowlist; result-store ownership/paging mechanics unchanged (only the disclosure field threads through commit/entry).
