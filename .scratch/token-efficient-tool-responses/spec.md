## 2. REQUIREMENTS

- **R1 (pass-through).** A result whose measured bytes are ≤ `delivery_ceiling_bytes` is delivered byte-identically to the pre-change SDK marshaling; its oracle is one small-result golden fixture per paged surface, each with its own literal expected byte string and length — the four surfaces' pre-change result envelopes differ, so no single fixture supplies the literal for all four (AC1) — no re-marshal through the new path. The ≤ boundary's equality half is pinned: a result measuring exactly `delivery_ceiling_bytes` (8192 at the default) passes through unchanged, and only one measuring `delivery_ceiling_bytes` + 1 (8193) pages — the boundary pair of AC1's exactly-at-ceiling fixture and AC40's +1 fixture fails any implementation that pages at ≥ the ceiling.
- **R2 (measurement).** The measure is the byte length of the serialized complete `mcp.CallToolResult` as produced by the bridge's existing response path for that result — JSON-RPC envelope framing is outside the measure; every occurrence in the serialized form counts; no deduplication, reordering, or pretty-printing may reduce it. The sole permitted oracle form is a golden fixture with a literal expected byte string and a literal expected length, asserted on duplicate-bearing fixtures, one above and one below the ceiling.
- **R3 (preview).** An over-ceiling retainable result is delivered on every paged surface (call_tool, directly invoked projected tools, search_tools, describe_tool) as a preview ≤ `preview_ceiling_bytes` whose `Content` is a non-empty UTF-8-safe byte prefix of the serialized result; the preview is itself a `mcp.CallToolResult`, and its bound is measured by the same SDK marshaling of that preview value (R2's measuring rule), not by the length of its `Content` string alone. The preview metadata set — single-sourced; §3's Preview entry references it — is exactly `{paging_required: true, handle, total_bytes, is_error, upstream_code? per R8}`.
- **R4 (handles).** Handles are opaque `crypto/rand` values (43-char base64url), bound to one owner namespace — (session, stamped epoch) or the session-less publisher namespace — and expire at `handle_ttl`; the epoch component is the value the inbound layer already stamped, read via `requestExposureEpoch` (internal/service/session_exposure.go), never client-supplied, and the seam performs no admission. Discriminator (observable at the seam): a request is session-ful iff its inbound headers carry a non-empty `Mcp-Session-Id` value (internal/service/inbound.go:24) after the bridge's own header handling; a request with no such header is session-less and is the only kind that reaches the shared publisher namespace. Retention for a session-ful request additionally requires a stamped epoch readable through `requestExposureEpoch` (internal/service/session_exposure.go:146-164); when that presence flag is false, no handle is issued and nothing is retained (R10 `result_epoch_unresolved`); a session-ful request never falls back to the publisher namespace. `retrieve_result` is the only handle-accepting surface; exactly the six enumerated handle rejections there — unknown, forged, cross-namespace, post-epoch-bump, retired-namespace, session-ful no-epoch binding (a well-formed handle under a session-ful request whose stamped epoch is absent or empty) — are byte-identical: the same serialized code `invalid_handle`, rendered as §3's pinned rejection value — the errorResult-shaped tool result defined once in §3: `isError` true, exactly one `TextContent` carrying the code's fixed message, `StructuredContent` carrying the code — with no page content, no page metadata, no handle, one shared rejection path, no cause-distinguishable shape. The typed codes `result_expired`/`result_evicted` (R16) and `invalid_arguments` (R13) lie outside that byte-identical set. Entries expire at `handle_ttl`, markers/tombstones at `tombstone_ttl` (R16); an entry's expiry aligns with its handle's — a handle never outlives a retrievable entry (AC5).
- **R5 (paging completeness).** Each page is a rune-aligned valid-UTF-8 slice of the serialized retained bytes (cut points fall only on rune boundaries; SDK JSON marshaling is valid UTF-8), so concatenating all pages of a handle reproduces the retained serialized bytes exactly. Sizing rule (pinned, deterministic, no fixed-point search): the preview's `Content` is the longest rune-aligned prefix of the serialized retained bytes whose serialized preview envelope, with preview metadata at R11(g)'s pinned maximum widths, is ≤ `preview_ceiling_bytes`; and each page's `Content` is the longest rune-aligned prefix of the not-yet-paged retained bytes whose serialized page envelope, with page metadata at R11(g)'s pinned maximum widths (`page`, `total_pages` and `remaining_pages` at 10 digits regardless of their actual values), is ≤ the delivery ceiling pinned at retention. Because every envelope is sized at the pinned maximum metadata widths, a page's size never depends on `total_pages`' actual digit width: one greedy pass over the retained bytes both cuts every page and yields `total_pages` as the number of pages it produces — `total_pages` is read off the completed pass, never fixed up during it. Page cut points are chosen against the serialized page value (the page envelope as serialized, after JSON escaping), never against a raw slice length, so a page's escaped serialization never exceeds the pinned delivery ceiling. The page metadata set — single-sourced; §3's Page entry references it — is exactly `{handle, page, total_pages, remaining_pages, total_bytes, remaining_bytes, is_error, upstream_code? per R8}`; `remaining_bytes` is measured on the retained serialized bytes, the same byte domain as `total_bytes` — the retained bytes after this page's slice. Reconstruction is per-surface observable: each paged surface's issued handle is retrieved through `retrieve_result`, its pages concatenate to that surface's own independent golden literal (R1/R2's per-surface fixture form), and repeated retrieval of the same page delivers byte-identical output (AC19, T5's integration).
- **R6 (bounded retention).** Retention is hard-bounded per namespace in bytes and entries, capped per entry by `max_retained_result_bytes`, and evicts FIFO / expires by TTL under those bounds. Per-namespace accounting domain: bytes under `max_bytes_per_namespace` count entry payloads only — markers and tombstones count against `max_bytes_aggregate`. The per-namespace bound is enforced by eviction alone and has no refusal terminal: R11(c) guarantees `max_bytes_per_namespace` ≥ `max_retained_result_bytes`, so an entry that passes the per-entry cap always fits after FIFO eviction of that namespace's older entries — per-namespace infeasibility is unreachable, and only the aggregate bound can refuse (AC15). Charge disposition: a cap-evicted marker (R16) releases its 256-byte charge immediately at the evicting commit, and namespace retirement releases every record it held (entries, their reservations and live markers; retirement evictions install no markers), with AC39 and AC43 asserting exact aggregate deltas (before/after) for both paths. Eviction never crosses namespaces: a namespace's overflow evicts only that namespace's entries. The aggregate bound `max_bytes_aggregate` is HARD — every retained record, whether entry, tombstone or sweep marker (R16), is admitted only if the total retained bytes across all namespaces stay within it after the commit. Aggregate admission for an entry or tombstone commit evicts only that namespace's FIFO-oldest live entries — never another namespace's records: an expired or evicted entry holds no aggregate charge to release (its reservation became its marker's charge at the transition, R16); outside retirement admission, only R16's marker cap evicts a marker — and an entry is admitted only if the same commit can also hold its 256-byte eviction/expiry marker (R16); the reservation is durable — an admitted entry's aggregate footprint is its serialized bytes plus 256 reserved bytes, converting into the marker's charge at expiry or eviction and leaving when the marker clears — so a marker commit draws on its entry's reservation and never evicts another record; outside retirement admission, R16's marker-cap eviction is the sole marker-evicting exception, and it evicts only a marker (the namespace's oldest), never an entry or tombstone — a retirement commit instead releases its namespace's records under R7's disposition. Only if an entry commit is still infeasible is the result delivered as the `result_aggregate_capacity_exceeded` terminal (no handle); a retirement commit is never infeasible (R7) — a namespace holding at least one live record funds its tombstone from its own releases, and a namespace holding none has no store presence to retire. Consequence, per R16's retrieval-resolution rule (stated once there): every admitted entry yields its deterministic typed code (`result_evicted` / `result_expired`) per that rule — pages while the entry is live, otherwise the transition-fixed cause's code for that marker's lifetime, `invalid_handle` at and after that marker's deadline (R16's half-open rule) — every store-level retirement (R7) completes with its tombstone, and a commit landing on a retired namespace yields `result_namespace_retired` regardless of any surviving record: the retirement is visible to the commit through the shared pre-commit owner resolution (the session/SDK mapping and live owner are gone, R7), never through tombstone presence, so the same terminal follows while the tombstone is live, after the tombstone clears (R16's half-open rule), and after the zero-effect completion that removed the namespace's only record, and no post-retirement commit creates a fresh namespace, retains an entry, increases the aggregate or persists anything (R6's retained-metadata bound) — and the byte-identical `invalid_handle` (R4's shared rejection; AC18/AC39) covers exactly the states with no retrievable record — a retired namespace (terminal precedence, §3), a cleared marker, and a marker evicted by R16's cap; `invalid_handle` never encodes a FIFO or TTL eviction that left a live marker, nor a tombstone-less retirement. Retained-metadata bound (there is no fourth record class): the store's retained state is exactly its live entries (serialized bytes + 256-byte reservation), live markers and live tombstones, each charged as specified above — no empty namespace container and no deferred-retirement bookkeeping exists: a namespace whose last live record leaves (by eviction, expiry, or the completing retirement commit) leaves no container record behind, and a retirement is never refused or deferred between sweeps (R7): a trigger on a namespace holding no live record persists nothing — no tombstone, no container, no retry — so total retained memory is a function of the configured bounds and the current record set alone, and many-session churn cannot grow it (AC7's churn oracle).
- **R7 (retired namespace).** Namespace retirement leaves a store-internal tombstone with a stated lifetime (`tombstone_ttl`) and an explicit clearing condition, the half-open rule pinned in R16 — the tombstone is live while the clock is before its creation time plus `tombstone_ttl`, and at now ≥ its creation time plus `tombstone_ttl` it is cleared, its 256 bytes leaving the aggregate accounting — counted in retention accounting at a fixed per-record charge of 256 bytes; the retirement is admitted by construction — no refusal terminal and no retry exists for retirement (R6, AC38): the retirement commit atomically removes every entry and marker record of that namespace, so only the tombstone survives it — it first releases the creating namespace's live markers (the released set is exactly that namespace's live markers, each surrendering its 256-byte aggregate charge, R6's charge disposition), then removes its expired/evicted records and its remaining entries (R6's order), and installs the tombstone in the same commit; the tombstone is funded by the commit's own releases: every live record the namespace holds surrenders at least 256 aggregate bytes (a live entry its serialized payload plus its durable 256-byte reservation, a live marker its 256-byte charge), so whenever the namespace holds at least one live record the post-commit aggregate never exceeds the pre-commit aggregate and the tombstone always fits the hard aggregate bound (R6) — the trigger's own production state funds the completion, and no stored record or later rediscovery is needed; a trigger arriving for a namespace that holds no live record has no store presence to retire (R6's retained-metadata bound — no container record exists) and completes with zero store effect: no tombstone, no aggregate delta, nothing persisted, no sweep retry; every store-level retirement — a namespace holding at least one live record — completes with its tombstone in its trigger commit. Retrieval of a handle from a retired namespace returns the byte-identical `invalid_handle` rejection (R4's retired-namespace class; retirement is terminal and precedes entry/marker state, §3). Retirement's production call sites are all on the inbound path and all funnel through the shared retire seam — `ToolSurface.retireLiveOwnerAtInboundLock` plus `ToolSurface.cleanupRetiredOwner` (internal/service/projection.go:863/:877): the two expiry-reaping invocations of `reapExpiredLocked` (internal/service/inbound.go:522 in the existing-session branch and :767 in the new-session branch, each flowing to `cleanupRetiredOwners` at :676/:770), the missing-session rewrite branch retiring the live owner (`retireLiveOwnerAtInboundLock` at internal/service/inbound.go:808 plus its `cleanupRetiredOwner` call at :813, inside the `if mappedSDKRequest && responseObserver.missingSession()` branch spanning :799-813), and session `DELETE` termination (internal/service/inbound.go:950-966, the `r.Method == http.MethodDelete` branch: `retireLiveOwnerAtInboundLock` at :962 plus its `cleanupRetiredOwner` call at :966). Decision: T3 wires the retention-namespace sweep at each call site — the shared seam is named for review orientation but is not made a write root — and T3's existing `internal/service/inbound.go` (sweep-trigger call only) write root is the delivery vehicle; AC43 (`TestInboundRetirementHooks`) asserts that a retirement through any of these paths retires the retention namespace — installing and counting its tombstone when the namespace holds a live record (funded per R7; no admissibility condition remains) and completing with zero store effect when it holds none — with the retired owner supplied only by the production trigger, never reinjected by the fixture (AC38's cheap false pass excluded).
- **R8 (execution facts).** `is_error` and `upstream_code` are preserved identically on the preview, every page, and every terminal; paging never re-executes the upstream; bridge-side dispatch failures remain small `errorResult` responses, never paged. The prohibition is oracle-backed by upstream invocation count, never by byte reconstruction alone: an invocation-counting upstream fixture — the counting stub is the independent observable, not the implementation under test — observes exactly one execution (the original delivery) and zero additional executions across full page retrieval, repeated retrieval of the same page, and every retrieval-failure outcome (`invalid_arguments`, `invalid_handle`, `result_expired`, `result_evicted`); byte-identical reconstruction with a count above one fails (AC6/T3 on call_tool, AC19/T4 on call_tool and direct invocation, T5's integration end-to-end). Presence test: the upstream result has `is_error` true and the extracted value is a JSON string; otherwise `upstream_code` is absent from every rendered surface, never null. Producer per surface: on `call_tool`, `structuredContent.upstream_result.structuredContent.code` of the bridge envelope (internal/service/tools.go); on directly invoked projected tools, the upstream `CallToolResult`'s own `structuredContent.code`; on `search_tools` and `describe_tool`, the result is bridge-generated — `is_error` is always false and `upstream_code` is always absent on those two surfaces. A value is truncated whenever the JSON-escaped serialized contribution of its complete decoded value plus the JSON-escaped `[truncated]` marker exceeds `max_upstream_code_bytes` — the trigger is the escaped serialized contribution, never the decoded length (e.g. a value of ten `"` characters at a bound of 11 decodes to 10 bytes while its escaped contribution is 20, so it is truncated) — deterministically in the per-entry pinned `upstream_code` rendering only: the rendered value is the longest rune-aligned prefix of the decoded value whose JSON-escaped serialized form — the escaped characters of the value as it appears inside the JSON-serialized envelope, not counting the member's delimiting JSON quotes — plus the JSON-escaped literal `[truncated]` marker appended directly after it is ≤ `max_upstream_code_bytes`; the literal `[truncated]` marker is inside the bound, and this rule selects exactly one prefix for every input, so R9's rendered-value pinning is testable against an exact golden literal (asserted in AC9); retention stores the unmodified serialized result, and the bound and its marker never edit it: `total_bytes` (R14), `remaining_bytes` (R5), AC6's byte-exact literals and page reconstruction all stay in the unmodified serialized-result domain. The bound applies to the escaped serialized contribution of `upstream_code` — the value as it appears inside the JSON-serialized envelope — not to its decoded length: the value's escaped serialized form, `[truncated]` marker inside that bound, never exceeds `max_upstream_code_bytes`, so an admitted config cannot push a preview, page or terminal past its ceiling through code escaping.
- **R9 (pinning).** The per-entry `upstream_code` bound and rendered value, and the page/preview sizing derived from the ceilings, are fixed at retention time; a config reload of `max_upstream_code_bytes`, `delivery_ceiling_bytes` or `preview_ceiling_bytes` cannot change a re-retrieved page's bytes or `total_pages`. TTL deadlines are pinned at record creation the same way: an entry's `handle_ttl` deadline is fixed when the entry is committed, and a marker's or tombstone's `tombstone_ttl` deadline is fixed at its transition/creation instant; a reload of `handle_ttl` or `tombstone_ttl` never moves an existing record's deadline — only records created after the reload adopt the reloaded values, and R16's deadline arithmetic always reads the record's pinned creation-time value, never the current config (asserted per AC29).
- **R10 (terminals).** Each unretainable over-ceiling outcome — per-entry cap exceeded, aggregate cap exceeded, namespace retired before commit, entropy failure at handle generation, session-ful call with no stamped epoch at retention — produces a distinct typed terminal preview (no handle), bounded by `preview_ceiling_bytes` — the bound measured by R3's measuring rule (the serialized terminal value after escaping, never the length of its `Content` alone) — with a non-empty UTF-8-safe prefix and preserved execution facts; asserted per terminal under one pinned terminal-evaluation order, evaluated once per input in this fixed order: per-entry cap exceeded (`result_capacity_exceeded`) → aggregate cap exceeded (`result_aggregate_capacity_exceeded`) → namespace retired before commit (`result_namespace_retired`) → entropy failure (`result_entropy_unavailable`) → no stamped epoch (`result_epoch_unresolved`) — consistent with R14's lifecycle note; an input satisfying several causes yields exactly the earliest cause in this order, asserted by one overlap fixture (a serialized result over `max_retained_result_bytes` whose commit would also exceed `max_bytes_aggregate` resolves to `result_capacity_exceeded`). Terminal `Content` sizing is normative, mirroring R5: the longest rune-aligned prefix of the serialized result whose serialized terminal envelope, with terminal metadata at R11(g)'s pinned maximum widths, is ≤ `preview_ceiling_bytes` (R5's rule covers preview/page envelopes only). The terminal `StructuredContent` set — single-sourced; §3 Terminals and R11(g) reference it — is exactly `{retention, execution_state: "executed", total_bytes, is_error, upstream_code? per R8}`; no `paging_required`, no `handle`. Truncation on a terminal is always machine-detectable without altering R8's preserved `is_error`: every terminal carries a non-empty `retention` code and a `total_bytes`, and its `Content` is always a proper prefix of the serialized result with `total_bytes` strictly greater than the delivered prefix's byte length — always proper because every terminal arises from an over-ceiling outcome while the terminal `Content` is bounded by `preview_ceiling_bytes < delivery_ceiling_bytes`; a client comparing `total_bytes` against the received content bytes detects the truncation, and `retention` names its cause; no terminal ever reports a complete result.
- **R11 (config validation).** Relations (a)–(k) are validated at config load with typed diagnostics, each relation carrying a named diagnostic code — every new code (`ceiling_order`, `entry_cap_order`, `namespace_cap_order`, `ttl_invalid`, `aggregate_order`, `envelope_feasibility`, `entry_cap_bound`, `upstream_code_marker_bound`) is registered in internal/config/diagnostics.go's closed `diagnosticCodes` array; T1's relation range and registered-code list extend accordingly, and §6's `max_upstream_code_bytes` rule row includes this floor); startup fails closed: (a) `preview_ceiling_bytes < delivery_ceiling_bytes`, equal rejected (`ceiling_order`); the 6-byte `\uXXXX` figure describes first-serialization escaping (R2's measure), not this re-encoding — 6 bytes is retained as a declared conservative pinned constant: the last-rune headroom (g) demands is exactly 6 bytes — room for at least one full escaped rune at maximal metadata, so no admitted config can force an empty preview or page through a single rune's escaping. The maximal-metadata envelope is computed with the `Content` block representation pinned once here for R2, R5, R10 and this check: the envelope contains the `Content` item present with zero text bytes — exactly one `mcp.TextContent` block serialized as `{"type":"text","text":""}` — so the item's structural bytes count inside the inequality; `Content` is never absent and never an empty array in the maximal-metadata envelope, and the pinned 6 bytes cover re-escaping only, not content bytes. - **R16 (sweep markers).** Expiry and eviction install store-internal markers parallel to the tombstone: stated lifetime (`tombstone_ttl`), explicit clearing deadline — the expiry/eviction instant plus `tombstone_ttl`, measured by the clock, under the half-open rule pinned once here and applied verbatim by R7, AC5, AC18 and AC39: a marker or tombstone is live while the clock is before transition + `tombstone_ttl`; at now ≥ transition + `tombstone_ttl` it is cleared, its 256-byte charge is released, and retrieval returns the byte-identical `invalid_handle`; a sweep only reclaims memory — a born-dead marker (one whose deadline the clock has already reached at installation) is discarded at installation: it never enters the live-marker set, never consumes a marker slot, and never invokes cap eviction, so it can never evict a live marker and handle resolution stays a function of logical state, never of sweep progress — and the AC39 oracle covers the residual case: with the marker cap full, an already-dead transition is discarded and every live marker and every live handle's retrieval code is unchanged, the aggregate delta exactly zero, asserted before and after the born-dead transition; logical expiry is evaluated from timestamps, never sweep progress (evict at T, first sweep at T+10m: T+14m → `result_evicted`, T+16m → `invalid_handle`) — counted in `max_bytes_aggregate` at R7's fixed 256-byte charge, drawn from the installing entry's durable reservation (R6), so a marker's admission never refuses; the only record a marker commit may evict is another marker, under the cap below. Live markers per namespace are capped at `max_markers_per_namespace` (§6) and are cleared at now ≥ their transition plus `tombstone_ttl` (AC39); beyond the cap the oldest marker in that namespace is evicted first, and a marker evicted by the cap makes its handle resolve to the byte-identical `invalid_handle` immediately (R4; AC18/AC39) — R6's sole marker-eviction exception outside retirement admission (R7). Retrieval resolution is one rule, stated once here and referenced by R6 — a function of logical state, never of marker materialisation: a handle returns its entry's pages while the entry is live (the clock before `handle_ttl`); at now ≥ `handle_ttl` or evicted, it returns that terminal cause's typed code (`result_expired` / `result_evicted`) — the cause fixed at the transition, an evicted entry never later expires, so eviction's code wins — for that marker's `tombstone_ttl` lifetime whether or not a sweep has yet materialised the marker; and the byte-identical `invalid_handle` (R4) at and after that lifetime's deadline (now ≥ transition + `tombstone_ttl`): from the marker's stated clearing, immediately when its marker was evicted by the cap, and always for a retired namespace, whose terminal precedence (§3) is checked before entry/marker state even when the entry or marker is also expired or evicted (R4/R7). ACs pin the injectable clock; none depends on sweep scheduling.

## 8. NON-GOALS and OPEN DECISIONS

**Non-goals.** No content summarization, compression, or semantic truncation · no upstream body-cap enforcement on the shared client/transport · no change to `catalog_changed` semantics, catalog-revision checks, `decodeStrict` admission, or the `errorResult` taxonomy · no multi-process retention (handles die with the process) · no streaming/chunked transport · ticket-02 count clipping and provenance-envelope work remain separate tickets.

**Open decisions** (defaults chosen here; an owner may flip one without reopening the requirements):

- **OD1 page sizing.** Pages derive from the delivery ceiling pinned at retention, cut on rune boundaries; no separate `page_bytes` key (avoids a fifth ceiling relation to validate).
- **OD2 publisher namespace.** Session-less results share one publisher namespace under the same per-namespace bounds (preserves recoverability for session-less discovery).
- **OD3 tombstone and marker accounting.** Tombstones and R16 markers count against `max_bytes_aggregate`, not the per-namespace byte bound, each at R7's fixed 256-byte per-record charge, and clear by `tombstone_ttl`; every admitted entry also holds a durable 256-byte marker reservation (R6), converting into its marker's charge at expiry or eviction — the reservation and the marker charge are the same 256 bytes at different life stages, never additive. No closed-form aggregate-headroom arithmetic is stated: the number of live tombstones (retirements landing inside one `tombstone_ttl` window) is not derivable from configured keys alone, so the aggregate bound is enforced where it is hard — at commit admission (R6, AC15), with retirement admission funded by its own releases rather than by headroom (R7, AC38) — not by documented headroom.
