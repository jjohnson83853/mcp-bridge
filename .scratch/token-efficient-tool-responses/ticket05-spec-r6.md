## 2. REQUIREMENTS
- R1 (scope): Exactly two allowlisted operations: (a) server `portainer`, upstream tool name `EndpointList`; (b) server `portainer`, upstream tool name `docker_proxy`, discriminator `path == "/containers/json"` (exact). Proxmox/OPNsense EXCLUDED (conditional unmet). Does not weaken AC1–AC7.
- R2 (default projection + disclosure): When no explicit projection request is present and an entry matches, the bridge replaces the upstream list payload with the entry's default projection across EVERY carrier — the text block AND the payload-bearing structuredContent member — and discloses it per the D-table channel: on the call_tool built-in via the outer envelope's `projection` member; on the direct path via the bridge-owned reserved member `mcp_bridge_projection` on the result's StructuredContent (C4b). Non-payload upstream structuredContent members are preserved verbatim; the payload-bearing member is rewritten to the projected list (carrier completeness, F-A). The response never presents projected objects as the upstream's full shape; no unprojected upstream object may remain in any carrier when the disclosure says applied.
- R3 (full opt-in): `projection.full` on the call_tool built-in returns unprojected objects, still ceiling-bounded. The direct path has no bridge-level projection argument; its opt-out is the same tool invoked through the call_tool built-in with `projection.full` — the full result is always reachable (AC2).
- R4 (custom selection + precedence + admission validation): A field selection overrides the default projection, copies raw upstream top-level item keys verbatim, and rejects unknown fields deterministically — post-dispatch, payload-relative, AFTER shape confirmation, and only against a NON-EMPTY list; an EMPTY list cannot establish unknown-ness, so fields mode on an empty list is ACCEPTED with an empty projected list and disclosure (N1). Admission validation (pre-dispatch, fixed messages): `full` and `fields` together → invalid_arguments; wire→request mapping (N9): a PRESENT `fields` member — even an empty array — is a fields request subject to the bounds (so `fields: []` rejects pre-dispatch); only an ABSENT or NULL `projection` key means no request; `projection: {}` and `{"full": false}` without a fields member are treated as absent; `full: true` with a fields member is the full+fields conflict; any other shape is invalid_arguments. Bounds: `fields` = 1–16 unique strings, each 1–64 characters from `[A-Za-z0-9_]`, AND the fields array's total ENCODED width ≤ the runtime-derived disclosure budget (F-D): `fieldsBudget = PreviewCeilingBytes − MaxUpstreamCodeBytes − retainedEnvelopeHeadroom(6) − measured(probe envelope with the maximal base render metadata + the fixed disclosure keys and an empty fields array)`, computed with the same measure/encode helpers the delivery path uses; under the default bounds (1536/512/6) this is ≥ 512 and the documented default cap is 512 (`projectionFieldsMaxEncodedBytes` under defaults). A request whose fields array exceeds the runtime budget is a deterministic pre-dispatch invalid_arguments rejection (reason `not_supported` — the selection is not supported under the current configuration; F-D). The MAXIMAL LEGAL REQUEST is the largest fields array satisfying BOTH the count/length/alphabet bounds AND the runtime budget (computed, never assumed). Unknown-field rejection requires a non-empty list whose items all lack a requested field.
- R5 (allowlist discipline): Explicit identities (server id + raw tool name + discriminator), never patterns; each entry justified by captured schema/payload evidence; unrelated Docker paths never projected, labeled `not_allowlisted` (N3).
- R6 (safe degradation): Upstream tool errors, empty lists, carrier failures (non-list payloads, unparseable wrappers, payload-bearing structuredContent members that do not mirror the wrapper, non-object items), default-mode AGGREGATE all-default-fields-missing, and direct-path reserved-key collisions must not silently drop fields: the bridge applies the projection faithfully (disclosed on its D-table channel) or passes the full upstream payload through unchanged with a disclosed skip per its channel. Aggregate predicate (N10): the skip fires only when EVERY item misses ALL default/requested fields (reason `item_shape_unexpected`); partial misses project present members (AC6(e)). Empty list + `fields` is ACCEPTED; non-empty list + a requested field absent from every item is a deterministic REJECTION. Skip/reject events registered in the closed `eventMessage` vocabulary. No partial payloads masquerading as complete projections.
- R7 (non-interference): Non-allowlisted tools byte-identical to today when no effective request is sent — both invocation paths, no reserved member, no disclosure, unchanged sizes; render metadata gains a disclosure key only when a bridge decision actually produced one and the runtime budget admits it (F-D); bridge-writers only, shape-validated (F-H).
- Non-goals (unchanged): no Proxmox/OPNsense; no new config surface; no change to config validation/feasibility (F-D); no bridge-side JMESPath; no new paging mechanism; no numeric performance AC; no projection of search_tools/describe_tool results; no change to session-projection semantics.

## 4. DESIGN
Selected approach (unchanged in kind; carrier + budget completed): pure field-projection engine in NEW package-private `internal/service/field_projection.go`, invoked from TWO call sites — `callTool` at the decodeUpstreamResult call site (tools.go:1000) and `boundDirectExecution.call` (direct_execution.go:30) between its decode (:53) and result construction (:60-64) — in both cases before `t.boundedCallToolResult` (direct call site :65).
- Single-transformed-result rule (F1, both paths): APPLY → one transformed result feeds every downstream derivation on that path (callTool: `payload["upstream_result"]` bytes + returned result + envelope disclosure; direct path: returned result's Content + StructuredContent with the payload-bearing member rewritten per F-A and the C4b reserved-member disclosure); SKIP/pass-through → original bytes/value flow unchanged, no disclosure member added to the upstream result (channel rules below).
- NORMATIVE D-TABLE (F-B reinstated, 21 rows; each row: outcome, reason, disclosure CHANNEL — P = payload member (`projection` envelope on the multiplexer; `mcp_bridge_projection` reserved member on the direct path), L = one registered log record, C = counter; invocation surface noted where it differs):
  1. no entry match | request absent/empty (N9) | — | — | outcome pass-through | reason — | channel NONE (byte-identical, R7)
  2. no match | full | — | no error | pass-through | full_requested | P + C
  3. no match | full | — | error | pass-through | upstream_error | P + C
  4. no match | fields | — | — | REJECT pre-dispatch | not_supported | L + C
  5. match | absent | select absent | no error | shape ok | APPLY default | — | P
  6. match | absent | select absent | no error | carrier failure | SKIP | payload_unparseable | payload_shape_unexpected | item_shape_unexpected | structured_content_not_mirrorable (per failure) | P + L + C
  7. match | absent | select absent | no error | shape ok, EVERY item misses ALL default fields (aggregate, N10) | SKIP | item_shape_unexpected | P + L + C
