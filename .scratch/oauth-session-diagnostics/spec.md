## Problem Statement

The MCP bridge's terminal HTTP diagnostics do not distinguish enough of the request decision path to diagnose recurring authentication/session failures safely. Outer OAuth rejection occurs before the current inner completion owner; inner rejection can mean an absent session or an existing session with a different exact-bearer binding. Status alone cannot distinguish these paths, and HTTP success does not establish tool success. The retained normalized Loki sample preserved status and fixed message but not decisive stage/reason.

The particular incident cause remains UNKNOWN. Reconnecting OMP is the only observed restorative action and may replace both credentials and session state. The user's hypothesis that OMP retains a long-lived connection without refreshing its access token while Gemini may use fresh connections is unverified client behavior. TCP connection, MCP session and access-token lifetimes are independent: stale token A can fail outer OAuth; valid token B with retained session S_A can pass OAuth but fail inner exact-bearer comparison; fresh TCP alone does not imply a fresh MCP session. Reconnect success cannot choose between those explanations. Active OMP/Gemini builds and actual renewal behavior remain unknown; no refresh failure, expiry, restart remedy or historical cause is established.

The deployed application is current GitHub HEAD **e621622397298bb4eb44a9b0f5ff1a00d6f16300**, as confirmed by the user; local-only planning changes are not deployed. No image/digest attestation is required to establish that relationship. Runtime process/replica/stdout identity, effective policy and instrumentation availability are separate facts.

The objective is one truthful, privacy-bounded terminal completion attempt per completed inbound listener request, including outer rejection, with server-owned correlation and preserved causal/provenance fields through actual queried Loki. Stdout remains best effort; local JSON acceptance is not end-to-end delivery acceptance.

## Implementation Decisions

### Sole completion owner and inner contribution

Wrap the whole existing public listener composition before routing/OAuth, covering protected inbound, metadata, health and unmatched routes. Retain the existing logger/sink and downstream/configuration records. One private server-created owner holds bounded state, native writer and sole response observation. A private typed context marker detects it; a private writer-carrier interface recovers the same owner if the context marker is lost. A small by-value claimant lease controls finalization. The factory's facade embeds its owner/state rather than allocating a second observer or finalizer callback.

Existing owner means contribution only: preserve the incoming writer chain, reinstall the marker if recovered through the carrier, return a nonclaimant lease, and do not generate correlation, wrap again, reset a header or register another completion. A supported direct-inner call without an owner claims through the same mechanism; it cannot claim OAuth was evaluated.

The claimant registers one terminal finalizer. The inner handler removes its old separate timer/generator/observer/terminal logging defer, but retains the existing metrics/count conditions and a typed legacy-result contribution defer. For standalone fallback, the inner defer runs before the claimant finalizer; under the outer owner it contributes and the outer finalizer runs last. Existing admission/body-limit/delivery classifiers read the shared observation, preserving current order and metrics. No new counts for previously uncounted outer OAuth, metadata, health or unmatched requests.

The finalizer snapshots actual state and attempts the same completion on normal return or panic unwinding; it does not recover, suppress, inspect/log a panic value or invent a500. Preserve the current uncovered initial clock/generator panic window before finalizer registration rather than claiming complete panic coverage. Zero-write return retains null/unavailable status; the later implicit response from the HTTP server was not observed. Streaming/hijacked completion remains handler return/unwind, not per frame or connection lifetime. Abrupt process loss may lose the record.

Contributors use closed enums, booleans and validated owned refs; no arbitrary logger maps, claims, header maps or error prose. First actual decisive rejection is immutable. Later operation/delivery evidence cannot overwrite it. Opaque static pass-through is not static acceptance; inner authentication establishes that. Current auth, handler and logger entrypoints remain compatible through additive typed interfaces, whose exact signatures are retained in the linked technical resolution.

### Capability-preserving response observation

Use maintained, standard-library-only offline generation with checked-in concrete facades and a static factory switch, not64 hand-maintained variants, runtime reflection/generation or a new dependency. A fixed six-capability descriptor produces every method-set combination: flushing, hijacking, pushing, close notification, optimized reader copying and string writing. The factory probes/caches support once, selects one facade and initializes its embedded owner in place. No extra base/state allocation, large owner copy, allocated finalizer callback or per-request method map. Normal builds/tests use checked-in output; the retained generator is a maintainer tool, not a runtime step or throwaway scaffold.

Preserve both presence and absence of those six optional capabilities. The base writer provides ordinary response operations, unwrapping and the private owner carrier. Its always-present FlushError control adapter does not by itself advertise http.Flusher: when the underlying writer lacks ordinary flushing, the facade must not implement http.Flusher, even if native error-aware flushing exists. The adapter delegates actual native error-aware flushing first, otherwise supported ordinary flushing; if neither exists, it returns ErrNotSupported without committed status, false success, flush/write, byte mutation or other response side effect. Supported delegates preserve actual observation, including successful implicit status and errors, rather than inventing success. The selected six-capability facade policy is unchanged. This preserves response-controller flush observation while unwrapping supports native deadlines/full-duplex. Unsupported methods are not fake no-ops.

Forward promptly with exact delegate values/errors/channels, no new goroutine, body buffering, per-frame event or fallback copy buffer. Observe actual returned write bytes/first write failure and implicit200 on actual write or supported successful flush. Delegated reader copying with positive bytes can establish implicit200; zero bytes without other commitment stays unavailable. Failed error-aware flush without observed commitment does not invent200. Successful hijack without observed status stays null/unavailable; directly written hijacked bytes are unobservable, so byte bucket is unavailable. Keep current first-status-wins behavior; do not repair informational-response behavior incidentally.

The request-size limiter must retain the original pre-observer native writer for the HTTP server's close-on-limit signaling. Unwrapping alone is not proof of preservation. The current wrapper's always-advertised flush and absent hijack are established limitations; the selected transparency/restoration is a reviewed design change still requiring runtime proof.

### Correlation and selected response contract

The existing public X-Request-ID accepts a caller-supplied valid32-lowercase-hex value, otherwise generates, and is echoed only on the current inner path. It is therefore ineligible as trusted diagnostic identity. Preserve that policy and placement. The existing internal request ID is independently server-generated from16 cryptographic random bytes and already links downstream operations. Move that **single owned HTTP generation** before routing/OAuth and reuse it for owner, inner, terminal and trusted downstream request. Do not mint an unrelated HTTP ID or trust a JSON-RPC/public/caller ID.

The selected addition is one response **Mcp-Diagnostic-Id**, equal to that moved owned ID. This is a distinct header justified by caller-controlled public-ID semantics, not another generated identifier. It remains subject to the affected response-contract checkpoint; implementers cannot choose another header or add aliases. Do not expose an additional internal transport response header.

Private owner context takes precedence; caller public/internal/diagnostic headers cannot supply identity. Scrub caller diagnostic/internal values, install the owned response value before routing/auth/any write, and use the same owned value on the trusted downstream clone. Contributors do not regenerate/reset it. Request entropy or format failure removes diagnostic header/request_id and records unavailable; no caller/time/counter/hash fallback or retry. Public X-Request-ID remains independent even on diagnostic entropy failure; do not log/export its caller value.

The diagnostic header is neither credential, session ID, capability nor lookup API. It is emitted on ordinary origin responses, including401/403/404 and metadata/health when available. No CORS/expose-header/proxy changes or guaranteed browser/wrapper readability. Visibility distinguishes visible, absent_at_origin, stripped_in_transit, cors_invisible, wrapper_hidden and unknown using actual boundary evidence; time coincidence or wrapper traces are not exact bridge joins.

### Independent process/session/operation references

Generate separate independent128-bit cryptographic process incarnation once per process and live-session diagnostic reference once on actual new live-record insertion, encoded32 lowercase hex. Share process context across reloads/handlers; standalone default is process-scoped, not per constructor. Request/process/session failures are independent and explicitly unavailable, with one draw each and no retries, derived fallback or cross-reference derivation.

Preserve session ref/state when accepted reuse replaces the entire record or the same live entry is replaced. Generate neither on missing-header capacity checks nor reuse/mismatch/serialization/unavailable-state retry. Preserve existing response-header-driven insertion and DELETE deletion timing without adding success-status predicates. Reaping/deletion removes reference with entry; no tombstones, background cleanup, retained per-request map, lookup endpoint or index. Snapshot under the existing session lock, serialize outside it. Existing mismatch may include its live reference in server logs only, never a response; absent entry has none.

Absent/not-created/not-evaluated session ref is not_applicable; extant entropy failure unavailable; valid extant ref available; budget removal omitted_for_budget. Evidence-bundle privacy removal uses separate omitted_for_privacy, never falsifies the server entropy state. Random session refs are stable pseudonyms: export only for necessary pairing and verify existing restricted retention/access.

Reuse existing independently server-generated operation correlation only after its complete ownership path and schema compatibility are proved. Relation none/single/multiple/unavailable is bounded; only a single eligible operation ID may be optional. Multiple operations retain established per-operation records linked by request ID, never an unbounded terminal list. Unsafe/unproved ID is unavailable. Existing backend/operation IDs retain their different scopes; exporting existing records requires the same complete-byte privacy review, not automatic permission.

### Authoritative classification, serialization and byte limits

Record actual decisions in unchanged admission order. Observed credential absence/malformed bearer, explicit unusable keyset, explicit verified audience denial and scope denial have their finite outer reasons. The currently generic parser rejection uses jwt_invalid_other. Public expiry/not-yet-valid/issuer error sentinels are established API capabilities, but exhaustive returned-error wrapping/compound taxonomy remains unproved; do not infer specific reasons from fixture claims or match error strings. Unmapped branches fail exhaustive acceptance, not the privacy contract. Missing-header presence is observed separately; the inner admission layer does not reject it. Emit session_header_missing only after an authoritative actual protocol cause is established; exact SDK non-init status is still unknown. Legal fresh initialization is not a rejection.

Absent entry and existing comparator mismatch have distinct session reasons and retain current401/bare Bearer. Host/origin/body/capacity/routing retain their observed causes and status/order. Actual tool/upstream evidence contributes separately; delivery evidence never overwrites an earlier decisive rejection. Conditional path-bearing metadata mismatch is observed, not fixed.

Keep generic substring redaction, the configuration manifest and non-HTTP protections unchanged. The typed HTTP snapshot contains only concrete closed fields, no arbitrary maps/arrays/interfaces/custom marshaling. The projection owns the complete62-key schema universe. **Delete/clear all owned keys first** from any legacy/redacted candidate, including shared/base names and keys without sensitive substrings, then insert only freshly validated authoritative values. Also reject non-schema extras. Invalid/absent/unavailable/budget-omitted typed values must never fall back to producer fields, stale base values or redacted placeholders. Required invalid core makes the record invalid; freshly insert null status/canonical closed error as applicable.

Use a fixed-slot HTTP projection/encoder under the existing logger mutex, not an additional per-request overlay map. Reset owned slots, rebuild closed legacy values and actual snapshot fields once, then insert validated diagnostic fields. This narrow typed serialization lane lets safe schema/session/header-named enums survive without exempting arbitrary same-named maps or weakening generic redaction.
