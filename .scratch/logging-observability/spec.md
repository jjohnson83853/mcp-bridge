## Problem Statement

The bridge currently records too little information to distinguish HTTP admission failures, MCP/JSON-RPC execution failures, backend failures and client-facing response-shape differences. An HTTP 200 can contain a JSON-RPC error or a tool result with `isError`; these are not successful tool executions. Existing request logging omits the captured HTTP status, labels inbound authentication failures as backend authentication failures, combines Host/Origin rejection and measures the enclosing HTTP lifetime rather than necessarily the operation lifetime.

Operators need payload-free evidence that answers: what transport and MCP operation occurred, whether the request was admitted, which admitted tool/backend was involved, where a failure was observed, what the upstream and final response shapes were, and how long the operation and transport each lived. Logs must not claim that a particular shape proves LibreChat rendering failure.

The upgrade must preserve tool responses, JSON-RPC IDs, public correlation headers/envelope IDs, authentication and sessions, network behavior, metrics and LibreChat compatibility. It must also preserve the existing configuration-diagnostic logger contract. The user approved reuse of the real HTTP/MCP composition-root harness as the primary test seam and subsequently approved publication of six issue tickets. Those approvals are not requirements, design or task checkpoint approvals and do not open the implementation gate.

## Solution

Extend the existing structured logger and actual composition-root wiring; do not add a logging framework, collector, endpoint, authentication policy or production test interface. Emit bounded terminal records at three distinct boundaries: HTTP transport, decoded MCP operation and admitted backend tool dispatch. Carry fresh internal correlation through context, independently of all caller-controlled and public identifiers. Observe existing protocol processing rather than parse a second authoritative request/response stream.

Use finite classifications, binding-derived identities, independent timers and bounded shape summaries. Record facts at their owning boundary; represent unavailable evidence explicitly. Preserve every existing response and existing metric classification. Keep the established allowlist and focused secret-safety tests, extending them for new records without making arbitrary metadata loggable.

Requirements R1–R32 are the numbered stories below. Acceptance AC1–AC24 and tasks T1–T9 are defined under Testing Decisions; each story has acceptance coverage. Implementation is not authorized by this document.

## Implementation Decisions

**Boundary ownership and wiring.** The HTTP wrapper owns transport/admission facts and one terminal HTTP record, including pre-decode rejection and non-MCP paths. Register SDK receiving middleware through AddReceivingMiddleware before serving. Its MethodHandler receives the SDK context, decoded method and request, establishes a fresh operation scope, starts its timer, invokes the next handler exactly once with the derived context and observes that exact terminal result/error before returning it unchanged. It does not wait for HTTP exit. Request exposes GetSession, GetParams and GetExtra, not the raw JSON-RPC ID or an HTTP-context accessor; RequestExtra.CloseSSEStream is a close capability, not disconnect evidence. Method/parameter checks and some transport rejections precede the hook: absent callback/status/prefix parsing cannot establish a decoded method, malformed_request or method_not_found; use transport facts and unknown/not_observed. Notifications use the closed known-method contract, never a raw-ID heuristic. Admitted dispatch owns one backend terminal record, not rejected tool calls or low-level callbacks. Preserve ResponseWriter optional interfaces/flushing and return the original Write byte count and error unchanged while retaining its observed failure; opaque Flush/context cancellation is not proof of disconnection. No second decoder, response-body interceptor, SDK fork or test-only production entry point. Exact callback signatures remain in the separate readiness evidence, not this decision narrative.

HTTP records emitted while work is still unobserved use `not_observed`, not a predicted operation result. A stream can outlive its operation or finish while cancellation is still unwinding; correlated terminal records may therefore arrive out of order. Do not maintain a global client-ID-indexed accumulator or delay delivery to force event ordering.

**Finite record contract.** Existing diagnostic and lifecycle records retain their established contract. Add only the following new request-observability fields and event values; all other keys are dropped. Existing base keys are retained rather than renamed. Each new field is typed and value-validated, including nested shape/error objects; no arbitrary map is accepted.

| Field group | Allowed values / bounds |
| --- | --- |
| Base | `time`: UTC RFC3339Nano; `level`: debug/info/warn/error; `service`: fixed mcp-bridge; `environment`, `version`: fixed unspecified unless an already established trusted build/deployment value exists; `message`: fixed event-specific text, never interpolated input. The current `time` key is the UTC timestamp; do not introduce a competing clock field. |
| New events | `http_complete`, `mcp_complete`, `backend_complete`; preserve every currently supported event. |
| Internal identity | `request_id`, `operation_id`, `backend_call_id`: server-generated 32-character lowercase hexadecimal values; omit child IDs when their boundary never existed. `correlation_state`: available/unavailable. `generation`: existing numeric catalog generation where known. |
| HTTP | `http_method`: GET/POST/DELETE/HEAD/OPTIONS/PUT/PATCH/OTHER; `route`: mcp/not_found; `http_status`: observed integer 100–599 or null if no response was observed; `http_outcome`: success/failure/incomplete/unknown; `http_bytes_bucket`: finite byte bucket below. Never log a path, query or arbitrary verb. |
| MCP | `mcp_method`: finite manifest below; `message_kind`: request/notification/unknown; `rpc_outcome`: success/error/notification/not_observed/unknown; `rpc_error_class`: none/parse_error/invalid_request/method_not_found/invalid_params/internal_error/server_error/other/not_observed. No raw client ID or error data. |
| Tool/backend | `tool`: approved identity or unknown; `server`: approved configured identity or existing _bridge sentinel; `tool_outcome`: success/error/not_run/not_observed/unknown; `backend_outcome`: success/failure/not_run/unknown. No raw upstream tool name inferred from input and no endpoint. |
| Failure | `stage`, `reason`: finite manifests below; `error`: absent or fixed object containing only `class` (same finite reason) and `rpc_error_class` when applicable. No message, stack, formatted Go error or arbitrary dependency code in this object. |
| Timing | Existing `duration_ms`: nonnegative elapsed milliseconds for the emitting boundary only. `timing_scope`: http/operation/backend. A zero-duration fast operation is valid. No client timestamps. |
| Shape | `upstream_shape`, `final_shape`: exact bounded objects below; absent only when no corresponding result was observed. Never attach a result body. |

The legacy `operation`, `outcome` and `reason` remain finite. Extend logger vocabularies as necessary for these records, but do not reuse the new MCP classifier to alter the existing request metrics vocabulary. Existing metrics may still aggregate a method as request when the new log names it precisely.

**Method manifest.** Map exact decoded method names to these log values: initialize → initialize; ping → ping; tools/list → tools_list; tools/call → tools_call; prompts/list → prompts_list; prompts/get → prompts_get; resources/list → resources_list; resources/templates/list → resources_templates_list; resources/read → resources_read; resources/subscribe → resources_subscribe; resources/unsubscribe → resources_unsubscribe; completion/complete → completion_complete; logging/setLevel → logging_set_level; notifications/initialized → notification_initialized; notifications/cancelled → notification_cancelled; notifications/progress → notification_progress; notifications/roots/list_changed → notification_roots_changed. Other decoded strings → other. Missing/non-string method on a decoded invalid message → invalid. No decoded message → not_observed. A known method classification does not claim that the bridge supports the capability; unsupported-method responses remain unchanged. Additions to this manifest require tests, not dynamic labels.

**Stage manifest.** `none`, `http_route`, `host_admission`, `origin_admission`, `client_auth`, `session_admission`, `request_limits`, `mcp_decode`, `mcp_dispatch`, `tool_admission`, `backend_dispatch`, `backend_response`, `response_delivery`, `unknown`. Report the stage where the fact was established, not an imagined remote failure location.

**Reason manifest.** `none`, `route_not_found`, `host_rejected`, `origin_rejected`, `client_auth_failed`, `session_auth_failed`, `session_capacity`, `request_too_large`, `malformed_request`, `invalid_request`, `method_not_found`, `invalid_arguments`, `unknown_tool`, `catalog_changed`, `unsupported_schema`, `backend_unavailable`, `backend_auth_failed`, `backend_busy`, `deadline_exceeded`, `request_cancelled`, `client_disconnected`, `upstream_protocol_error`, `unsupported_capability`, `tool_reported_error`, `internal_error`, `correlation_unavailable`, `unknown`. Existing logger reasons remain supported for existing records. Map only branch-local decisions, typed errors, explicit protocol outcomes and cancellation/deadline evidence. Never search error text, inspect credentials or infer authentication from an HTTP status unrelated to its owning boundary. Unknown dependency codes map to unknown.

Host admission remains first, then Origin admission, then the existing remaining checks. If both fail, record only the first decisive rejection, without evaluating a different policy or exposing either value. Split observation at the existing predicates; do not change their semantics. Credential failure and invalid session binding retain their existing HTTP challenge/status behavior. A request rejected before MCP processing has no tool/backend identity, no tool success and no backend attempt.

**Separate outcome semantics.** HTTP success means an observed status below 400 and completed delivery, not successful execution. A committed HTTP 200 followed by a failed write/disconnect retains status 200 and records incomplete transport. An implicit successful response is 200, including first flush/write; absent evidence is null, never invented zero. JSON-RPC error and tool `isError` are independent: a tool error returned as a successful JSON-RPC result has rpc_outcome success and tool_outcome error. A JSON-RPC error with no tool result has tool_outcome not_observed or not_run when admission proves execution did not begin. A notification has rpc_outcome notification, not a fabricated response. A backend exchange can succeed while its tool result reports an error. Do not infer a JSON-RPC error solely from HTTP 400/500 or a tool error from HTTP 200.

Explicit deadline expiration maps to deadline_exceeded; explicit MCP cancellation maps to request_cancelled only where exposed. A typed canceled context without attributable signal is request_cancelled, never proof of client_disconnected; that reason requires actual transport close/write failure or equivalent positive evidence. Unexplained failures remain unknown. Preserve SDK cancellation semantics: current nil options leave Stateless, JSONResponse and PropagateRequestCancellation false; stateful sessions use the existing random session-ID default and later POSTs reuse their connected transport. The SDK detaches the initial connection context and queues accepted operations independently of HTTP completion. Do not enable request-cancellation propagation, replace SDK operation cancellation with the HTTP context, or change session/stream defaults to manufacture tests. The receiving result is not delivery confirmation. Pre-hook rejection permits only exposed facts, not confident inference from HTTP status or an absent callback.

**Closed backend evidence contract.** Add an internal typed value contract beside existing observation types, separate from public CallError/DispatchError codes: an owning phase enum `admission/session_connect/tool_call`; a closed fact set `busy/unavailable/deadline/cancelled/protocol_error/malformed_result/needs_input/transport_failure/unknown`; optional integer HTTP status 100–599; and optional finite rpc_error_class mapped from a typed numeric JSON-RPC code, never its message/data. The dispatch scope supplies immutable backend/operation identity and execution-stage ownership, not caller values. Capture facts BEFORE existing lossy conversions at ServerClient.CallTool's actual typed admission/cancellation/protocol/nil-result/NeedsInput branches, Dedicated's session-acquisition boundary and credentialsTransport.RoundTrip's existing response/error return. For the latter inspect only a non-nil actual response's numeric status and positive typed transport evidence, with the current phase/scope supplied by the caller; return the identical response/error, make exactly the existing RoundTrip call, and never read its body, headers, URL or error text for classification. Attributable HTTP 401/403 establishes upstream authentication/authorization rejection; HTTP 200 is an HTTP fact, not RPC success. Background/discovery/session work lacking a live admitted dispatch scope cannot invent a backend attempt. Do not use final public codes as evidence: internal_error loses cancellation, backend_unavailable loses cause, and the existing unsupported-capability message-suffix branch is text-derived. That branch's unchanged public code is not diagnostic proof of unsupported capability; typed protocol error remains protocol_error, while the explicit NeedsInput predicate is valid capability evidence. Unknown stays unknown even where unchanged public behavior says backend_unavailable.

Use one fixed-size, dispatch-local synchronized evidence owner in typed context, not a global/session registry or per-exchange log producer. Callers publish copied immutable fact snapshots, merging a closed bitset and bounded per-phase numeric-status slots under a short lock; no payload/error object, variable-length history or per-fact allocation. A slot with different observed statuses records a conflict rather than arbitrarily selecting one, retaining bounded seen-200/401/403 facts for truthful classification. After the actual dispatch returns, its sole terminal owner snapshots/closes the evidence owner; late/background callbacks cannot change or emit its terminal record. A terminal successful tool exchange remains backend success even if its tool result has IsError; intermediate HTTP facts alone cannot reverse it. For failure choose typed deadline, typed cancellation, observed 401/403 auth rejection, branch-local busy/unavailable, typed protocol/malformed-result, explicit NeedsInput capability, positive typed transport failure, then unknown, in that order; generic/text-derived public codes never establish any choice. Multiple/conflicting facts never imply a more specific unobserved cause. Keep numeric status/internal facts private unless projected into an already allowlisted finite log field. Public errors, ExecutionState, breaker RecordFailure/RecordSuccess decisions, admission, retryability, retries, networking and return values remain exactly as before.

**Approved identity policy.** Resolve tool from the registered public tool table and exact successfully admitted catalog binding, and configured server from that same binding; never trust syntax or the submitted string. At admission capture one immutable generation-scoped identity snapshot containing the admitted tool/server, numeric generation and matching immutable approval set. Retain that snapshot through dispatch and terminal emission; never revalidate an old call against the newly published set or mutate a shared/global logger's current approvals. Built-in identities use approved constants; pre-admission unknown/stale/malformed identities stay unknown. Validate type/membership/bounds against the captured set, retaining existing server-name safety constraints and tool maximum 256 ASCII letters/digits/underscore/hyphen/dot/colon; invalid approved names become unknown without changing admission. The operation scope owns a write-once immutable admitted identity/upstream-shape summary published by the actual tool handler for the middleware's terminal snapshot; do not infer admission from input or modify the public result. Synchronize publication without mutating the context's identity values or sharing writable maps between requests/generations. Lease/draining/reload behavior remains unchanged.

Configured/catalog identity values are operator-approved metadata, not universally secret-free strings. This design intentionally preserves configured backend IDs and useful tool names; it does not add aliases, HMACs or key management. Operators must not configure credentials/documents as approved identifiers. Secret-safety claims cover untrusted submissions and arbitrary metadata, not a promise to conceal an operator-approved name intentionally configured to be a secret. External metadata is not approved merely because it appeared in a backend response: require existing catalog admission and the selected binding. Record this trust boundary in the operator guidance and privacy review.

**Internal correlation without public changes.** Generate an internal request ID at every HTTP entry independently of public X-Request-ID; each decoded operation and actual dispatch gets its own child ID. Current POST attribution must come from that request, not the reused session's initial context. Preserve the original request/Header and every existing public ID/header policy; pass only to the existing SDK handler a shallow request copy with a cloned Header. Reserve `X-Mcp-Bridge-Internal-Request-Id`: remove every case-insensitive submitted spelling/value in the SDK-only clone and set exactly one fresh server-generated value, or no value on entropy failure. No mutation of the original or cloned map after delegation: queued notifications can outlive HTTP return. In receiving middleware recover only that overwritten current RequestExtra.Header value; a missing/invalid carrier means unavailable parentage, never fallback to stale connection context, session/client/JSON-RPC/envelope IDs. Install a fresh typed immutable operation scope in the SDK-provided ctx and call next with it, preserving SDK deadline/cancellation semantics; actual dispatch derives its own immutable child scope. All production HTTP paths to the SDK pass this owner; lower-level calls without a carrier explicitly lack request correlation. Never copy arbitrary inbound/RequestExtra headers into outbound clients, responses, envelopes or logging fields. The generated carrier may appear only as its designated internal request_id, never as dumped header metadata; neither its private header name nor submitted values are logged. No new generated header appears on any public/upstream wire and configured upstream headers remain unchanged. No session-ID/global registry. Multiple operations from one POST share only that POST's parent; later POSTs on the same stateful session get fresh parents, and frames/queued operations retain their established scope.

Use the existing server-side random-ID mechanism with empty input, never its caller-ID acceptance path, once per owned boundary. On entropy failure delete all private-carrier spellings from the SDK-only clone, omit only unavailable internal IDs and mark correlation_state unavailable with fixed correlation_unavailable classification, without suppressing the actual boundary terminal event or changing its observed outcomes/public response. An independently available child ID does not repair a missing parent or make the chain available. Missing/forged/malformed carriers on lower-level paths cannot fall back to connection/client/session IDs. Preserve legacy correlation behavior for existing non-upgraded diagnostics. Test entropy failure through a bounded package-local test seam around random generation, not global replacement of crypto/rand.Reader or a new public constructor/configuration interface.

**Independent timers and bounded shape contract.** Start/stop monotonic timers at each owned boundary: HTTP entry/handler exit, decoded operation entry/terminal result, and admitted dispatch entry/return. Stop each operation/backend timer and snapshot its terminal facts before writing its terminal record; writer backpressure is not operation/backend execution time. Emit the operation terminal synchronously after the next handler returns and before returning its unchanged result/error to the SDK, not at HTTP exit. A blocked existing stdout dependency can therefore delay SDK response delivery and extend the associated HTTP lifetime without extending the already-stopped operation/backend timers. This is stdout backpressure, not a claim that the SDK naturally leaves a completed POST's SSE response open. The harness may simulate that dependency with its injected writer, but production gains no delay, hook, endpoint or interface. This upgrade adds no retry; one backend record means one existing dispatch. Existing lifecycle events remain the lifecycle source; do not duplicate startup/reload/readiness messages.

For each observed upstream and final tool result, emit only: `content_count` (0–1024, saturating); `count_capped` (boolean); `blocks_inspected` (0–64); `shape_complete` (boolean); `content_types` (deduplicated subset of text/image/audio/resource/resource_link/other, at most six entries); `text_presence` (present/absent/unknown); `structured_presence` (present/absent/unknown); `encoded_bytes_bucket` (empty/le_1k/le_16k/le_256k/le_1m/gt_1m/unavailable). The buckets denote bytes, with thresholds 0, 1024, 16384, 262144 and 1048576. Count a text block as text presence even when its text is empty; do not scan its body. Presence of structured content means its member is present/non-nil, not that it is nonempty or renderable. Inspect at most the first 64 already-decoded content blocks. If more exist, types describe the inspected prefix, shape_complete is false, and unseen text is unknown rather than absent. Nil/unavailable results are not empty results.

Observe upstream_shape at the existing raw-result/decodeUpstreamResult path, using only already-available attributable raw byte length. Derive final_shape from the actual non-nil `*mcp.CallToolResult` returned by `next` in receiving middleware: inspect its Content, StructuredContent and IsError after SDK tool dispatch/normalization, not the earlier wrapper construction or a presumed success result. Nil/other results are unavailable, not empty. A successful empty upstream can have no upstream structured member while the actual final provenance wrapper is present; error-result variants describe their actual terminal shape. The hook is before later per-request protocol metadata decoration and wire encoding, not a serialization/delivery callback. Final encoded bytes remain unavailable unless an existing attributable encoded length is already exposed; never marshal again, parse structured bodies, scan text, copy payloads, buffer streams or attribute whole-stream length to a tool. HTTP buckets count actual writes, saturating above 1 MiB. Shape/size is compatibility evidence, not proof of rendering failure.

**Observability and operations contract.** New records are single-line JSON to the existing injected stdout writer; current process/container/service stdout collection remains the shipping boundary. No collector, Loki tenant, deployment environment, retention setting or dashboard was established by the evidence, so this plan does not invent one. New records supply UTC time, finite severity/event/message, service, environment/version, applicable internal IDs, scoped duration and payload-free structured error detail. Unknown optional deployment metadata uses unspecified; never ingest arbitrary environment values for log enrichment.

Successful HTTP/operation/backend completions are info. Admission rejection, protocol rejection, tool-reported error, timeout and observed cancellation/disconnection are warn. Unclassified internal/backend failures are error. Do not emit both a separate failure and another identical terminal event at one boundary. Three correlated boundary records are deliberate, not three failed attempts. Existing logging-level behavior for existing events is unchanged.

If an already deployed collector forwards stdout to Loki, only service/environment/level/event may be labels; request/operation/backend IDs, tool/server, errors and shape values stay JSON fields. This change inherits existing deployment retention and access controls and changes neither; actual retention duration and durable delivery are unverified deployment concerns, not guaranteed features. Local capture tests prove bytes reach the configured writer, not Loki. Existing encoder/write failure behavior is retained: no request failure, recursive logger use, retry queue, disk spool or new network delivery. A broken stdout collector can lose records; external collector ingestion failures must remain visible through its existing supervision. This explicit delivery/retention exception avoids silently promising durability or unauthorized infrastructure work.

Prometheus scrape is GET /metrics on operations.listen through the existing shared operations-listener limiter/policy, not the public /mcp listener; do not introduce a new method/auth rule. The private registry exposes bridge_requests_total (counter, requests; server/operation/outcome), bridge_catalog_tools (gauge, count; server), bridge_catalog_prompts (gauge, count; no labels), bridge_catalog_age_seconds (gauge, seconds; server), bridge_catalog_refresh_total (counter, attempts; server/outcome/reason), bridge_config_reload_total (counter, attempts; outcome/reason), bridge_readiness (gauge, 0 unavailable/1 degraded/2 ready; server). No latency histograms/buckets are registered. Existing inbound metric operations request/prompts_list/prompts_get and outcomes success/failure with _bridge attribution remain unchanged; no new log method/reason vocabulary enters labels/counters. T7 pins manifest/types/labels and controlled deltas through the real operations listener, not volatile exposition bytes (AC17/20). New duration/failure facets remain logs; no new throughput/error/saturation/queue/dependency collector is authorized or falsely claimed. This justified metrics exception preserves unchanged monitoring.

No new alerts or dashboards are deployed. Existing ones must remain compatible. Operator guidance will describe correlation, three outcome dimensions, timings, shape completeness and bounded filters for client_auth_failed, backend_auth_failed, deadline_exceeded and upstream_protocol_error. Saved queries/dashboards are not assumed to exist. Tests prove JSON validity, writer delivery, failure visibility and unchanged scrape output; a live Loki delivery, retention or alert evaluation test is not claimed. T2/T3/T6/T7/T8 implement and validate this scaled observability contract; AC14–AC18 make its measurable parts explicit.

## Testing Decisions

**Evidence and truth status.** The supplied evidence reports PASS for `go test ./cmd/mcp-bridge -run '^TestServeCompositionRootServesCatalogAndSurvivesReload$' -count=1` (0.118s), proving only the existing harness baseline. Proposed logging has not been implemented or tested. No full-suite, coverage, race, lint or smoke result is claimed. Planning inspection used bounded local retrieval because source-search MCP devices are unavailable; gopls confirmed the actual tool-handler signature. Graphify was skipped because the tree is dirty and no graph path is verified.

The supplied stream probe demonstrates only SDK next-handler-return and same-response delivery ordering behind its own middleware barrier; it is not root logging evidence or an AC10 PASS. Existing root stdout injection and synchronous logger writing are source-established. The actual-root stdout-backpressure fixture and its independent same-POST wire/mutation oracles below are future authorized RED/GREEN obligations, not prerequisites requiring a nonexistent operation event before its implementation.

**Primary seam and assertion strategy.** Extend the existing real runContext/listeners/MCP client harness with local deterministic fake MCP/embedding upstreams and its synchronized JSON log capture. Exercise the public HTTP/MCP surface and captured log writer, not private logger calls for integration behavior. Retain focused observe-package allowlist/diagnostic tests for logger safety invariants; do not duplicate the primary behavioral matrix across several lower-level suites. Parameterize fixtures within this seam and use subtests with independent captured-log windows. Existing regression suites remain the full compatibility net.

Assert decoded log objects, boundary counts, finite values, correlation joins and complete absence of injected sentinel bytes in all captured JSON bytes, not snapshots of timestamps/random IDs or loose substring-only success checks. Use typed local upstream failures/protocol responses and explicit synchronization barriers. Do not use production retry policies, remote services, new clocks/endpoints exposed only to tests, sleeps as ordering proof or log-text heuristics to make classification tests pass.

**AC10 stdout-backpressure fixture and independent wire oracle.** After authorization, extend the existing real composition-root harness, not the SDK-only probe. Preinitialize a real stateful session, then send one identifiable successful tools/call POST on a dedicated raw loopback HTTP connection with existing SSE negotiation and unchanged production options. Start its continuous raw response reader before releasing the local upstream call. The fake upstream has distinct entered, release and return-edge notifications; the return-edge notification is owned by that backend fixture, not synthesized from operation/HTTP logs. Join the completed backend terminal and targeted operation record through their internal IDs and the actual call. Do not replace this POST with an unrelated GET, a different request or an upstream stream.

Inject a harness-only selective stdout writer through the existing io.Writer parameter. It copies the complete targeted tools_call mcp_complete JSON record into synchronized capture, publishes one record-arrival notification, releases the capture-buffer lock, then waits for an idempotently releasable channel before returning the normal successful write result. Selection uses the decoded event/method and the isolated fixture's admitted call; other records are captured normally. It adds no production logger/event callback. Missing target records terminate through bounded failure guards; the writer must not retain the encoder's reusable byte slice. The production logger may still hold its own existing serialization lock, so absence of http_complete or any other later log while this writer is blocked is not independent ownership evidence.

With the independent backend return edge and targeted record arrival established and stdout release not yet signaled, the raw reader must establish that this same POST has not delivered its matching JSON-RPC result. Correct middleware is still inside its terminal write before returning to SDK delivery, so positive pre-release result delivery is neither required nor allowed.

Require exactly one backend and operation terminal for the call, and no pre-release HTTP terminal for that parent. Wire result delivery is the independent oracle; log ordering alone is insufficient.

The backend duration must fit within operation duration where nested, allowing one millisecond of independent truncation. The HTTP duration must be strictly longer than operation duration and must include the measured stdout hold: duration_http_ms >= duration_operation_ms + hold_ms - 2, where hold_ms is the monotonic gate-notification-to-release interval in milliseconds. Use the bounded negative-read phase to obtain a resolvable hold, not an arbitrary execution-speed threshold or exact timestamp equality; a hold too short to distinguish millisecond quantization is inconclusive, not acceptance. Operation duration is the terminal fact already captured before the writer wait and must not be recomputed after release. Review the stop/snapshot-before-write boundary as well as these observable inequalities; do not subtract backpressure from the HTTP timer.
