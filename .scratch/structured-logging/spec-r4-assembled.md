## 2. REQUIREMENTS

Stable requirement IDs; owner decision (D#) from `.scratch/structured-logging/decisions.md` in parentheses.

<!-- specdd:requirements:start -->
- R1 (D1): Every application log record and every CLI error is one newline-delimited JSON envelope. No mixed text/JSON output on any process path. Application log records include the service/tool-surface records (`internal/service`), the upstream ephemeral handshake record (`internal/upstream/dedicated.go`), and the HTTP diagnostic lane.
- R2 (D2): Application-owned envelope fields exactly: `schema_version`, `level`, `service` (hard-coded `mcp-bridge`), `event`, `message`, `operation`, `outcome`, nested `error`, the event-specific objects `config` and `resource`, the typed event-specific entry fields `request_id`, `generation`, `duration_ms`, `server`, and the closed event-specific field vocabulary enumerated in §4 AD8 (D2's "event-specific" authority). No key outside that enumeration may be emitted.
- R3 (D3, D4): The application never emits timestamps, `subsystem`, container identity, host, `environment`, or `version`. No application timestamp at all.
- R4 (D5): debug/info → stdout; warn/error → stderr. One JSON object per line, one write, no retry, no partial output, no plaintext fallback.
- R5 (D6): Nested `error` = `code`, `kind`, `retryable`, `remediation`. `message` is human-only; queries use `event`, `error.code`, `error.kind`. The HTTP lane's error slot carries the same nested shape (see §4 AD2).
- R6 (D7): Configuration diagnostics carry `config.path`, `config.property_path`, one-based `config.line`/`config.column`, safe validated identifiers (`config.server`, `config.pin_server`, `config.pin_tool`, `config.ref_kind`, `config.ref_name`), and `config.related` (property path, line, column, plus optional ref/server identity) for conflicts. Where no source position exists (§4 AD10 exception list), line/column are omitted; the exception itself is part of this requirement.
- R7 (D8): Pin ceiling reports `property_path: "pins[64]"`, that element's one-based line/column, safe `pin_server`/`pin_tool` of the first excess entry — included only when that entry's identity passes the same per-pin validation as entries 0..63, otherwise omitted — plus `actual_count`, `max_count`, `first_excess_index`. Only the first excess entry, never every excess entry. The ceiling is raised at its document-order position: after entries 0..63 validate, so an earlier malformed pin wins under R9.
- R8 (D9): No record serializes secret values, URLs, query strings, headers, payloads, raw YAML fragments, or arbitrary Go error text. Only validated identifiers, finite classes, and static package-owned reasons. This applies with full force to the unvalidated excess pin entry's identity (§4 AD9).
- R9 (D10): Fail-fast: the first error in deterministic document order, exactly one detailed event, no detail-plus-summary pair.
- R10 (D11): Startup rejection = level `error`, exit 1. Reload rejection = level `warn`, candidate discarded, active configuration keeps serving.
- R11 (D12): Non-configuration failures (listener bind, state directory, embedding provider, tool surface, CLI usage) use the same envelope with stable codes/kinds/retryability/static remediation and safe resource identifiers only.
- R12 (D13): `--help` stays human-readable and emits no JSON record.
- R13 (D14): Validation success emits `config_validation_succeeded` with `outcome: "success"`, no `error` object, no configuration contents, exit 0.
- R14 (D15): Exit code for configuration failure stays 1.
- R15 (D16): No panic recovery; Go's crash report is untouched. Non-goal.
- R16 (D17): No raw-cause diagnostic mode. Non-goal.
- R17 (D18): No legacy aliases: `time`, `environment`, `version`, flat `reason`, flat `error.class` are removed (the HTTP lane's `error` slot becomes the nested R5 object; `service` already exists in the lane and stays); repository consumers (tests, queries, docs — including `README.md`) migrate in the same change.
- R18 (D19): `schema_version` starts at 1; removed/renamed/retyped/semantically changed fields increment it; optional event-specific additions do not. Evolution rule documented.
- R19 (D20): The Docker Compose `mcp-bridge-network |` prefix is orchestrator output; the application does not work around it. Non-goal.
