- R1 (D1): Every application log record and every CLI error is one newline-delimited JSON envelope. No mixed text/JSON output on any process path. Application log records include the service/tool-surface records (`internal/service`), the upstream ephemeral handshake record (`internal/upstream/dedicated.go`), the HTTP diagnostic lane, and the loop-lifecycle warnings (`startup_snapshot_rejected`, `prompt_publication_failed`, `reload_rejected`, r7 AD13).
- R2 (D2): Application-owned envelope fields exactly: `schema_version`, `level`, `service` (hard-coded `mcp-bridge`), `event`, `message`, `operation`, `outcome`, nested `error`, the event-specific objects `config` and `resource`, the typed event-specific entry fields `request_id`, `generation`, `duration_ms`, `server`, and the closed event-specific field vocabulary enumerated in §4 AD8 — which explicitly covers BOTH the shared record lane and the COMPLETE HTTP diagnostic lane key set (the 60-slot map in §4 AD2). No key outside that enumeration may be emitted.
- R3 (D3, D4): The application never emits timestamps, `subsystem`, container identity, host, `environment`, or `version`. No application timestamp at all. This applies with full force to the HTTP lane's `diag_environment` and `source_revision` slots (removed, §4 AD12).
- R4 (D5): debug/info → stdout; warn/error → stderr. One JSON object per line, one write, no retry, no partial output, no plaintext fallback.

Where no source position exists (§4 AD10 exception list and r7 per-stage node-source table), line/column are omitted; the exception itself is part of this requirement.

Only the first excess entry, never every excess entry. The ceiling is raised at its document-order position: after entries 0..63 validate, so an earlier malformed pin wins under R9.
- R8 (D9): No record serializes secret values, URLs, query strings, headers, payloads, raw YAML fragments, or arbitrary Go error text. Only validated identifiers, finite classes, and static package-owned reasons.
