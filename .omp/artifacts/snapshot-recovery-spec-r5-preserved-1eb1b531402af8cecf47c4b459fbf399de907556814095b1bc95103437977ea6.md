2. REQUIREMENTS
- R1 Single recovery locus: a new Store recovery method executes once per process, after storage.Open acquires the writer lock and before startup admission (Loop.Start). It never runs in Reload, mid-run saves, or ensureReplaceable; ensureReplaceable is unchanged.
- R2 Quarantinable class: any Load/LoadPrompts ErrCorrupt rejection (decode/envelope, trailing data, checksum mismatch, unsupported schema, failed Validate) and any read failure of a REGULAR file at the snapshot path are quarantinable: one atomic same-directory rename of the original file to a timestamped quarantine name before any fresh snapshot is published. Bytes are preserved exactly; no delete, truncate, or overwrite-first.
- R3 Fatal class: a non-regular file at a snapshot path (directory, device, socket — a directory cannot follow the rename rule), quarantine rename failure, and post-rename directory-sync failure are fatal: startup exits failure with code state_directory, kind resource, remediation and resource.path per the existing stateDirectoryFailure record (cmd/mcp-bridge/startup_failure.go:26-33). The typed record is the only output for the condition: arbitrary Go error text is never a log field or free-text line (docs/logging-contract.md); the class, kind and configured-path attribution carry the diagnosis. When no rename occurred, the file is untouched; a failed rename leaves the original bytes at the original path; a failed post-rename sync leaves the bytes at the quarantine path with the original absent.
- R4 Typed warning: for each quarantined file exactly one structured record, event startup_snapshot_rejected, operation startup, level warn, outcome degraded, error.code snapshot_unavailable (closed AD13 mapping, docs/logging-contract.md AD13), error.kind resource, error.retryable true, existing static remediation and message, resource.path = configured state directory (the resource object carries only configured path/listener/address attribution, docs/logging-contract.md:252, :338), plus two optional event-specific fields under the documented optional-addition rule (docs/logging-contract.md:499-512, :585-586; schema_version stays 1): failure_reason with the finite value corrupt_json | checksum_mismatch | unsupported_schema | validation_failure | read_error, and quarantine_path = the quarantined file's full path (validated: absolute path, .json suffix, base name in the snapshot.corrupt-*.json | prompts.corrupt-*.json families). The observe envelope write path accepts exactly these two extensions (internal/observe/envelope.go: failure_reason whitelist extension, quarantine_path field case); no other envelope vocabulary widens. No startup_failed or internal_error record is emitted for a quarantinable condition.
- R5 Retention bound: at most 5 quarantine files per family (snapshot.corrupt-*.json, prompts.corrupt-*.json); after each successful rename, the oldest beyond the bound is pruned. Ordering parses each name's RFC3339Nano UTC timestamp strictly (time.Parse; names matching a family glob with an unparsable or invalid timestamp, and any non-conforming directory entry, are never pruned and never counted toward the bound — foreign/operator files are never deleted). Prune failure is non-fatal and reported exactly once per affected family via a typed lifecycle record event snapshot_retention_failed, operation startup, level warn, outcome failure, error.code snapshot_unavailable, kind resource, retryable true (new AD13-table row added under the optional-addition rule; schema_version stays 1), carrying resource.path = configured state directory and optional quarantine_path naming the file that could not be removed. internal_warning is NOT used: it is pinned to operation reload and defined as a defect indicator (docs/logging-contract.md:481-488).
- R6 No-op on valid or absent snapshots: when Load/LoadPrompts succeeds or reports ErrNoSnapshot, recovery mutates nothing — no rename, no warning, no retention pass; a successfully loaded snapshot keeps its trusted state and the existing no-overwrite protection is untouched.
- R7 Prompt-snapshot coverage: prompts.json receives identical quarantine behavior with prompts.corrupt-*.json names and the same retention bound.
- R8 Operator opt-out: environment variable MCP_SNAPSHOT_QUARANTINE=off (case-insensitive comparison) disables recovery (fail-closed): no quarantine rename and no new recovery record (no startup_snapshot_rejected record carrying failure_reason/quarantine_path, no snapshot_retention_failed record). Today's wedge semantics otherwise hold: the Durable loader failure still emits the pre-existing structured startup_snapshot_rejected record (internal/service/loop.go:148-151 translated by cmd/mcp-bridge/wiring.go:485-492), the admission persist fails fatally, the startup_failed/internal_error record is emitted, and the process exits 1. Any other value, including unset, enables recovery. [OWNER-CONFIRMED 2026-11-21] default = enabled.
- R9 Machine-readable reasons: Load/LoadPrompts rejections gain errors.Is-compatible reason sentinels chained under ErrCorrupt, so every existing errors.Is(err, ErrCorrupt) caller and test is unaffected.

Non-goals: no new metric names or series and no reloadReasons/reloadOutcomes extension; no stale temp-file (.snapshot.json.N.tmp) cleanup; no general redesign of startupFailureForError beyond R3's fatal recovery path (opt-out mode intentionally keeps today's internal_error wedge); no recovery during Reload or mid-run saves; no operator tooling for quarantine files; no Windows rename-semantics work; no changelog file (none exists; docs/logging-contract.md is the operational doc updated); no Envelope struct field additions (the two new fields flow through the Entry.Fields validated path).

4. DESIGN
New file internal/storage/recovery.go. New sentinels in internal/storage/store.go, chained under ErrCorrupt so errors.Is(err, ErrCorrupt) is preserved for all callers: ErrSnapshotDecode = fmt.Errorf("%w: decode", ErrCorrupt), ErrSnapshotChecksum, ErrSnapshotSchema, ErrSnapshotValidate (same for prompt variants where applicable); trailing-data rejection re-wraps under ErrSnapshotDecode (reason corrupt_json); Load/LoadPrompts wrap their rejections with the matching sentinel instead of bare ErrCorrupt. New Store method:
  func (s *Store) RecoverRejected(now func() time.Time) (RecoveryResult, error)
type RecoveryResult struct { Recoveries []Recovery; RetentionFailure *RetentionFailure }; type Recovery struct { Original, QuarantinePath, Reason string }; type RetentionFailure struct { Family, QuarantinePath string }; Reason ∈ the five finite values; package constants QuarantineKeep = 5 and quarantine name prefixes. Contract per file (snapshot.json then prompts.json), executed while the Store's writer flock is held, once per process:
1) Lstat(path): ErrNotExist → skip (R6 absent subcase). Mode is not regular → fatal error wrapping new sentinel ErrSnapshotUnrecoverable with the path (R3).
2) Load()/LoadPrompts(): nil → skip (trusted set, R6 preserved); ErrNoSnapshot → skip; ErrCorrupt → reason from sentinel (decode incl. trailing data→corrupt_json, checksum→checksum_mismatch, unsupported schema→unsupported_schema, validate→validation_failure); any other error → read_error (regular file already proven by step 1). The file read inside Load goes through an unexported package variable (default os.ReadFile) so tests inject read failures deterministically.
3) Rename os.Rename(path, quarantine) via an unexported seam variable (default os.Rename); rename failure → fatal, original untouched. On rename success run syncDirectory via an unexported seam (default internal/storage/store.go:309 syncDirectory); sync failure → fatal with the bytes at the quarantine path and the original absent (R3); on success record the Recovery in the result.
4) Retention (only after a successful rename, for that family): list entries; keep ONLY names matching the strict grammar prefix + RFC3339Nano-UTC timestamp + .json, parsed with time.Parse; sort kept names by parsed timestamp newest-first; unlink beyond QuarantineKeep; unlink failure → populate RetentionFailure{Family, QuarantinePath} with the first failing path, continue with remaining unlinks, never fail startup. Non-conforming entries are never sorted, counted, or unlinked.
Fatal ordering (HIGH-4 closure): accumulation — every successful quarantine performed before a fatal is returned in RecoveryResult alongside the fatal error; a fatal stops all further mutation immediately. The caller emits one structured warning per accumulated Recovery even when the overall result is fatal.
Cmd wiring (cmd/mcp-bridge/serve.go serveWithToolPageSize, between the Open error check at :96-98 and NewLoop at :213): unless strings.EqualFold(os.Getenv("MCP_SNAPSHOT_QUARANTINE"), "off"), call store.RecoverRejected(time.Now). For each Recovery emit one structured warn record per R4 via the observe.Entry/Fields path (observe.Entry{Level warn, Event startup_snapshot_rejected, fixed message "startup snapshot unavailable", Operation startup, Outcome degraded, Error = the fixed AD13 object, Fields{resource.path: store.Dir(), failure_reason: r.Reason, quarantine_path: r.QuarantinePath}}) written to the stderr lane (Logger.write selects stderr for warn, log.go:117-125; equivalent direct envelope build acceptable). If RetentionFailure is non-nil, emit exactly one snapshot_retention_failed record (warn/failure, same AD13-code class per R5, Fields{resource.path: store.Dir(), quarantine_path}). Emission happens for accumulated recoveries BEFORE the fatal return. On fatal error return stateDirectoryFailure(store.Dir()) so writeStartupFailure/startupFailureForError emit the typed startup_failed/state_directory record (cmd/mcp-bridge/startup_failure.go:118-133, serve.go:340); no raw error text is logged anywhere.
envelope.go additions (T2, enumerated exhaustively): (a) validFailureReason accepts additionally corrupt_json, checksum_mismatch, unsupported_schema, validation_failure, read_error; (b) addEnvelopeFields gains one case "quarantine_path" validating a non-empty absolute path with a .json suffix whose base name starts with snapshot.corrupt- or prompts.corrupt-; (c) nothing else in the file changes. docs/logging-contract.md edits (T2, enumerated exhaustively): one optional-addition-table row for startup_snapshot_rejected (failure_reason, quarantine_path), one new AD13-table row for snapshot_retention_failed (warn/startup/failure/snapshot_unavailable/resource/true/static remediation "inspect the state directory; an old quarantine file could not be removed"/fixed message), and one field-union sentence documenting quarantine_path; schema_version stays 1; no field is removed, renamed, or retyped.
Compatibility: W09E walk — Lifecycle: sole writer is the flock-holding process; recovery is a one-shot pre-admission transition rejected-file→quarantine; restart after quarantine loads a valid or absent file (idempotent). Shared state: no read-modify-commit across processes; rename is atomic within the locked directory; competing-operation schedule (quarantine then admission persist then second-restart Load) traced in §5 schedules. Contract: every R maps to ≥1 AC (R1→AC2-1, R2→AC2-1/AC1-4, R3→AC2-4/AC2-5/AC2-7/AC2-8, R4→AC2-2/AC2-7, R5→AC1-3/AC1-5/AC2-3, R6→AC1-1, R7→AC1-4, R8→AC2-6, R9→AC1-2); oracles distinct. Authority: no owner stop touched; R8 default is OWNER-CONFIRMED (§2, §3 Q4). Ticket mapping: the ticket's required-behavior bullets map to R1-R8 with the two documented vocabulary reconciliations (retained warning under R8; classification-level cause preservation under R3) — the former "verbatim"/"1:1" claims are withdrawn.
