**F1 [HIGH] — R5 / §3 "Page" + AC3, AC6, AC11, AC37: the fill/packing rule is unpinned, so the literal oracles are not derivable.** R3 requires only a *non-empty* prefix within the ceiling; R5 requires only that each page is ≤ the ceiling and rune-aligned. Neither says the prefix/page is the *longest* that fits. AC3/AC11 nevertheless expect a literal "truncated to the ceiling" prefix, and AC6/AC37 expect literal per-page `remaining_pages`/`remaining_bytes`, which presuppose a specific packing. Worse, `total_pages` is itself page metadata: a page's size depends on the digit width of `total_pages`, which depends on the global page count, which depends on every page's size — circular, with no fixed-point rule in R5. Consequence: two conforming implementations produce different `total_pages`/previews and the literal ACs cannot be written deterministically. Fix: pin the rule (e.g. "Content is the longest rune-aligned prefix whose serialized envelope, sized with R11(g)'s pinned `total_pages`/`remaining_pages` widths, fits the ceiling").

**F2 [HIGH] — R6 (first paragraph) + AC7: per-namespace infeasibility is unreachable and carries the wrong terminal.** R11(c) gives `max_bytes_per_namespace ≥ max_retained_result_bytes`, namespace accounting counts entry payloads only, and FIFO eviction can remove every other entry, so an entry that passes R10's per-entry cap always fits. Fix: delete the per-namespace refusal (per-entry cap + FIFO covers it) or introduce a distinct namespace terminal with a load relation making it reachable; never reuse the aggregate code.

**F3 [HIGH] — R6 "Consequence" vs R16/AC18/AC39: `invalid_handle` vs eviction.** R6 states "`invalid_handle` no longer encodes an eviction"; R16 states a cap-evicted marker's handle resolves to byte-identical `invalid_handle` immediately, and AC18/AC39 assert exactly that. **F4 [HIGH] — R4/§3/AC31: no observable predicate separates session-ful from session-less.** Inbound stamps an epoch only when a session id exists; the seam would decide publisher retention versus `result_epoch_unresolved` purely from epoch presence, which cannot distinguish "session-less" from "session-ful with no stamped epoch".
