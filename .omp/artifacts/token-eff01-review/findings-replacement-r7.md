**F1 [HIGH] — §7's finite labels contradict the existing closed vocabularies, and T2's write roots cannot reconcile them.**
Section: §7 Finite labels, §5 T2 write roots, R12/AC13.
`outcome` is validated by `validEnvelopeOutcome` (`internal/observe/envelope.go:201`) against `outcomeVocabulary` (`internal/observe/log.go:156`: `unknown, success, failure, error, denied, busy, timeout, fallback, degraded`). The spec lists 12 paging outcomes and gives T2 only `envelope.go`, `log_test.go`, `metrics*`, `docs/logging-contract.md` — not `log.go`. As written, a record carrying `paged`/`result_expired`/… fails `buildEnvelope`, and `Logger.Log` (`log.go:85-97`) then emits the fixed `logging_write_failed` fallback: every paging event becomes a false write-failure record, and AC13's `TestLogLabelEnumeration` cannot be satisfied truthfully. The same section's `operation` set `{search_tools, describe_tool, call_tool, retrieve_result}` also omits live operations (`refresh` `internal/service/refresh.go:235`, `startup` `internal/observe/edge_test.go:94`, `reload` `log_manifest_test.go:48`, `handshake` `internal/upstream/dedicated.go:345`); the only closed operation set, `operationVocabulary` (`internal/observe/httpdiagnostics.go:660`), lacks `search_tools` and `retrieve_result`. The spec never says whether these enums replace or extend the existing sets. Observable consequence: either existing records start being rejected/rewritten, or the new vocabularies are silently bypassed (`finiteOutcome` still uses `log.go`'s set), so R12's "unlisted value fails" has no single enforcement point. Fix: state that §7 extends the existing closed sets; add `internal/observe/log.go` (and `internal/observe/httpdiagnostics.go` if the shared-lane `operation` enum reuses that list) to T2's write roots; name the exact enum edits and the `docs/logging-contract.md` vocabulary rows.

**F2 [MEDIUM] — R8/R11(g)/§6 undercount `upstream_code` in the maximal-metadata feasibility worst case.**
Section: R8, R11(g), §6.
Two unstated factors: (a) §3 says an over-bound render "ends with the literal `[truncated]` marker" while R11(g) computes the worst case with `upstream_code` at exactly `max_upstream_code_bytes`; it is undefined whether the 11-byte marker sits inside the bound or is appended beyond it. (b) The bound applies to the raw string, but the size that matters is the marshaled envelope, and Go's JSON encoder expands `<`, `>`, `&` to six bytes each, so a bound-satisfying code of 512 such bytes serializes near 3 KB. Consequence: a config accepted by R11(g) can render a terminal or preview larger than `preview_ceiling_bytes`, breaching R10's bound and AC11/AC26, and a page envelope can breach the pinned delivery ceiling. Fix: define the bound on the serialized value (or state the escaping factor used in R11(g)/§6), state whether `[truncated]` is reserved inside the bound, and add an escape-expanding code fixture to AC9/AC11/AC26.

**F3 [MEDIUM] — R12/AC13's producer rule has no producer for `outcome: "delivered"`.**
Section: §7 Events + Finite labels, R12, AC13.
§7 enumerates `delivered` but the Events list names only `result_paged`, `result_page_served`, the rejections and the five terminal events; no event for a pass-through (≤ ceiling) delivery is named, and no AC exercises it. R12 requires every enumerated value to have at least one producing path, and AC13 (T3/T4) asserts that clause, so the document is internally inconsistent. Consequence: `TestLogLabelProducers` fails or the implementer invents an unspecified event/severity. Fix: either name the delivery event and its pinned level/fields, or remove `delivered` from the enumeration.

**F4 [LOW] — the entry-retention TTL is never pinned.**
Section: R6, R4, R16, AC5.
R6 says retention "expires by TTL", but two TTLs exist (`handle_ttl`, `tombstone_ttl`); AC5 exercises only the handle-expiry path and asserts `result_expired` "while entry or marker exists", which is ambiguous if the entry itself outlives the handle. Consequence: implementations may differ on when the entry is dropped, changing eviction/accounting ordering that AC7 measures. Fix: state that entry retention expires at `handle_ttl`, that the expiry installs the R16 marker, and that a handle whose entry is present but past `handle_ttl` also returns `result_expired`.
