A TRUE CYCLE is a symlink component whose EXPANSION KEY is revisited WHILE STILL ON THE ACTIVE STACK (an ancestor splice still in flight UNDER THE SAME RESOLVED CONTAINING-DIRECTORY CONTEXT) — it terminates the walk harmlessly as the cycle class (no final target, no fatal, visited entries still protected). A FINITE REPEATED TRAVERSAL is a revisit of a KEY whose expansion already POPPED — NOT a cycle: the component is spliced again as a fresh expansion (pushed and popped anew) and the walk continues, still bounded — **and a revisit of the same INODE under a DIFFERENT containing directory (a hard-linked symlink alias) is a DIFFERENT KEY, never a cycle: it splices as a fresh finite expansion exactly like a popped revisit (r23-C4; AC1-10(b-hardalias)/(b-hardalias2))**. A symlinked directory component is spliced like any symlink component — recorded, pushed, its target resolved, popped on completion; a `..` after it applies to the **resolved** parent (r20-C1 order preserved) — and because a directory splice pops as soon as its target text resolves, a directory symlink re-reached later is always a popped, finite revisit. BASES: a spliced component's target resolution starts at that component's own base — `filepath.Dir` of the component's own path for a relative target, the filesystem root for an absolute one (the per-hop base rule, restated per spliced component). BOUNDS (exact counting): (budget) at most **4096 spliced symlink components per configured-family-path walk** — every symlink component whose own target text the walk resolves, including symlinked components of the configured link's own target text; the configured entry's own `Readlink` is the walk's input hop and is **never** a spliced component; `.`/empty/`..` components and non-symlink components never count; a splice that would exceed 4096 terminates the walk harmlessly (the budget class). (depth) at most **4096 expansion keys on the active expansion stack simultaneously** — a splice that would push the 4097th terminates the walk harmlessly (the depth class, the same belt-and-suspenders family as the budget). Termination: every splice consumes budget, so the walk always terminates; the stack rule catches ancestor cycles immediately (a linear chain of 4097 distinct links requires 4097 splices and trips the budget **or the depth bound — both 4096 bounds trip on the SAME 4097th splice attempt, so either bound may be the one that reports (r23, CR22-LOW: no `trips first`/`whichever` claim)**).** **C1 counterexample (r20):** `<state>/sub/alias → ../deep` (a symlinked directory component) and `snapshot.json → sub/alias/../q5`: filesystem resolution reaches `<state>/q5` — `alias` resolves to `<state>/deep` before the `..` applies, then the parent hop lands on `<state>`, then `q5` — while the r19 lexical `Clean`+`Dir`-join produced `<state>/sub/q5`, an absent path: protection recorded nothing for `q5`, retention evicted it, and the moved link dangled (a residual C1/F2-family deletion, not a reopening of the F2 fixture — F2 fixed the hop **base**, C1 fixes the **intra-hop component order**). **C1 counterexample (r21, fixed r22):** five conforming snapshot quarantines `q1..q5` (`q5` oldest, backing store-rejected bytes), a real directory `deep`, `alias → deep`, and `snapshot.json → alias/../alias/../q5`: filesystem resolution reaches `<state>/q5`, but the r21 global visited-set rule terminated the walk at the SECOND `alias` identity — a finite repeated traversal misread as a cycle — protecting nothing; the family pass moved the configured link and retention deleted `q5`, destroying the backing evidence and dangling the moved link. **Approach.** One new exported storage API plus one serve-side startup hook; the failure vocabulary grows by optional event-specific additions only. No new packages, dependencies, or goroutines.

**Storage contract (`internal/storage/recovery.go`, new).**

- Sentinels/values: `ErrSnapshotUnrecoverable` (fatal class); `QuarantineKeep = 5`; `RecoveryFamily` values `"snapshot"`, `"prompts"`; `Reason` values per R6 (six, incl. `orphaned_link`).
- `Recovery` carries `Family`, `Reason` (R6 taxonomy), `OriginalPath`, `QuarantinePath` (both absolute). `RetentionFailure` carries `Family`, `QuarantinePath`. `RecoveryResult` carries `Recoveries []Recovery` and `RetentionFailures []RetentionFailure`.
- `func (s *Store) RecoverRejected() (*RecoveryResult, error)`: closed store → non-nil error; **populates the run-level protected-target set once, before the first family pass (C1/F1/CR-LOWs/F2 — the complete backing chains of both configured family paths, resolved component-wise (D11/r20-C1; expansion keys per r23-C4), with each configured path's pre-pass chain record, resolution identity, and link status recorded for the orphan and mutual-loop detection (C7/D12, r23-C5); mechanics in step (3))**; processes the snapshot family then the prompts family **and stops at the first fatal (D2): a fatal in the snapshot family leaves the prompts family unexamined, untouched, and unrecorded (AC2-7 fatal-first subcase)**; **then, on the fatal-free path only, runs the orphan reconciliation step once (C7/D12 + r23-C5 — mechanics in step (3), evaluating the ordinary run-orphaned detection and the mutual loop-partner detection), which appends its `Recovery` entries after both passes and runs the reconciled family's ordinary retention pass**; returns `(result, fatal)` where a fatal error wraps `ErrSnapshotUnrecoverable` + the real cause, and `result` still carries any completed `Recovery` entries (AC2-8a; also on a reconciliation-fatal, R4/D12).
- Per family: (1) `os.Stat` (behind a seam). `ErrNotExist` (also a broken/dangling symlink, which resolves through the link) ⇒ absent: zero recovery, no mutation. Stat success with any **other non-regular mode — FIFO, socket, device, or a symlink resolving to one ⇒ fatal** (R3): **the entry is never opened and never read** (a read open on a FIFO blocks indefinitely; a device can produce unbounded data) and never renamed; `ErrSnapshotUnrecoverable` wraps a typed cause naming the mode family. No open flags (`O_NONBLOCK`) are needed because no open of the family entry ever happens on this branch; symlinks are followed by `Stat` only (no `O_NOFOLLOW` open — the link-entry-moves rule of AC1-10 applies only to quarantinable branches). Any other stat error (e.g. `ELOOP`, permission) ⇒ `read_error` quarantine — the entry itself moves (R2, never read). (2) Stat success with mode `IsRegular` (a symlink to a regular target resolves through the link): read via a read seam; classify via the shared walk (D7). Valid ⇒ zero recovery, entry untouched (AC1-1c).
