## 2. REQUIREMENTS

Stable ids R1–R9. Non-goals follow.

- **R1 Recovery locus — one startup-phase mutator.** Recovery is exactly one new `Store` method, `RecoverRejected`, called **once per process** by `cmd/mcp-bridge/serve.go` immediately after `storage.Open` succeeds and before any admission/loop work. It is the only code path that creates or prunes quarantine files. `Load`, `Save`, `LoadPrompts`, `SavePrompts`, and `ensureReplaceable` keep today's observable behavior byte-for-byte and never quarantine.
- **R2 Quarantine-once byte preservation.** Per family, a store-rejected **regular** file — **a symlink entry resolving to one, or an entry whose `os.Stat` fails with a recoverable stat error other than `fs.ErrNotExist` (e.g. `ELOOP` from a symlink loop; the rename needs no successful read)** — is moved exactly once via `os.Rename` into the same state directory under a bounded conforming quarantine name; bytes are preserved (rename, never delete/truncate/overwrite-first); the configured path is absent afterwards; a file that loads is never moved; **the complete resolved backing chain of a symlinked entry — every hop from the moved link entry through intermediate symlink entries (pre-existing conforming quarantine symlinks included) to the final regular target — is never unlinked or deleted by this run's retention passes: a run-level protected-target set (R5/§4 step (3)), populated before the first family pass by walking each configured family path's complete backing chain (not one `Readlink` hop; every resolution failure mode terminating the walk harmlessly), so it covers every link entry this run moves and every chain element behind it, including the link of a family not yet examined when the other family runs first (F1/C1), is consulted by both family passes: a chain element (**relative resolution against `filepath.Dir` of the link just read` — each link's own containing directory (F2/D11) — included; matched by **entry identity** — `lstat` device+inode of the element's own path, `os.SameFile` semantics — with the final regular target's backing `Stat` identity (identical to its entry identity) recorded alongside it and **every visited element's cleaned absolute path recorded as a lexical fallback (F1)**; protection membership and retention candidacy compare the candidate's **entry** identity and cleaned path, never its `Stat` resolution (L1)**) is never an eviction candidate and never unlinked, even when it is a pre-existing conforming quarantine candidate of either family (C6/F1/C1 → R5/D10; AC1-3/AC1-10 same-family, cross-family, chain, subdirectory, alternating-hop, alias, ELOOP, mixed, vacuous, and configured-path subcases). The one documented touch outside the retention/unlink rule is the **cross-family configured-path move-through**: a chain whose final target is the other family's configured path (`snapshot.json`/`prompts.json`) is moved by **the target family's own recovery pass, in the fixed family order (snapshot first, prompts second — L2)** — renamed to that family's quarantine name — after which the moved entry's configured path is absent while its bytes survive at that family's quarantine path (rename preserves identity and bytes); a source family's link left pointing at that absent path dangles, and which family moves it is fixed by the target's position: a `prompts.json` target moves in the prompts pass (second), after the snapshot pass has classified and moved its own link through the still-present chain, and a `snapshot.json` target moves in the snapshot pass (first), after which the prompts pass observes its chain's target absent and no-ops via the absent branch (zero prompts `Recovery`, no prompts record); the move is recovery, never retention, and both families report only their own quarantines (at most one `Recovery` per family, no cross-family record).** **A stat-error entry is never read (unreadable ⇒ `read_error`, R6) and the entry itself — the link — is what moves (AC2-4 loop subcase).** Non-regular entries (stat-success modes that are neither directory nor regular file) are never read and never renamed (R3).
- **R3 Fatal classes.** A directory at a family path (including a symlink resolving to a directory), a **non-regular entry that is neither absent, directory, nor regular file — FIFO, socket, or device, including a symlink resolving to one — which is never opened and never renamed**, a rename failure, a reservation-create failure **other than `fs.ErrExist`** (a colliding candidate name is expected, not fatal: the reservation advances to the next candidate; only a create error other than `fs.ErrExist` is fatal), a post-rename directory-sync failure, and exhaustion of all 4096 reservation candidates are **fatal**: `RecoverRejected` returns an error wrapping the new sentinel `storage.ErrSnapshotUnrecoverable` and the real cause; `serve.go` maps it to the existing `stateDirectoryFailure(state dir)` and returns that classification **wrapped together with the real cause** in one error value (an unexported `serve.go` error type whose chain yields both the `startupFailure` and the cause), so `runContext` writes exactly one `startup_failed` record (`code=state_directory`, `kind=resource`, `resource.path`) and the real cause stays reachable on the returned error via `errors.Is`/unwrap — never rendered into any record field. Nothing is overwritten on the fatal path.
- **R4 Typed warning records.** Each completed quarantine yields exactly one stderr `startup_snapshot_rejected` record: level `warn`, operation `startup`, outcome `degraded`, `error.code=snapshot_unavailable` (`kind=resource`), `failure_reason` (finite taxonomy), `resource.path`=configured state directory, `quarantine_path`=absolute quarantine path. Retention failures yield one `snapshot_retention_failed` record each — level `warn`, operation `startup`, outcome `failure`, `error.code=state_directory` (`kind=resource`, `retryable=false`, remediation `"create the configured state directory or fix its permissions"`) — carrying the event's **fixed `eventMessage` text `"quarantine retention failed"`, not the generic default `"mcp-bridge event"`**. No `startup_failed` and no `internal_error` is emitted for the recoverable path. Records for completed recoveries are emitted **before** any fatal return.
- **R5 Retention bounds — per-family filter, total bound, pinned eviction, failure-exceed permitted.** Retention is strictly **per family**: a retention pass considers only its own family's conforming quarantine names — `<family>.corrupt-<RFC3339Nano UTC Z>.json` with `<family>` instantiated to the pass's family (`snapshot` or `prompts`); a conforming name of the **other** family is **foreign — never counted toward the bound, never a prune candidate, never unlinked**. Per family, after a run at most `QuarantineKeep` (5) **total** conforming quarantine files of that family are retained **on the successful eviction path** (ordinary case; the protection carve-out below is the stated exception): pruning keeps this run's own file unconditionally and **evicts that family's unprotected pre-existing conforming files oldest-first (by parsed RFC3339Nano timestamp, ties broken by full name ascending) until exactly four pre-existing conforming files of the family survive (a no-op when four or fewer pre-exist)** — so **on the successful path** the total never exceeds `QuarantineKeep` and this run's file is never pruned, even when a future-dated pre-existing name outranks it. **Run-level protected-target set, complete-chain population, entry-identity matching, and eviction skip (C6/F1/C1 + CR-LOWs; candidate set per F2; entry identity per F1/L1; resolution base per F2/D11): the set is populated once at the start of `RecoverRejected`, before the first family pass, from BOTH configured family paths — for each family path whose directory entry is a symlink (`lstat`), walk its COMPLETE backing chain hop by hop: `os.Readlink` the current link, `filepath.Clean` the target text, join a **relative** target onto **`filepath.Dir` of the link just read** — that link's own containing directory: the state directory for the configured family path and any state-dir-resident intermediate link (identical before and after the same-directory rename), the link's own subdirectory for a subdirectory link, so `/s/sub/l1 → ../snapshot.corrupt-q5.json` resolves to `/s/snapshot.corrupt-q5.json` and never to an out-of-directory path (F2) — then resolve the target's entry — an intermediate symlink entry continues the walk, a regular file ends it (the final target), and each resolution failure terminates it harmlessly (no fatal, no record, visited entries still protected): **ELOOP** (a cycle — an already-visited link identity revisited — or an `ELOOP`/loop error from `Stat`; the cycle's visited link entries match by their own recorded **entry** identities and paths, never by `Stat`, which loops — F1), **dangling link** (a target path that does not exist; its cleaned path is recorded as a lexical fallback), **non-conforming final target** (a regular final target that is not a conforming quarantine name of either family or lies outside the state directory — protected by identity, never a listing candidate), **directory final target** (never a candidate; its own family is R3-fatal through the resolved `Stat`), **alias spelling** (an alternate spelling of the same file — absolute alias or symlinked directory component — handled by entry-identity matching, not lexical comparison). EVERY visited chain element — each intermediate link entry and the final target — is added to the set by its **entry identity** (`lstat` device+inode of the element's own path; the final regular target's `lstat` identity equals its `Stat` backing identity, so `Stat` is recorded only for that backing target — L1) **and by its cleaned absolute path as a lexical fallback** (F1 — a `Stat`-failing link still matches by its own entry identity and its own recorded path); an element whose entry identity cannot be obtained (`lstat` failure) is recorded by its cleaned absolute path alone. Rename preserves identity, so the quarantined symlink entries this run creates remain protected after their move; each moved entry is this run's own family file (never a candidate) and foreign-named for the other pass (never a candidate). Protection membership and retention candidacy are compared on the candidate side by **entry identity** (`os.SameFile` semantics, device+inode) and cleaned path — **never by the candidate's `Stat` resolution (L1: a conforming symlink that merely resolves into a protected target is NOT itself protected)**: a candidate is protected iff its entry identity equals a recorded protected identity, or its cleaned absolute path equals a recorded lexical fallback path (no spurious protection: a candidate matching no identity and no fallback path is unprotected). An out-of-directory chain element is recorded but can never match a state-directory listing entry (vacuous protection, no error, no read); no target is opened — the set is identities plus recorded fallback paths. Population is a superset of every link entry this run moves and every chain element behind it, and the set is consulted unchanged by BOTH family passes, so the resolved backing evidence of a moved link is protected even when the family that would evict it runs first (F1 counterexamples A/B; C1's chain counterexample; AC1-3/AC1-10 cross-family, chain, subdirectory, alternating-hop, alias, ELOOP, mixed, and vacuous subcases). A resolved element that is absent, a directory, not a conforming quarantine name of either family, or one of the two configured family paths itself (a self-referential link `Stat`s `ELOOP` and quarantines as `read_error`) can never be a listing candidate: protection there is vacuous and the bound is unaffected. The eviction candidate set is ALL unprotected pre-existing conforming files of that family, oldest-first: this run's own file and every run-level protected chain element are excluded before selection, and each selected candidate is attempted at most once, oldest first, until exactly four pre-existing survive — or until no unprotected candidate remains, when a walked chain protects more than four pre-existing conforming files of the family: then every protected file survives, the family retains above `QuarantineKeep` on the successful path, and **the survivor bound yields to protection, never the reverse — evicting a protected file to force four survivors would reintroduce C1**. **Mixed case (L3): when more than four protected pre-existing conforming files coexist with additional unprotected ones, the exhaustion deletes EVERY unprotected pre-existing file oldest-first and then stops with no candidate remaining — the bound cannot be restored (the protected files alone exceed the four slots), the family retains this run's file plus every protected file above `QuarantineKeep`, and the successful deletion count is the full unprotected set (AC1-10(b-mix) pins the survivor/deletion counts).** In the ordinary case (at most four protected — and, with entry-identity candidacy, no over-protection through `Stat` resolution, L1) the survivors are exactly this run's file plus four pre-existing — a protected file holds one of the four surviving pre-existing slots — so the total never exceeds `QuarantineKeep`, protection never breaches it, and the greater-than-four carve-out is the only successful-path excess. **No deletion cap exists (C2): the successful-path deletion count equals the excess of unprotected pre-existing conforming files above the four surviving pre-existing slots — a nine-file backlog deletes exactly five — and the `QuarantineKeep` bound applies to survivors only, never to deletions. (AC1-3/AC1-10 subcases pin the skip past each protected candidate to the next-oldest unprotected, the explicit survivor and deletion counts, the preserved target bytes, and the quarantine read-through — same-family, cross-family, chained, aliased, dangling, ELOOP, subdirectory, alternating-hop, configured-path, mixed-carve-out, vacuous-target, and backlog.)** **Failure path (C5/D10): the candidate set is selected once from the pass's listing (all unprotected pre-existing conforming files of that family, oldest-first — this run's file and every protected chain element excluded, F1/F2/C1) and each selected candidate is attempted at most once, oldest first; no candidate is retried and no younger candidate substitutes for a failed one. The first unlink failure ends that family's retention pass after exactly that one attempt with exactly one `RetentionFailure` record for the family (R4); a listing failure skips the family's prune with zero unlink attempts and exactly one `RetentionFailure` naming this run's just-created quarantine path. When listing or unlink fails the retention bound is explicitly permitted to be exceeded — the family retains more than `QuarantineKeep` conforming files, this run's file included, every surviving file's bytes untouched, and `RecoverRejected` still returns nil error (AC1-5/AC1-6 pin the attempt counts and the surviving bytes).** Pruning runs only for a family that created a quarantine this run; non-conforming, offset-form, **and other-family names are never counted or touched**; prune/listing/unlink failures are reported as non-fatal `RetentionFailure` entries, never silently ignored.
- **R6 Reason taxonomy — per-family mapping.** `Recovery.Reason` is a five-value closed vocabulary — `corrupt_json`, `checksum_mismatch`, `unsupported_schema`, `validation_failure`, `read_error` — derived deterministically from the same branch walk `Load`/`LoadPrompts` exercise. **Catalog family:** every schema-1 branch failure (decode, trailing data, frozen-checksum mismatch) is `corrupt_json`; the schema-2 checksum sentinel (`store.go:185`) is `checksum_mismatch`; the schema-version default branch is `unsupported_schema`; a failed `Snapshot.Validate` is `validation_failure`. **Prompts family:** the decode and trailing-data branches (`store.go:93-99`) are `corrupt_json`; a failed `PromptSnapshot.Validate` (`store.go:100-102`) is `validation_failure`; the prompts checksum sentinel (`store.go:103-107`, `ChecksumValue` error or `Checksum` mismatch) is `checksum_mismatch`; `unsupported_schema` is **never** produced by the prompts walk — it has no schema-version branch (`PromptSchemaVersion` is 1, `snapshot.go:111`), so a prompts seed with a foreign `schema_version` is classified by the branch it actually fails (decode or `Validate`). Unreadable paths (read or unclassified stat errors) are `read_error` for both families. `checksum_mismatch` is produced only by a checksum sentinel (catalog schema-2 or prompts), never by a schema-1 seed.
- **R7 Opt-out.** `MCP_SNAPSHOT_QUARANTINE` defaults **ON** (unset ⇒ enabled). The value `off`, compared case-insensitively and exactly, is the only disabled spelling (fail-closed opt-out for manual-inspection deployments). When disabled, no recovery runs, no file is renamed, and **no record produced by the recovery or retention path is emitted** — neither serve's enriched `startup_snapshot_rejected` (from `emitRecoveryRecords`) nor any `snapshot_retention_failed`; the **existing Durable-loader `startup_snapshot_rejected` record (`wiring.go:486-493`) is outside this prohibition and is retained exactly as today** (AC2-6 arm 1); today's behavior is otherwise retained.
- **R8 Envelope vocabulary evolution.** The shared envelope gains the optional event-specific field `quarantine_path`; the existing `failure_reason` field's admitted vocabulary is extended with the five snapshot reasons; `snapshot_unavailable` and `state_directory` join the closed runtime error classification; the new event `snapshot_retention_failed` gets a fixed message — the literal `"quarantine retention failed"`. All are optional event-specific additions: `schema_version` stays 1, no field is removed/renamed/retyped. `docs/logging-contract.md` union and tables are updated; the `EnvelopeFieldNames` count pin moves 129→130.
- **R9 Continue startup and self-heal.** After recovery, startup proceeds with no restored catalog/prompt state, admission persists and publishes a fresh valid `snapshot.json`, the loop's async initial refresh republishes `prompts.json` (`internal/service/loop.go:172` `Trigger()`; admission skips `PersistPrompts`, `internal/service/reload.go:728`), and a second run against the same state directory is a no-op (no new quarantine file, no new record).

**Non-goals (explicit):** no YAML configuration key for quarantine (env var only); no recovery for any persisted file beyond `snapshot.json`/`prompts.json` (publish temp files are already self-cleaning); no mid-run, reload-triggered, or watch-triggered recovery; no change to `ensureReplaceable` semantics or mid-run `Save`; no raw OS error text in any log field (finite codes only); no new metrics, dashboards, or alerts (see §7's documented alert-coverage exception); no schema-version change; no deletion or truncation of quarantined bytes; no `--check-config` interaction (it never opens the store).

**Approach.** One new exported storage API plus one serve-side startup hook; the failure vocabulary grows by optional event-specific additions only. No new packages, dependencies, or goroutines.

**Storage contract (`internal/storage/recovery.go`, new).**

- Sentinels/values: `ErrSnapshotUnrecoverable` (fatal class); `QuarantineKeep = 5`; `RecoveryFamily` values `"snapshot"`, `"prompts"`.
- `Recovery` carries `Family`, `Reason` (R6 taxonomy), `OriginalPath`, `QuarantinePath` (both absolute). `RetentionFailure` carries `Family`, `QuarantinePath`. `RecoveryResult` carries `Recoveries []Recovery` and `RetentionFailures []RetentionFailure`.
- `func (s *Store) RecoverRejected() (*RecoveryResult, error)`: closed store → non-nil error; **populates the run-level protected-target set once, before the first family pass (C1/F1/CR-LOWs/F2 — the complete backing chains of both configured family paths; mechanics in step (3))**; processes the snapshot family then the prompts family **and stops at the first fatal (D2): a fatal in the snapshot family leaves the prompts family unexamined, untouched, and unrecorded (AC2-7 fatal-first subcase)**; returns `(result, fatal)` where a fatal error wraps `ErrSnapshotUnrecoverable` + the real cause, and `result` still carries any completed `Recovery` entries (AC2-8a).
- Per family: (1) `os.Stat` (behind a seam). `ErrNotExist` (also a broken/dangling symlink, which resolves through the link) ⇒ absent: zero recovery, no mutation. Stat success with mode `IsDir` (including a symlink resolving to a directory) ⇒ **fatal** (R3; a directory cannot be renamed into a file slot). Stat success with any **other non-regular mode — FIFO, socket, device, or a symlink resolving to one ⇒ fatal** (R3): **the entry is never opened and never read** (a read open on a FIFO blocks indefinitely; a device can produce unbounded data) and never renamed; `ErrSnapshotUnrecoverable` wraps a typed cause naming the mode family. No open flags (`O_NONBLOCK`) are needed because no open of the family entry ever happens on this branch; symlinks are followed by `Stat` only (no `O_NOFOLLOW` open — the link-entry-moves rule of AC1-10 applies only to quarantinable branches). Any other stat error (e.g. `ELOOP`, permission) ⇒ `read_error` quarantine — the entry itself moves (R2, never read). (2) Stat success with mode `IsRegular` (a symlink to a regular target resolves through the link): read via a read seam; classify via the shared walk (D7). Valid ⇒ zero recovery, entry untouched (AC1-1c). Rejected ⇒ reserve+rename (D6): candidate names from a clock seam at `now()+i ns`, `i ∈ [0, 4096)`; a reservation create returning `fs.ErrExist` ⇒ **advance to the next candidate** (a collision is expected, never an overwrite — AC1-9(b)); any **other** create error ⇒ fatal (b-res); rename failure ⇒ remove reservation, fatal, original bytes intact (b); post-rename `syncDirectory` failure ⇒ fatal, bytes already moved, `Recovery` still returned (a); success ⇒ one `Recovery`. (3) Retention pass **only** for a family that created a quarantine this run: list via a `ReadDir` seam and parse names **per this family only** — the conforming pattern is `^<family>\.corrupt-<RFC3339Nano UTC Z>\.json$` with `<family>` instantiated to this pass's family (`snapshot` or `prompts`); a name conforming to the **other** family's pattern (`prompts.corrupt-*` during a snapshot pass, `snapshot.corrupt-*` during a prompts pass) is **foreign: never counted toward this family's `QuarantineKeep` bound, never a prune candidate, never unlinked** (R5, CR13-01). **Run-level protected-target set (C1/F1/CR-LOWs/F2/L1): populated once at the start of `RecoverRejected`, before the first family pass, from BOTH configured family paths — for each family path whose directory entry is a symlink (`lstat`), walk the COMPLETE backing chain hop by hop: `os.Readlink` the current link, `filepath.Clean` the target text, join a **relative** target onto **`filepath.Dir` of the link just read** — that link's own containing directory: the state directory for the configured family path and any state-dir-resident intermediate link (identical before and after the same-directory rename, so a link resolved at its configured path and the same link resolved at its quarantine path yield one protected element), the link's own subdirectory for a subdirectory link (D11/F2) — then resolve the target's entry. An intermediate symlink entry continues the walk (its own target read the same way); a regular file ends it (the final target); a chain element equal to the other family's configured path is walked through like any other element and is named by the cross-family configured-path move-through below. Every resolution failure terminates the walk harmlessly — no fatal, no record, visited entries still protected: **ELOOP** (a cycle — an already-visited link identity revisited — or an `ELOOP`/loop error from `Stat`; the cycle's visited link entries match by their own recorded **entry** identities and paths, never by `Stat`, which loops — F1), **dangling link** (a target path that does not exist; its cleaned path recorded as a lexical fallback), **non-conforming final target** (a regular final target that is not a conforming quarantine name of either family or lies outside the state directory — protected by identity, never a listing candidate), **directory final target** (never a candidate; its own family is R3-fatal through the resolved `Stat`), **alias spelling** (an alternate spelling of the same file — absolute alias or symlinked directory component — matched by entry identity, not lexical comparison). EVERY visited chain element — each intermediate link entry and the final target — is added to the set by its **entry identity** (`lstat` device+inode of the element's own path; a regular file's `lstat` identity equals its `Stat` backing identity, so `Stat` is recorded only for that backing target — L1) **and by its cleaned absolute path as a lexical fallback** (F1); an element whose entry identity cannot be obtained (`lstat` failure) is recorded by its cleaned absolute path alone. Identities are preserved by rename, so the quarantined symlink entries this run creates remain protected after their move, and each moved entry is this run's own family file (never a candidate) and foreign-named for the other pass (never a candidate). No target is opened; the set is identities plus recorded fallback paths. An **out-of-directory** element is recorded but can never match a state-directory listing entry — vacuous protection, no error, no read. This population is a superset of every link entry this run moves and every chain element behind it, and the set is consulted unchanged by BOTH passes — so the link of a family not yet examined is already protected when the other family runs first (F1 counterexamples A/B), and so is every deeper hop behind it (C1's chain counterexample) **and every subdirectory hop resolved against its own `filepath.Dir` (F2)**. Edge behaviors (each vacuous — the bound is unaffected): a chain element that is **absent** contributes a fallback path no listing entry can match; one that is a **directory** is never a retention candidate; one whose base name is **not a conforming quarantine name of either family** is never a candidate; one equal to **either configured family path itself** (including a self-referential link, which `Stat`s `ELOOP` and quarantines as `read_error`) is never a retention candidate. R2): when a walked chain's final target is the other family's configured path, the target family's own pass — in the fixed order (snapshot first, prompts second; D2): a `prompts.json` target moves in the second pass, after the snapshot pass has classified and moved its own link through the still-present chain; after that move the source family's moved link targets an absent path while the target's bytes survive at the target family's quarantine path (rename preserves identity and bytes); each family still reports only its own `Recovery` — no cross-family record — and retention never unlinks the entry (the move is a rename, not an unlink; the moved entry is the target family's this-run file, never a candidate).** **Eviction (F2-aligned with R5/D10): the candidate set is ALL pre-existing conforming files of this family, oldest-first (parsed RFC3339Nano timestamp, then full name ascending) — this run's own file never a candidate (even if a future-dated pre-existing name outranks it), and every run-level protected chain element excluded before selection (F1/C1) — and each selected candidate is attempted (unlink seam) at most once, oldest first, **until exactly four pre-existing conforming files of this family survive** (a no-op when four or fewer pre-exist) — **or until no unprotected candidate remains, when a walked chain protects more than four pre-existing conforming files of this family: then every protected file survives and the family retains above `QuarantineKeep` — the survivor bound yields to protection, never the reverse (C1); in the mixed case — more than four protected plus additional unprotected — the exhaustion deletes every unprotected pre-existing file and stops, the bound unrestorable (L3; AC1-10(b-mix)). The protected file is not in the candidate list: it holds one of the four surviving pre-existing slots, so the successful-path family total — this run's file plus four pre-existing — never exceeds `QuarantineKeep` in the ordinary case, and — with entry-identity candidacy (L1) — no over-protection through `Stat` resolution exists, so protection never breaches it (R5, closes SR12-04, CR13-01, CR16-F2). ## 8. RELEASE AND RECOVERY

- **Environment:** `MCP_SNAPSHOT_QUARANTINE` unset or any value other than case-insensitive `off` (including the empty string) ⇒ **enabled**; `off` ⇒ fail-closed manual-inspection mode (R7). Read once at serve startup; a change requires a process restart.
- **Deploy order:** standard image rollout + container restart; no migration, no data conversion, `schema_version` stays 1; existing quarantine files from earlier runs are inert and are honored by the retention rule at the next recovery.
- **Rollback:** redeploying a previous image is safe — old binaries never read or write quarantine names; quarantine files simply persist (optionally removed by hand). The rename is atomic; no partial state exists to clean up.
- **Irreversible steps (explicit):** (1) the quarantine rename moves the **only copy** of the rejected bytes out of the configured path — recovery for manual inspection is `MCP_SNAPSHOT_QUARANTINE=off` + restart, or renaming the file back by hand; (2) retention evicts that family's **unprotected** pre-existing conforming quarantine files oldest-first **until exactly four pre-existing survive** — **no deletion cap (C2): the successful-path deletion count equals the excess above the four surviving pre-existing files (`QuarantineKeep−1` slots), so a nine-file pre-existing backlog deletes exactly five; the `QuarantineKeep` bound applies to survivors only, never to deletions; deleted quarantined bytes are gone** — and **the other family's conforming names are foreign and never pruned (R5/CR13-01)** — **and no file in this run's run-level protected-target set is ever deleted (C6/F1/C1 → R2/R5/D10): the set is populated before the first family pass by walking each configured family path's COMPLETE backing chain — every intermediate link entry plus the final regular target, **each relative target resolved against `filepath.Dir` of the link just read (F2/D11)**, matched by **entry identity (`lstat`)** with the final target's backing `Stat` identity and **every visited element's cleaned path as a lexical fallback (F1/L1)**, each resolution failure (ELOOP, dangling link, non-conforming final target, directory final target, alias spelling) terminating the walk harmlessly — so the resolved backing evidence of a moved link survives even when the family that would evict it runs first, even when it is older than the eviction would otherwise keep, and even when it is reachable only through intermediate pre-existing conforming symlinks (C1's chain counterexample) **or through subdirectory links whose parent-relative targets resolve back into the state directory (F2)**; each family ends at or below `QuarantineKeep` in the ordinary case because every protected pre-existing file occupies one of the four surviving pre-existing slots — when a chain protects more than four, every protected file survives and the family retains above `QuarantineKeep`: protection wins over the survivor bound, never the reverse; **in the mixed case — more than four protected pre-existing conforming files coexisting with additional unprotected ones — the exhaustion deletes every unprotected pre-existing file while the bound cannot be restored (L3; AC1-10(b-mix) pins the counts)**; the one documented move that reaches a protected target is the cross-family configured-path move-through (CR-LOW/L2; R2): **the target family's own pass, in the fixed order (a `prompts.json` target moves second, after the snapshot pass has classified and moved its own link through the still-present chain; a `snapshot.json` target moves first, after which the prompts pass no-ops on the absent branch), renames its configured path to quarantine (a recovery move, never a retention unlink)**, after which the source family's link target path is absent while its bytes survive at that family's quarantine path, and each family still reports only its own quarantine — **a retention failure (listing or unlink) ends that family's pass with one warn record and explicitly leaves the family above `QuarantineKeep`: never a silent retry, a deletion retry, or a fatal (R5/D10, C5)**; (3) a crash between reservation and rename can leave one empty conforming-named file (inert; counted by a later retention pass; manually removable). **The irreversible-deletion contract of step (2) is flagged for the affected owner's confirmation before implementation (C5/C6/C1;
