# SNAPREC-SPEC-r12 — snapshot-recovery (fresh revision, plan round 1 of ≤3)

## 1. STATUS

- **Spec ID / revision:** `SNAPREC-SPEC-r12`, revision **r12**, plan round **1** of at most 3.
- **Status:** DRAFT — ready for staged independent review; planner approves nothing and gates nothing.
- **Objective:** A snapshot (`snapshot.json`) or prompt snapshot (`prompts.json`) the store refuses is **recoverable startup state**: its entry is quarantined exactly once by an atomic same-directory rename before admission, startup continues with no cached state and publishes a fresh generation, and the act is reported in one typed warn record per affected family — without weakening `ensureReplaceable`'s no-overwrite protection (`internal/storage/store.go:295-306`) or `Load`'s rejection wrapping (`internal/storage/store.go:149-195`).
- **Freshness:** newly derived from ticket 01 + this session's verified reads. It does not repair, reuse, review, or copy any r11 clause, task ledger, or finding ledger; r10 review classes are treated only as advisory hazards (§9).

## 2. REQUIREMENTS
<!-- specdd:requirements:start -->

Stable ids R1–R9. Non-goals follow.

- **R1 Recovery locus — one startup-phase mutator.** Recovery is exactly one new `Store` method, `RecoverRejected`, called **once per process** by `cmd/mcp-bridge/serve.go` immediately after `storage.Open` succeeds and before any admission/loop work. It is the only code path that creates or prunes quarantine files. `Load`, `Save`, `LoadPrompts`, `SavePrompts`, and `ensureReplaceable` keep today's observable behavior byte-for-byte and never quarantine.
- **R2 Quarantine-once byte preservation.** Per family, a store-rejected file is moved exactly once via `os.Rename` into the same state directory under a bounded conforming quarantine name; bytes are preserved (rename, never delete/truncate/overwrite-first); the configured path is absent afterwards; a file that loads is never moved; the target of a symlinked entry is never touched.
- **R3 Fatal classes.** A directory at a family path (including a symlink resolving to a directory), a rename failure, a reservation-create failure, a post-rename directory-sync failure, and exhaustion of the 4096 reservation attempts are **fatal**: `RecoverRejected` returns an error wrapping the new sentinel `storage.ErrSnapshotUnrecoverable` and the real cause; `serve.go` maps it to the existing `stateDirectoryFailure(state dir)`, so `runContext` writes exactly one `startup_failed` record (`code=state_directory`, `kind=resource`, `resource.path`). Nothing is overwritten on the fatal path.
- **R4 Typed warning records.** Each completed quarantine yields exactly one stderr `startup_snapshot_rejected` record: level `warn`, operation `startup`, outcome `degraded`, `error.code=snapshot_unavailable` (`kind=resource`), `failure_reason` (finite taxonomy), `resource.path`=configured state directory, `quarantine_path`=absolute quarantine path. Retention failures yield one `snapshot_retention_failed` record each (`warn`/`startup`/`failure`, `code=state_directory`). No `startup_failed` and no `internal_error` is emitted for the recoverable path. Records for completed recoveries are emitted **before** any fatal return.
- **R5 Retention bounds.** Per family, at most `QuarantineKeep` (5) newest **conforming** quarantine files are retained; pruning runs only for a family that created a quarantine this run; this run's own file is never pruned; non-conforming and offset-form names are never counted or touched; prune/listing/unlink failures are reported as non-fatal `RetentionFailure` entries, never silently ignored.
- **R6 Reason taxonomy.** `Recovery.Reason` is a five-value closed vocabulary — `corrupt_json`, `checksum_mismatch`, `unsupported_schema`, `validation_failure`, `read_error` — derived deterministically from the same branch walk `Load`/`LoadPrompts` exercise: every schema-1 branch failure (decode, trailing data, frozen-checksum mismatch) is `corrupt_json`; `checksum_mismatch` is produced only by the schema-2 checksum sentinel; unreadable paths (read or unclassified stat errors) are `read_error`.
- **R7 Opt-out.** `MCP_SNAPSHOT_QUARANTINE` defaults **ON** (unset ⇒ enabled). The value `off`, compared case-insensitively and exactly, is the only disabled spelling (fail-closed opt-out for manual-inspection deployments). When disabled, no recovery runs, no file is renamed, and **no** recovery or retention record of any kind is emitted; today's behavior is retained.
- **R8 Envelope vocabulary evolution.** The shared envelope gains the optional event-specific field `quarantine_path`; the existing `failure_reason` field's admitted vocabulary is extended with the five snapshot reasons; `snapshot_unavailable` and `state_directory` join the closed runtime error classification; the new event `snapshot_retention_failed` gets a fixed message. All are optional event-specific additions: `schema_version` stays 1, no field is removed/renamed/retyped. `docs/logging-contract.md` union and tables are updated; the `EnvelopeFieldNames` count pin moves 129→130.
- **R9 Continue startup and self-heal.** After recovery, startup proceeds with no restored catalog/prompt state, admission persists and publishes a fresh valid `snapshot.json`, the loop's async initial refresh republishes `prompts.json` (`internal/service/loop.go:172` `Trigger()`; admission skips `PersistPrompts`, `internal/service/reload.go:728`), and a second run against the same state directory is a no-op (no new quarantine file, no new record).

**Non-goals (explicit):** no YAML configuration key for quarantine (env var only); no recovery for any persisted file beyond `snapshot.json`/`prompts.json` (publish temp files are already self-cleaning); no mid-run, reload-triggered, or watch-triggered recovery; no change to `ensureReplaceable` semantics or mid-run `Save`; no raw OS error text in any log field (finite codes only); no new metrics, dashboards, or alerts; no schema-version change; no deletion or truncation of quarantined bytes; no `--check-config` interaction (it never opens the store).

## 4. DESIGN
<!-- specdd:design:start -->

**Approach.** One new exported storage API plus one serve-side startup hook; the failure vocabulary grows by optional event-specific additions only. No new packages, dependencies, or goroutines.

**Storage contract (`internal/storage/recovery.go`, new).**

- Sentinels/values: `ErrSnapshotUnrecoverable` (fatal class); `QuarantineKeep = 5`; `RecoveryFamily` values `"snapshot"`, `"prompts"`.
- `Recovery` carries `Family`, `Reason` (R6 taxonomy), `OriginalPath`, `QuarantinePath` (both absolute). `RetentionFailure` carries `Family`, `QuarantinePath`. `RecoveryResult` carries `Recoveries []Recovery` and `RetentionFailures []RetentionFailure`.
- `func (s *Store) RecoverRejected() (*RecoveryResult, error)`: closed store → non-nil error; processes the snapshot family then the prompts family; returns `(result, fatal)` where a fatal error wraps `ErrSnapshotUnrecoverable` + the real cause, and `result` still carries any completed `Recovery` entries (AC2-8a).
- Per family: (1) `os.Stat` (behind a seam). `ErrNotExist` (also a broken/dangling symlink, which resolves through the link) ⇒ absent: zero recovery, no mutation. Resolves to a directory ⇒ fatal (R3; a directory cannot be renamed into a file slot). Any other stat error (e.g. `ELOOP`, permission) ⇒ `read_error` quarantine — the entry itself moves. (2) regular file (a symlink to a regular target resolves through the link): read via a read seam; classify via the shared walk (D7). Valid ⇒ zero recovery, entry untouched (AC1-1c). Rejected ⇒ reserve+rename (D6): candidate names from a clock seam at `now()+i ns`, `i ∈ [0, 4096)`; reservation create failure ⇒ fatal (b-res); rename failure ⇒ remove reservation, fatal, original bytes intact (b); post-rename `syncDirectory` failure ⇒ fatal, bytes already moved, `Recovery` still returned (a); success ⇒ one `Recovery`. (3) retention pass **only** for a family that created a quarantine this run: list via a `ReadDir` seam, parse conforming names `^(snapshot|prompts)\.corrupt-<RFC3339Nano UTC Z>\.json$`, sort by parsed timestamp (ties by name ascending), retain `QuarantineKeep` newest with this run's file always retained, unlink older conforming files via an unlink seam; any unlink failure ⇒ `RetentionFailure{family, path}`; listing failure ⇒ prune skipped for the family and exactly one `RetentionFailure{family, this run's quarantine path}` (the one file this run created but could not verify retention for). Non-conforming and offset-form names are never counted or removed.
- Seams are unexported package vars in `recovery.go` (`stat`, `readFile`, `reserve`, `rename`, `remove`, `readDir`, `syncDir`, `now`); `recovery_test.go` is the internal `package storage` test file that injects them (Go permits mixed internal/external test files; `store_edge_test.go` stays `package storage_test`).

**Serve wiring (`cmd/mcp-bridge/serve.go`).**

- Immediately after the `storage.Open`/`defer store.Close()` block (`serve.go:96-99`), before JWKS construction: if `quarantineEnabled(os.Getenv("MCP_SNAPSHOT_QUARANTINE"))` (D4), call `store.RecoverRejected()`; emit records via a new `emitRecoveryRecords(logger, stateDir string, result *storage.RecoveryResult)`; then `if errors.Is(err, storage.ErrSnapshotUnrecoverable) { return stateDirectoryFailure(settings.StorageDirectory) }`. Disabled ⇒ no call, no records.
- `emitRecoveryRecords`: per `Recovery` → one `logger.Log` entry `warn`/`startup_snapshot_rejected`/`startup`/`degraded`, `Error{snapshot_unavailable, resource, retryable true, static remediation}`, `Fields{failure_reason, quarantine_path, resource.path: stateDir}`; per `RetentionFailure` → one `warn`/`snapshot_retention_failed`/`startup`/`failure` entry, `Error{state_directory, resource, false, static remediation}`, `Fields{quarantine_path, resource.path: stateDir}`. Family order fixes stream order (snapshot record before prompts record).
- `startupFailureForError` and `startup_failure.go` are untouched; the fatal mapping lives in `serve.go` and reuses the existing constructor (`startup_failure.go:26`).

**Observe vocabulary (`internal/observe/envelope.go`, `log.go`).**

- `addEnvelopeFields`: new `"quarantine_path"` case — non-empty string admitted, else the record falls back (closed union discipline preserved). `validFailureReason` extended with the five snapshot reasons. `runtimeErrorInfo` extended with `snapshot_unavailable` (resource, retryable, existing remediation) and `state_directory` (resource, not retryable, existing remediation). `envelopeFieldNames` gains `"quarantine_path"` (sorted between `publication_impact` and `refresh_id`; count 129→130). `eventMessage` gains `snapshot_retention_failed` → fixed message. No existing field removed/renamed/retyped; `schema_version` stays 1 (optional event-specific additions per the docs rule).
- `docs/logging-contract.md`: field-union block += `quarantine_path`; event table += `snapshot_retention_failed | startup | warn / failure`; AD13 lifecycle table += `snapshot_retention_failed` row and `startup_snapshot_rejected` event-specific fields (`failure_reason`, `quarantine_path`, `resource.path`); shared error-classification table += `snapshot_unavailable`, `state_directory`; `failure_reason` vocabulary extension documented (discovery ∪ snapshot reasons).

**Compatibility/security/failure behavior.**

- `Load`/`Save`/`ensureReplaceable` public behavior byte-identical (existing unmodified tests are the regression oracle). After a quarantine, `ensureReplaceable` sees `ErrNoSnapshot`→replaceable, so admission publishes the fresh generation without any new trust logic.
- Quarantine names come from a fixed grammar + clock; no user/peer input enters a name. No credentials exist in snapshots by design; records carry only paths and finite codes. Env values are never logged.
- Logger failure behavior unchanged: one write attempt, `logging_write_failed` fallback on the opposite lane, no retry.

**Shared-state / lifecycle walk (W09E).** Writers of state-dir entries: `publish`/`publishFile` (temp+rename), recovery (startup rename), retention (unlink), `Close` (lock removal). Quarantine runs in the single-threaded bootstrap window before the loop exists, so no competing `Save`/`Load` can interleave; `RecoverRejected` has no internal concurrency. Crash between reservation and rename leaves one empty conforming-named file — inert, counted by a later retention pass, prunable by hand (documented in §8). A crash after rename before sync leaves the bytes safely at the quarantine path. Mid-run rejection still wedges exactly as today (AC1-7/AC2-6 arm 1) — the recovery path is startup-only by construction.

**Alternatives considered.** Recovery inside `ensureReplaceable` (rejected, D1) — mutates state mid-run and changes `Save`; emission via `wiring.go` `operatorLog` (rejected, D8) — file is read-only and the format-string matching cannot carry structured results; deleting the rejected file instead of quarantining (rejected) — destroys the operator's only evidence, the exact incident harm; a config-file setting (rejected) — owner chose an env var; recovery on every `Load` (rejected) — would quarantine during reload probes and break AC1-7.

## 8. RELEASE AND RECOVERY

- **Environment:** `MCP_SNAPSHOT_QUARANTINE` unset or any value other than case-insensitive `off` ⇒ **enabled**; `off` ⇒ fail-closed manual-inspection mode (R7). Read once at serve startup; a change requires a process restart.
- **Deploy order:** standard image rollout + container restart; no migration, no data conversion, `schema_version` stays 1; existing quarantine files from earlier runs are inert and are honored by the retention rule at the next recovery.
- **Rollback:** redeploying a previous image is safe — old binaries never read or write quarantine names; quarantine files simply persist (optionally removed by hand). The rename is atomic; no partial state exists to clean up.
- **Irreversible steps (explicit):** (1) the quarantine rename moves the **only copy** of the rejected bytes out of the configured path — recovery for manual inspection is `MCP_SNAPSHOT_QUARANTINE=off` + restart, or renaming the file back by hand; (2) retention deletes quarantine files beyond the `QuarantineKeep` newest per family — deleted quarantined bytes are gone; (3) a crash between reservation and rename can leave one empty conforming-named file (inert; counted by a later retention pass; manually removable).
- **Post-acceptance persistence failures** (`startup_publication_failed`) and reload rejections are unchanged by this feature.
