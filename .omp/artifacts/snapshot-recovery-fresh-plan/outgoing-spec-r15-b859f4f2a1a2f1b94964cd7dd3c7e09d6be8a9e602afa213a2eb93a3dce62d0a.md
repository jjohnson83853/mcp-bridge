## 2. REQUIREMENTS

Stable ids R1–R9. Non-goals follow.

- **R1 Recovery locus — one startup-phase mutator.** Recovery is exactly one new `Store` method, `RecoverRejected`, called **once per process** by `cmd/mcp-bridge/serve.go` immediately after `storage.Open` succeeds and before any admission/loop work. It is the only code path that creates or prunes quarantine files. `Load`, `Save`, `LoadPrompts`, `SavePrompts`, and `ensureReplaceable` keep today's observable behavior byte-for-byte and never quarantine.
- **R2 Quarantine-once byte preservation.** Per family, a store-rejected **regular** file — **a symlink entry resolving to one, or an entry whose `os.Stat` fails with a recoverable stat error other than `fs.ErrNotExist` (e.g. `ELOOP` from a symlink loop; the rename needs no successful read)** — is moved exactly once via `os.Rename` into the same state directory under a bounded conforming quarantine name; bytes are preserved (rename, never delete/truncate/overwrite-first); the configured path is absent afterwards; a file that loads is never moved; the target of a symlinked entry is never touched. **A stat-error entry is never read (unreadable ⇒ `read_error`, R6) and the entry itself — the link — is what moves (AC2-4 loop subcase).** Non-regular entries (stat-success modes that are neither directory nor regular file) are never read and never renamed (R3).
- **R3 Fatal classes.** A directory at a family path (including a symlink resolving to a directory), a **non-regular entry that is neither absent, directory, nor regular file — FIFO, socket, or device, including a symlink resolving to one — which is never opened and never renamed**, a rename failure, a reservation-create failure **other than `fs.ErrExist`** (a colliding candidate name is expected, not fatal: the reservation advances to the next candidate; only a create error other than `fs.ErrExist` is fatal), a post-rename directory-sync failure, and exhaustion of all 4096 reservation candidates are **fatal**: `RecoverRejected` returns an error wrapping the new sentinel `storage.ErrSnapshotUnrecoverable` and the real cause; `serve.go` maps it to the existing `stateDirectoryFailure(state dir)` and returns that classification **wrapped together with the real cause** in one error value (an unexported `serve.go` error type whose chain yields both the `startupFailure` and the cause), so `runContext` writes exactly one `startup_failed` record (`code=state_directory`, `kind=resource`, `resource.path`) and the real cause stays reachable on the returned error via `errors.Is`/unwrap — never rendered into any record field. Nothing is overwritten on the fatal path.
- **R4 Typed warning records.** Each completed quarantine yields exactly one stderr `startup_snapshot_rejected` record: level `warn`, operation `startup`, outcome `degraded`, `error.code=snapshot_unavailable` (`kind=resource`), `failure_reason` (finite taxonomy), `resource.path`=configured state directory, `quarantine_path`=absolute quarantine path. Retention failures yield one `snapshot_retention_failed` record each — level `warn`, operation `startup`, outcome `failure`, `error.code=state_directory` (`kind=resource`, `retryable=false`, remediation `"create the configured state directory or fix its permissions"`) — carrying the event's **fixed `eventMessage` text `"quarantine retention failed"`, not the generic default `"mcp-bridge event"`**. No `startup_failed` and no `internal_error` is emitted for the recoverable path. Records for completed recoveries are emitted **before** any fatal return.
- **R5 Retention bounds — per-family filter, total bound, pinned eviction, failure-exceed permitted.** Retention is strictly **per family**: a retention pass considers only its own family's conforming quarantine names — `<family>.corrupt-<RFC3339Nano UTC Z>.json` with `<family>` instantiated to the pass's family (`snapshot` or `prompts`); a conforming name of the **other** family is **foreign — never counted toward the bound, never a prune candidate, never unlinked**. Per family, after a run at most `QuarantineKeep` (5) **total** conforming quarantine files of that family are retained **on the successful eviction path**: pruning keeps this run's own file unconditionally and **evicts pre-existing conforming files of that family oldest-first (by parsed RFC3339Nano timestamp, ties broken by full name ascending) while more than `QuarantineKeep−1` (4) pre-existing remain** — the eviction stops as soon as four pre-existing survive (a no-op when four or fewer pre-exist), so **on the successful path** the total never exceeds `QuarantineKeep` and this run's file is never pruned, even when a future-dated pre-existing name outranks it. **Failure path (C5/D10): the eviction candidate set is selected once from the pass's listing — this run's file never a candidate — and each selected candidate is attempted at most once, oldest first; no candidate is retried and no younger candidate substitutes for a failed one. The first unlink failure ends that family's retention pass after exactly that one attempt with exactly one `RetentionFailure` record for the family (R4); a listing failure skips the family's prune with zero unlink attempts and exactly one `RetentionFailure` naming this run's just-created quarantine path. When listing or unlink fails the retention bound is explicitly permitted to be exceeded — the family retains more than `QuarantineKeep` conforming files, this run's file included, every surviving file's bytes untouched, and `RecoverRejected` still returns nil error (AC1-5/AC1-6 pin the attempt counts and the surviving bytes).** Pruning runs only for a family that created a quarantine this run; non-conforming, offset-form, **and other-family names are never counted or touched**; prune/listing/unlink failures are reported as non-fatal `RetentionFailure` entries, never silently ignored.
- **R6 Reason taxonomy — per-family mapping.** `Recovery.Reason` is a five-value closed vocabulary — `corrupt_json`, `checksum_mismatch`, `unsupported_schema`, `validation_failure`, `read_error` — derived deterministically from the same branch walk `Load`/`LoadPrompts` exercise. **Catalog family:** every schema-1 branch failure (decode, trailing data, frozen-checksum mismatch) is `corrupt_json`; the schema-2 checksum sentinel (`store.go:185`) is `checksum_mismatch`; the schema-version default branch is `unsupported_schema`; a failed `Snapshot.Validate` is `validation_failure`. **Prompts family:** the decode and trailing-data branches (`store.go:93-99`) are `corrupt_json`; a failed `PromptSnapshot.Validate` (`store.go:100-102`) is `validation_failure`; the prompts checksum sentinel (`store.go:103-107`, `ChecksumValue` error or `Checksum` mismatch) is `checksum_mismatch`; `unsupported_schema` is **never** produced by the prompts walk — it has no schema-version branch (`PromptSchemaVersion` is 1, `snapshot.go:111`), so a prompts seed with a foreign `schema_version` is classified by the branch it actually fails (decode or `Validate`). Unreadable paths (read or unclassified stat errors) are `read_error` for both families. `checksum_mismatch` is produced only by a checksum sentinel (catalog schema-2 or prompts), never by a schema-1 seed.
- **R7 Opt-out.** `MCP_SNAPSHOT_QUARANTINE` defaults **ON** (unset ⇒ enabled). The value `off`, compared case-insensitively and exactly, is the only disabled spelling (fail-closed opt-out for manual-inspection deployments). When disabled, no recovery runs, no file is renamed, and **no record produced by the recovery or retention path is emitted** — neither serve's enriched `startup_snapshot_rejected` (from `emitRecoveryRecords`) nor any `snapshot_retention_failed`; the **existing Durable-loader `startup_snapshot_rejected` record (`wiring.go:486-491`) is outside this prohibition and is retained exactly as today** (AC2-6 arm 1); today's behavior is otherwise retained.
- **R8 Envelope vocabulary evolution.** The shared envelope gains the optional event-specific field `quarantine_path`; the existing `failure_reason` field's admitted vocabulary is extended with the five snapshot reasons; `snapshot_unavailable` and `state_directory` join the closed runtime error classification; the new event `snapshot_retention_failed` gets a fixed message — the literal `"quarantine retention failed"`. All are optional event-specific additions: `schema_version` stays 1, no field is removed/renamed/retyped. `docs/logging-contract.md` union and tables are updated; the `EnvelopeFieldNames` count pin moves 129→130.
- **R9 Continue startup and self-heal.** After recovery, startup proceeds with no restored catalog/prompt state, admission persists and publishes a fresh valid `snapshot.json`, the loop's async initial refresh republishes `prompts.json` (`internal/service/loop.go:172` `Trigger()`; admission skips `PersistPrompts`, `internal/service/reload.go:728`), and a second run against the same state directory is a no-op (no new quarantine file, no new record).

## 4. DESIGN
<!-- specdd:design:start -->

**Approach.** One new exported storage API plus one serve-side startup hook; the failure vocabulary grows by optional event-specific additions only. No new packages, dependencies, or goroutines.

**Storage contract (`internal/storage/recovery.go`, new).**

- Sentinels/values: `ErrSnapshotUnrecoverable` (fatal class); `QuarantineKeep = 5`; `RecoveryFamily` values `"snapshot"`, `"prompts"`.
- `Recovery` carries `Family`, `Reason` (R6 taxonomy), `OriginalPath`, `QuarantinePath` (both absolute). `RetentionFailure` carries `Family`, `QuarantinePath`. `RecoveryResult` carries `Recoveries []Recovery` and `RetentionFailures []RetentionFailure`.
- `func (s *Store) RecoverRejected() (*RecoveryResult, error)`: closed store → non-nil error; processes the snapshot family then the prompts family **and stops at the first fatal (D2): a fatal in the snapshot family leaves the prompts family unexamined, untouched, and unrecorded (AC2-7 fatal-first subcase)**; returns `(result, fatal)` where a fatal error wraps `ErrSnapshotUnrecoverable` + the real cause, and `result` still carries any completed `Recovery` entries (AC2-8a).
- Per family: (1) `os.Stat` (behind a seam). `ErrNotExist` (also a broken/dangling symlink, which resolves through the link) ⇒ absent: zero recovery, no mutation. Stat success with mode `IsDir` (including a symlink resolving to a directory) ⇒ **fatal** (R3; a directory cannot be renamed into a file slot). Stat success with any **other non-regular mode — FIFO, socket, device, or a symlink resolving to one ⇒ fatal** (R3): **the entry is never opened and never read** (a read open on a FIFO blocks indefinitely; a device can produce unbounded data) and never renamed; `ErrSnapshotUnrecoverable` wraps a typed cause naming the mode family. No open flags (`O_NONBLOCK`) are needed because no open of the family entry ever happens on this branch; symlinks are followed by `Stat` only (no `O_NOFOLLOW` open — the link-entry-moves rule of AC1-10 applies only to quarantinable branches). Any other stat error (e.g. `ELOOP`, permission) ⇒ `read_error` quarantine — the entry itself moves (R2, never read). (2) Stat success with mode `IsRegular` (a symlink to a regular target resolves through the link): read via a read seam; classify via the shared walk (D7). Valid ⇒ zero recovery, entry untouched (AC1-1c). Rejected ⇒ reserve+rename (D6): candidate names from a clock seam at `now()+i ns`, `i ∈ [0, 4096)`; a reservation create returning `fs.ErrExist` ⇒ **advance to the next candidate** (a collision is expected, never an overwrite — AC1-9(b)); any **other** create error ⇒ fatal (b-res); rename failure ⇒ remove reservation, fatal, original bytes intact (b); post-rename `syncDirectory` failure ⇒ fatal, bytes already moved, `Recovery` still returned (a); success ⇒ one `Recovery`. (3) Retention pass **only** for a family that created a quarantine this run: list via a `ReadDir` seam and parse names **per this family only** — the conforming pattern is `^<family>\.corrupt-<RFC3339Nano UTC Z>\.json$` with `<family>` instantiated to this pass's family (`snapshot` or `prompts`); a name conforming to the **other** family's pattern (`prompts.corrupt-*` during a snapshot pass, `snapshot.corrupt-*` during a prompts pass) is **foreign: never counted toward this family's `QuarantineKeep` bound, never a prune candidate, never unlinked** (R5, CR13-01). **Evict this family's pre-existing conforming files oldest-first by (parsed timestamp, then full name ascending): the candidate set is selected once from the listing — the pre-existing conforming files of this family beyond the `QuarantineKeep−1` (4) newest pre-existing slots, this run's own file never a candidate (even if a future-dated pre-existing name outranks it) — and each selected candidate is attempted (unlink seam) at most once, oldest first. The pass stops as soon as four pre-existing survive (a no-op with four or fewer pre-existing), so the successful path never exceeds `QuarantineKeep` (R5, closes SR12-04 and CR13-01). The first unlink failure ends this family's retention pass after exactly that one attempt with exactly one `RetentionFailure{family, attempted path}`; a listing failure skips the family's prune with zero unlink attempts and exactly one `RetentionFailure{family, this run's quarantine path}` (the one file this run created but could not verify retention for); no candidate is retried and no younger candidate substitutes for a failed one — and on either failure the family's retained total is explicitly permitted to exceed `QuarantineKeep`, every surviving file's bytes untouched (R5/D10, closes C5's non-termination and count contradictions). Non-conforming, offset-form, **and other-family names are never counted or removed.**

**Shared-state / lifecycle walk (W09E).** Writers of state-dir entries: `publish`/`publishFile` (temp+rename), recovery (startup rename), retention (unlink), `Close` (lock removal). Mid-run rejection still wedges exactly as today (AC1-7/AC2-6 arm 1) — the recovery path is startup-only by construction. A FIFO/socket/device entry is never opened on any path, so no branch can block bootstrap.

**Alternatives considered.** Recovery inside `ensureReplaceable` (rejected, D1) — mutates state mid-run and changes `Save`; emission via `wiring.go` `operatorLog` (rejected, D8) — file is read-only and the format-string matching cannot carry structured results; deleting the rejected file instead of quarantining (rejected) — destroys the operator's only evidence, the exact incident harm; a config-file setting (rejected) — owner chose an env var; recovery on every `Load` (rejected) — would quarantine during reload probes and break AC1-7; quarantining non-regular entries instead of failing (rejected) — a FIFO read blocks bootstrap indefinitely, and moving a device/socket under a conforming `.json` quarantine name hands retention an object whose unlink semantics destroy non-file state; wrapping only the classification (rejected, C1) — drops the real fatal cause from the returned error and unmeets the ticket's diagnostics requirement; **accumulate-across-fatal families (rejected, CR13-04) — a fatal first family would leave the pass examining a second family after an unrecoverable state, widening the fatal window; stop-on-first-fatal is chosen instead**; **re-evaluating the eviction loop condition after a retention failure (rejected, C5/D10) — the ">4 pre-existing" condition remains true after a failed unlink, so a retrying loop is non-terminating and over-deletes or emits unbounded records; select-once/attempt-once/first-failure-ends-pass is chosen instead**.

## 8. RELEASE AND RECOVERY

- **Irreversible steps (explicit):** (1) the quarantine rename moves the **only copy** of the rejected bytes out of the configured path — recovery for manual inspection is `MCP_SNAPSHOT_QUARANTINE=off` + restart, or renaming the file back by hand; (2) retention deletes pre-existing quarantine files beyond the `QuarantineKeep−1` newest **of their own family** — deleted quarantined bytes are gone, and **the other family's conforming names are foreign and never pruned (R5/CR13-01)** — **a retention failure (listing or unlink) ends that family's pass with one warn record and explicitly leaves the family above `QuarantineKeep`: never a silent retry, a deletion retry, or a fatal (R5/D10, C5)**; (3) a crash between reservation and rename can leave one empty conforming-named file (inert; counted by a later retention pass; manually removable). **The irreversible-deletion contract of step (2) is flagged for the affected owner's confirmation before implementation (C5; §9.11).**
