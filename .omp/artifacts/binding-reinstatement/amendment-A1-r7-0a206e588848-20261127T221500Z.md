## 1. STATUS

**DRAFT r7.** Objective: a configured server whose durable binding is `retired:true` is a deliberate operator re-add — every committed admission (startup or reload) reinstates it with no retired-era residue through any admission the bridge controls, exactly one bounded warn record at commit, and a fail-closed durability path that keeps the tombstone as the recovery signal; tombstones for servers no longer configured keep current semantics.

## 2. REQUIREMENTS

**R9 (ticket 02 / #11; owner decision 2026-11-27; trust model narrowed by owner ruling at r6).** A server present in the current configuration whose retained durable binding is retired MUST be reinstated at admission: tombstone cleared, binding carries the **current configured endpoint fingerprint only**, server admitted **without any retired-era state** — no tools, embeddings, health success, or stale prompt rows of the retired era survive on this start or through any later admission **the bridge controls**. "Without any retired-era state" (r6/CR6-04 definition): on a STARTUP admission the server's catalog is empty (nothing restored) until its first successful probe; on a RELOAD admission the server carries ONLY current-era, freshly discovered tools (a successful discovery registers them and stamps the row fresh — it is not "unbound" in the catalog-empty sense). **Trust model (owner ruling): the prompt-file lifecycle is bridge-owned — no stale rows persist through any admission the bridge controls; a `prompts.json` externally reintroduced (hand-written, restored from backup, or injected) after a committed non-retired generation is OUTSIDE this trust model and carries no reinstatement evidence.** Exactly **one** bounded warn record naming the server is emitted **per committed admission**. **Durability: a reinstatement admission that cannot durably purge the prompt state FAILS CLOSED — any `LoadPrompts` error (beyond `ErrNoSnapshot`, which the loader absorbs), a nil prompt dependency, or a prompt-persist error fails the build before the snapshot persist, leaving the binding retired as the recovery signal; no committed generation can carry a non-retired binding while retired-era prompt rows remain loadable bridge-managed evidence.** Tombstones for unconfigured servers keep current semantics. Non-goals: no change to `Binding.Retired` JSON, `Snapshot.Validate`, `BindingAllowed`, the live endpoint-change rebind, or schema-1 decode; no cmd classifier change (the cause-mapping gap is an owner-gated follow-up, §3 ADR12); no new metric; no refresh-mode guard (dropped r6/F1 — structurally unreachable).

## 8. RELEASE AND RECOVERY

In-process behavior change; no schema/config/wire change; no migration. Deployment order: standard image rollout; on the first committed admission after upgrade, a configured retired binding reinstates (one warn) with ADR9-ordered durable writes; `prompts.json` is purged on the reinstatement path (both modes) or refreshed by the first reload/refresh. **Rollback (r7/CR6-07 — scoped):** reverting to the previous image is safe — the old binary reads and validates the post-reinstatement snapshot (format unchanged, binding non-retired) and starts WITHOUT crash-loop or rejection. **Catalog scope:** after a STARTUP reinstatement the old binary serves an EMPTY catalog for that server until its first probe (its rows were purged); after a RELOAD reinstatement with successful discovery, current-era tool rows persist and the old binary's `definitionsFromSnapshot` (`reload.go:805-817`) restores them — either way no retired-era rows exist to resurrect. The old binary's tombstone-rebind refusal only fires again if a NEW tombstone is created for a then-configured server. **Failure recovery (carried; safe-not-atomic):** the ADR9 sequence is not atomic — the prompt persist may succeed and `deps.Persist` (`:724`) then fail; that intermediate state (purged prompt file + retired binding) is SAFE and uncommitted: no generation is ever published from a failed build, and the supervisor's retry re-runs both persists idempotently. If the prompt persist fails, a prompt dependency is nil (ADR13), or `LoadPrompts` errors (ADR10), the process exits with the typed startup failure and the durable binding REMAINS retired — the tombstone is the recovery signal. Under `MCP_SNAPSHOT_QUARANTINE=off` a load error persists until the operator repairs/removes the file (fail-closed by design). Irreversible steps: none.
