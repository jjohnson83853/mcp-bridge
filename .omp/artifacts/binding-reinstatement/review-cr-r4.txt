[HIGH][contract/repair-closure] ADR10 contradicts R9's absolute prompt-durability clause; retired-era prompts can resurrect.
Anchor: spec R9 §2, ADR10, AC25(d); `internal/service/reload.go:537-549`; `internal/storage/store.go:84-93`; `cmd/mcp-bridge/wiring.go:580-590`; `serve.go:39-41,140-148`.
Confidence: HIGH (reachability MEDIUM).
Issue: ADR10 skips the durable prompt rewrite and COMMITS a non-retired binding on ANY LoadPrompts error. promptLoader maps only ErrNoSnapshot to (nil,nil), so a read/permission error leaves a valid `prompts.json` with retired-era rows. With `MCP_SNAPSHOT_QUARANTINE=off`, RecoverRejected is skipped; a later successful LoadPrompts serves those rows for the now configured, non-retired server, and the next reload re-persists them. R9 requires zero stale rows on every later start; rows carry no binding-era discriminator, so ADR10's "hand-repaired file cannot resurrect" is false. AC25(d) asserts only "no empty set persisted".
Fix: fail closed on any LoadPrompts error during reinstatement (loader already absorbs ErrNoSnapshot), or quarantine/remove the file before commit; extend AC25(d)/AC24 with a post-load second start asserting zero rows.
