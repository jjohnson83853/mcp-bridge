## 2. REQUIREMENTS

**R9 (ticket 02 / #11; owner decision 2026-11-27; trust model narrowed at r6; durability narrowed at r13 per owner decision r13).** A server present in the current configuration whose retained durable binding is retired MUST be reinstated at admission: tombstone cleared, binding carries the **current configured endpoint fingerprint only**, server admitted **without any retired-era state** — no tools, embeddings, health success, or stale prompt rows of the retired era survive on this start or through any later admission **the bridge controls**. "Without any retired-era state" (r6/CR6-04, r8/F2): STARTUP — empty catalog until the first successful probe; RELOAD — no retired-era rows, **zero prompt rows at commit** (the deliberate discard, ADR9(a)), current-era discovered tools stamped fresh, discarded prompt rows repopulated on the next refresh pass. **Durable side effect (r12/CR11-05): the first startup prompt write prunes `prompts.json` rows of every unconfigured/prompt-disabled server — consistent with the bridge-owned trust model.** **Trust model (r6 ruling): bridge-owned prompt-file lifecycle; an externally reintroduced `prompts.json` after a committed non-retired generation is outside the trust model.** Exactly **one** bounded warn record naming the server, **per reinstated server per committed admission** (r13/CR12-05 wording). **Durability (r13/C1 — SPLIT):**
- **(a) PRE-RENAME failure — input validation, a `LoadPrompts` error beyond `ErrNoSnapshot`, any nil prompt/snapshot dependency, or a prompt-persist error (the prompt persist precedes the snapshot write): the build FAILS CLOSED, the binding STAYS RETIRED — the tombstone is the recovery signal; no committed generation exists; a retry repeats the fail-closed path.**
- **(b) POST-RENAME/FSYNC failure — `deps.Persist` returning an error after `os.Rename` published the candidate (`store.go:301-306`) but with the directory fsync (`syncDirectory`, `:327-336`) unconfirmed: the admission is REJECTED and NO `binding_reinstated` record is emitted (emission is commit-point, after acceptance), BUT the published snapshot MAY already be the non-retired, prompt-purged candidate. **This is GENUINE DURABILITY UNCERTAINTY — not a diagnostic-only state.** Its survival across a crash is UNKNOWN. On restart: if the new snapshot survived, `Reconcile` admits it (no retired-era residue — the prompt purge preceded publication) and the admission proceeds from the committed state with no new warn; if it did not survive, the tombstone remains and the next start repeats the (a) fail-closed path.**

Tombstones for unconfigured servers keep current semantics. Non-goals: no change to `Binding.Retired` JSON, `Snapshot.Validate`, `BindingAllowed`, the live endpoint-change rebind, or schema-1 decode; no cmd classifier change (owner-gated follow-up, ADR12); no new metric; no envelope widening (r11/C4); no refresh-mode emission (defensive check reinstated r13/CR12-03); **no storage-protocol change (owner decision r13 — `store.go` is untouched; the narrowed guarantee is stated, not engineered)**.

- **PRE-RENAME failures (validation, prompt load/persist, nil dependency): the binding STAYS RETIRED; the previous binary hits the ORIGINAL refusal (`reconcile.go:80-81`) — the crash-loop RESUMES until the new binary retries successfully or the owner lane repairs the state. - **POST-RENAME/FSYNC failure (ADR15): the admission is rejected and nothing is published in-process, but the on-disk snapshot MAY already be the non-retired candidate — its crash survival is UNKNOWN. Rollback compatibility therefore DEPENDS ON THE SURVIVED BRANCH: if the new snapshot survived, the previous binary reads/validates it and starts without crash-loop (startup: empty catalog until first probe; reload with successful discovery: current-era rows restored via `definitionsFromSnapshot` `:805-817`); if it did not survive, the tombstone remains and rollback resumes the crash-loop.** The operator determines the branch by inspecting `snapshot.json`'s binding state.
