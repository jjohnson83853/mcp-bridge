## 2. REQUIREMENTS

**R9 (ticket 02 / #11; owner decision 2026-11-27; trust model narrowed by owner ruling at r6).** A server present in the current configuration whose retained durable binding is retired MUST be reinstated at admission: tombstone cleared, binding carries the **current configured endpoint fingerprint only**, server admitted **without any retired-era state** — no tools, embeddings, health success, or stale prompt rows of the retired era survive on this start or through any later admission **the bridge controls**. "Without any retired-era state" (r6/CR6-04, refined r8/F2): on a STARTUP admission the server's catalog is empty (nothing restored) until its first successful probe; on a RELOAD admission the server's committed state carries NO retired-era rows and **zero prompt rows at commit** (the reinstatement build's deliberate prompt discard, ADR9(a)); current-era tool registrations from a successful discovery are stamped fresh, and the discarded prompt rows repopulate on the next refresh pass. **Trust model (owner ruling): the prompt-file lifecycle is bridge-owned — no stale rows persist through any admission the bridge controls; a `prompts.json` externally reintroduced (hand-written, restored from backup, or injected) after a committed non-retired generation is OUTSIDE this trust model and carries no reinstatement evidence.** Exactly **one** bounded warn record naming the server is emitted **per committed admission**. **Durability: a reinstatement admission that cannot durably purge the prompt state or persist the snapshot FAILS CLOSED — any `LoadPrompts` error (beyond `ErrNoSnapshot`, which the loader absorbs), ANY nil prompt/snapshot dependency, or a prompt-persist error fails the build before the snapshot persist, leaving the binding retired as the recovery signal; no committed generation can carry a non-retired binding while retired-era prompt rows remain loadable bridge-managed evidence.** Tombstones for unconfigured servers keep current semantics. Non-goals: no change to `Binding.Retired` JSON, `Snapshot.Validate`, `BindingAllowed`, the live endpoint-change rebind, or schema-1 decode; no cmd classifier change (the cause-mapping gap is an owner-gated follow-up, §3 ADR12); no new metric; no envelope widening (r11/C4 — the §7 exception is documented, not implemented); no refresh-mode guard (dropped r6/F1 — structurally unreachable).
