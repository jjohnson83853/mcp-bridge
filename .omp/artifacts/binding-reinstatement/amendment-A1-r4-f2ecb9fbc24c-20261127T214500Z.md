## 1. STATUS

**DRAFT r4.** Objective: a configured server whose durable binding is `retired:true` is a deliberate operator re-add — every committed admission (startup or reload) reinstates it unbound with no cache/prompt/health residue on this or any later start, exactly one bounded warn record at commit, and a fail-closed durability path that keeps the tombstone as the recovery signal; tombstones for servers no longer configured keep current semantics.

## 2. REQUIREMENTS

**R9 (ticket 02 / #11; owner decision 2026-11-27).** A server present in the current configuration whose retained durable binding is retired MUST be reinstated at admission: tombstone cleared, binding carries the **current configured endpoint fingerprint only**, server admitted **unbound** — no tools, embeddings, health success, or stale prompt rows of the retired era survive, on this start and on every later start — and exactly **one** bounded warn record naming the server is emitted **per committed admission**. **Durability (r3/H2, generalized r4/H2 to both modes): on ANY admission that reinstates, the purged prompt state is persisted BEFORE the snapshot persist and either persist failing fails the build — the durable binding stays retired, which is the recovery signal; no committed generation can carry a non-retired binding while retired-era prompt rows remain the persisted evidence for that server.** Tombstones for unconfigured servers keep current semantics. Non-goals: no change to `Binding.Retired` JSON, `Snapshot.Validate`, `BindingAllowed`, the live endpoint-change rebind, or schema-1 decode; no cmd classifier change; no new metric.
