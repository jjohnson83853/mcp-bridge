## 2. REQUIREMENTS

**R9 (ticket 02 / #11; owner decision 2026-11-27; trust model narrowed by owner ruling at r6; r12 disclosure added).** A server present in the current configuration whose retained durable binding is retired MUST be reinstated at admission: tombstone cleared, binding carries the **current configured endpoint fingerprint only**, server admitted **without any retired-era state** — no tools, embeddings, health success, or stale prompt rows of the retired era survive on this start or through any later admission **the bridge controls**. "Without any retired-era state" (r6/CR6-04, refined r8/F2): on a STARTUP admission the server's catalog is empty (nothing restored) until its first successful probe; on a RELOAD admission the server's committed state carries NO retired-era rows and **zero prompt rows at commit** (the reinstatement build's deliberate prompt discard, ADR9(a)); current-era tool registrations from a successful discovery are stamped fresh, and the discarded prompt rows repopulate on the next refresh pass. **Durable side effect (r12/CR11-05, disclosed): the reinstatement path's prompt persist writes the `promptsForServers`-filtered set (:553), so the FIRST startup prompt write also prunes `prompts.json` rows of every unconfigured or prompt-disabled server — consistent with the bridge-owned trust model (rows outside the configured, prompt-enabled set are not served state) and disclosed in AC24/§8.** **Trust model (owner ruling): the prompt-file lifecycle is bridge-owned — no stale rows persist through any admission the bridge controls; a `prompts.json` externally reintroduced after a committed non-retired generation is OUTSIDE this trust model.** Exactly **one** bounded warn record naming the server is emitted **per committed admission**. **Durability: a reinstatement admission that cannot durably purge the prompt state or persist the snapshot FAILS CLOSED — any `LoadPrompts` error (beyond `ErrNoSnapshot`), ANY nil prompt/snapshot dependency, or a prompt-persist error fails the build before the snapshot persist, leaving the binding retired as the recovery signal.** Tombstones for unconfigured servers keep current semantics. Non-goals: no change to `Binding.Retired` JSON, `Snapshot.Validate`, `BindingAllowed`, the live endpoint-change rebind, or schema-1 decode; no cmd classifier change (owner-gated follow-up, §3 ADR12); no new metric; no envelope widening (r11/C4); no refresh-mode guard (r6/F1).
