## 8. RELEASE AND RECOVERY

In-process behavior change; no schema/config/wire change; no migration. Deployment order: standard image rollout; on the first committed admission after upgrade, a configured retired binding reinstates (one warn) with the ADR9-ordered durable writes; `prompts.json` is purged on the reinstatement startup path or refreshed by the first reload/refresh. **Rollback (carried from r2, per CR-R1-05):** reverting to the previous image is safe — the old binary reads and validates the post-reinstatement snapshot (format unchanged, binding non-retired, `StatusNone` row) and starts serving with an empty catalog for that server (its first probe/refresh repopulates); it does NOT crash-loop or reject.
