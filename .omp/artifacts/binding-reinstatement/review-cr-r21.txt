### Issues

**[HIGH] CR21-01 — guard mechanism contradicts the owner decision, ADR18, AC25(h) and §9.**
`spec.md` Q2 says the guard is the emission condition `in.deps.Logger != nil && in.mode != buildRefresh` added at the post-commit emission loop (`reload.go:802-813`, after `published = true` `:799`). ADR18/AC25(h)/§9 instead require a pre-commit build error (`service: refresh reinstatement invariant violated…`) with "generation UNCHANGED" and placement "before any purge/persist work". These are mutually exclusive: Q2 cannot fail a build and leaves a committed refresh reinstatement with zero records (contradicting R9's one-record-per-committed-admission). `owner-decision-r21.json` authorizes only "restoring the `in.mode != buildRefresh` **emission** guard plus the refresh no-emission regression test" — the build-error form is not granted. **Fix:** adopt the emission guard as the sole normative design, delete ADR18's build-error semantics, and restate R9/AC25(h) as "zero `binding_reinstated` records; a reachable refresh pass is still rejected by the existing client-adoption check (`reload.go:611-614`)"; or obtain a new owner decision for the build-error guard.

**[MEDIUM] CR21-02 — AC25(h)/ADR18's oracle cannot fail on current code.**
`durable_test.go` (new `TestRefreshNeverEmitsReinstatement`) is declared "green-on-arrival": on HEAD the refresh already fails at `reload.go:611-614` (new client), zero records, generation unchanged. It therefore stays green if the guard is never added and cannot "pin the guard's earlier classified failure" (that requires asserting the guard's error string, which would make it RED — contradicting the green-on-arrival label). **Fix:** state the test's real oracle (no emission, rejection observed) and drop the guard-attribution, or assert the guard message and reclassify as RED.

**[MEDIUM] CR21-03 — reload-leg prompt purge is unverified.**
AC25(e1) uses `TestReloadReinstatesDroppedThenReaddedServer`: the drop's prompt persist *succeeds* and `promptsForServers` (`reload.go:580`) already filtered alpha, so no retired-era prompt rows ever exist at the re-add. The `:711-713` purge and the durable-before-snapshot persist (`:753-770`) are thus not exercised for reload, leaving R9's "reload: zero prompt rows at commit" without a discriminating oracle (startup is covered by `:572`). **Fix:** make the drop's `PersistPrompts` fail so the else-branch (`:783-785`) restores `previous.Prompts()` containing alpha — or seed alpha rows into the published generation — then assert the persisted `PromptSnapshot` has no alpha rows.
