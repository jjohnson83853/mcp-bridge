## 1. STATUS

**DRAFT r2.** Objective: a configured server whose durable binding is `retired:true` is a deliberate operator re-add — every committed admission (startup or reload) reinstates it unbound with no cache/prompt/health residue and exactly one bounded warn record, instead of crash-looping on `ErrRebindTombstoned`; tombstones for servers no longer configured keep current semantics.

## 2. REQUIREMENTS

**R9 (ticket 02 / #11; owner decision 2026-11-27, semantics unchanged from r1).** A server present in the current configuration whose retained durable binding is retired MUST be reinstated at admission: tombstone cleared, binding carries the **current configured endpoint fingerprint only**, server admitted **unbound** — no tools, embeddings, health success, or prompt rows of the retired era survive, on this start **and on every later start until fresh evidence exists** — and exactly **one** bounded warn record naming the server is emitted **per committed admission** (after the snapshot is persisted and the runtime generation accepted). Tombstones for unconfigured servers keep current semantics. Non-goals: no change to `Binding.Retired` JSON, `Snapshot.Validate`, `BindingAllowed`, the live endpoint-change rebind, or schema-1 decode; no cmd classifier change; no new metric.

## 4. DESIGN

**Q1 — where the reinstatement lives.** Rewrite the branch at `internal/storage/reconcile.go:80-81` to mirror the tombstone-creation arm's purge pattern (`:93-99`): `purged[binding.ServerID] = true` and append `Binding{ServerID, EndpointFingerprint: server.EndpointFingerprint}` (non-retired). No pre-admission normalization: the durable transform stays in the one pure function; `Reconcile`'s signature, purity, and previous-snapshot immutability are unchanged. `:82-91` (endpoint-change rebind; both retention arms) untouched.

**Q2 — the warn seam.** In `build`, hoist `base := in.reconcileBase(previous)` before the `:674` call; after the `:680-682` error check compute `reinstated := reinstatedServers(base, snapshot, configured)`. At the commit point (AD-R7: after `:749`), for each reinstated id in sorted order, if `in.deps.Logger != nil`, emit exactly one `observe.Entry{Level: "warn", Event: "binding_reinstated", Operation: modeOperation(in.mode) (AD-R8: "startup"|"reload"), Outcome: "degraded", Server: id}` — no `Fields`, no `Error`, no endpoint; the server id is the only payload (pattern-validated by `safeServer`). Written through the mutex-serialized `Logger.write` (`log.go:176-179`).

**Q3 — purge proof (no stale state survives, durably).** With `purged[id]` set by the rewritten branch — (i) health row reset to `StatusNone` + current fingerprint (`reconcile.go:119`, rows block `:111-127`), then stamped empty by the outcomes loop (`StampServerEmpty`, snapshot.go:225-237); (ii) tool rows dropped (`:129-139`); (iii) embeddings dropped transitively (`:140-149`); (iv) `definitionsFromSnapshot` restores nothing (tools absent; independent retired/mismatch guard `reload.go:817`) ⇒ admitted unbound with a fresh dedicated client (`reload.go:584-597`); (v) stale prompt rows dropped by the AD-R6 keyed purge in every build and made durable on the reinstatement path; (vi) query cache is in-memory per generation (`internal/config/command.go:55-56`; snapshot.go:102 comment) — empty at cold start; (vii) a stale health row is impossible in any valid snapshot (`snapshot.go:313-315`) and an invalid durable snapshot never reaches `Reconcile` (`loop.go:140-146`). AC24's tests assert (i)–(v) on the returned snapshot/assembly **and across a second start**.

**Q4 — fingerprint.** The reinstated binding carries ONLY the current configured fingerprint (`server.EndpointFingerprint` from `input.Servers`); the retired fingerprint is discarded; `BindingAllowed(id, currentFp)` true, `BindingAllowed(id, oldFp)` false. The branch is unconditional on fingerprint equality (a same-endpoint re-add clears + purges — a no-op purge, one warn).

**Q5 — interactions.** Live endpoint-change rebind (`:82-87`) unchanged; `Snapshot.Validate` unchanged (a reconciled snapshot satisfies it); schema-1 reinstates identically post-decode (`snapshot_v1.go:34` carries `retired`; AC26 names the assertions); unconfigured tombstones keep `:90-91` retention and `BindingAllowed` false. **Reload reachability (CR-R1-03):** a drop→re-add via SIGHUP reaches the branch with base = the published tombstoned snapshot (`reconcileBase` `:791-803`), builds a fresh client (`:584-597`), discovers fresh tools/prompts, and emits the warn with operation `reload` — pinned and tested; only refresh is structurally unreachable.

**Q6 — nothing else becomes lenient.** Exactly one switch case changes. Corrupt snapshots still fail closed (`previous.Validate`, `:47-51`); admission failures still reject (`loop.go:157-160`); unconfigured tombstones never reinstate. Concurrency: reinstatement reads are on immutable snapshots; the warn is emitted inside the `commitMu`-serialized commit section through the Logger's own lock; `-race` fixtures cover the reload/refresh interleaving.

**Event/contract wiring (CR-R1-07).** `eventMessage` gains `case "binding_reinstated": return "retired server binding reinstated by configuration"` (identical string pinned in `logging_contract_test.go`'s `eventMessages` map; `eventOperations` pins `"binding_reinstated": "startup"`; both maps extended, **count pin 36 → 37 at `:777-778`**). The reload-mode operation variant is pinned by AC25's reload fixture and the docs row. `docs/logging-contract.md`: one event/operation pins row (`binding_reinstated | startup` / `reload` variant) and one classification row stating level `warn`, outcome `degraded`, **no `error` object** (static message only — explicitly not an AD13-style `error.code`/`error.kind` row).

## 8. RELEASE AND RECOVERY

In-process behavior change; no schema/config/wire change; no migration. Deployment order: standard image rollout; on the first committed admission after upgrade, a configured retired binding reinstates (one warn) and the reconciled snapshot persists non-retired with purged rows; `prompts.json` is rewritten on the reinstatement path (startup, AD-R6) or the next reload/refresh. **Rollback (corrected per CR-R1-05):** reverting to the previous image is safe — the old binary reads and validates the post-reinstatement snapshot (format unchanged, binding non-retired, `StatusNone` row) and **starts serving with an empty catalog for that server** (its first probe/refresh repopulates); it does NOT crash-loop or reject.
