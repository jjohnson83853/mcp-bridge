1. STATUS
Spec ID SNAPREC-SPEC-r4, revision 4, DRAFT. Objective: a snapshot the store refuses is recoverable startup state — quarantine its bytes once before admission, continue startup, and report the act in one typed warning — without weakening ensureReplaceable no-overwrite protection (internal/storage/store.go:295-305, internal/storage/store.go:124).

2. REQUIREMENTS
- R1 Single recovery locus: a new Store recovery method executes once per process, after storage.Open acquires the writer lock and before startup admission (Loop.Start). It never runs in Reload, mid-run saves, or ensureReplaceable; ensureReplaceable is unchanged.
- R2 Quarantinable class: any Load/LoadPrompts ErrCorrupt rejection (decode/envelope, trailing data, checksum mismatch, unsupported schema, failed Validate) and any read failure of a REGULAR file at the snapshot path are quarantinable: one atomic same-directory rename of the original file to a timestamped quarantine name before any fresh snapshot is published. Bytes are preserved exactly; no delete, truncate, or overwrite-first.
- R3 Fatal class: a non-regular file at a snapshot path (directory, device, socket — a directory cannot follow the rename rule), quarantine rename failure, and post-rename directory-sync failure are fatal: startup exits failure with code state_directory, kind resource, remediation and resource.path per the existing stateDirectoryFailure record (cmd/mcp-bridge/startup_failure.go:26-33); the underlying error text is logged, never collapsed to internal_error. When no rename occurred, the file is untouched.
- R4 Typed warning: for each quarantined file exactly one structured record, event startup_snapshot_rejected, operation startup, level warn, outcome degraded, error.code snapshot_unavailable (closed AD13 mapping, docs/logging-contract.md AD13), error.kind resource, error.retryable true, existing static remediation and message, resource.path = quarantined file path, plus optional event-specific field failure_reason with the finite value corrupt_json | checksum_mismatch | unsupported_schema | validation_failure | read_error (added under the documented optional event-specific addition rule; schema_version stays 1). No startup_failed or internal_error record is emitted for a quarantinable condition.
- R5 Retention bound: at most 5 quarantine files per family (snapshot.corrupt-*.json, prompts.corrupt-*.json); after each successful rename, the oldest beyond the bound is pruned; prune failure is non-fatal and reported once via existing internal_warning vocabulary (warn/failure, internal_error — AD13).
- R6 No-op on valid or absent snapshots: when Load/LoadPrompts succeeds or reports ErrNoSnapshot, recovery mutates nothing — no rename, no warning, no retention pass; a successfully loaded snapshot keeps its trusted state and the existing no-overwrite protection is untouched.
- R7 Prompt-snapshot coverage: prompts.json receives identical quarantine behavior with prompts.corrupt-*.json names and the same retention bound.
- R8 Operator opt-out: environment variable MCP_SNAPSHOT_QUARANTINE=off disables recovery (fail-closed): no rename, no warning, and today's wedge semantics verbatim (degraded start, fatal persist, startup_failed/internal_error, exit 1). Any other value, including unset, enables recovery. [OWNER-CONFIRMED 2026-11-21] default = enabled.
- R9 Machine-readable reasons: Load/LoadPrompts rejections gain errors.Is-compatible reason sentinels chained under ErrCorrupt, so every existing errors.Is(err, ErrCorrupt) caller and test is unaffected.

Non-goals: no new metric names or series and no reloadReasons/reloadOutcomes extension; no stale temp-file (.snapshot.json.N.tmp) cleanup; no general redesign of startupFailureForError beyond R3's fatal recovery path (opt-out mode intentionally keeps today's internal_error wedge); no recovery during Reload or mid-run saves; no operator tooling for quarantine files; no Windows rename-semantics work; no changelog file (none exists; docs/logging-contract.md is the operational doc updated).

4. DESIGN
New file internal/storage/recovery.go. New sentinels in internal/storage/store.go, chained under ErrCorrupt so errors.Is(err, ErrCorrupt) is preserved for all callers: ErrSnapshotDecode = fmt.Errorf("%w: decode", ErrCorrupt), ErrSnapshotChecksum, ErrSnapshotSchema, ErrSnapshotValidate (same for prompt variants where applicable); Load/LoadPrompts wrap their rejections with the matching sentinel instead of bare ErrCorrupt. New Store method:
  func (s *Store) RecoverRejected(now func() time.Time) ([]Recovery, error)
type Recovery struct { Original, QuarantinePath, Reason string } with Reason ∈ the five finite values; package constants QuarantineKeep = 5 and quarantine name prefixes. Contract per file (snapshot.json then prompts.json), executed while the Store's writer flock is held, once per process:
1) Lstat(path): ErrNotExist → skip. Mode is not regular → return fatal error wrapping new sentinel ErrSnapshotUnrecoverable with the path (R3).
2) Load()/LoadPrompts(): nil → skip (trusted set, R6 preserved); ErrNoSnapshot → skip; ErrCorrupt → reason from sentinel (decode→corrupt_json, checksum→checksum_mismatch, unsupported schema→unsupported_schema, validate→validation_failure); any other error → read_error (regular file already proven by step 1).
3) Rename os.Rename(path, quarantine) atomically in the same directory; failure or subsequent syncDirectory failure → fatal error (R3); on success syncDirectory and record the Recovery.
4) Retention: list the family prefix, sort newest-first, unlink beyond QuarantineKeep; unlink failure → returned as a non-fatal per-family prune warning (R5), never fails startup.
Order: catalog first, then prompts; a fatal on one file stops before any further mutation. If recovery is disabled (R8) the method is not called and Store behaves exactly as HEAD. After a successful quarantine, trusted remains false; the admission persist then sees ErrNoSnapshot in ensureReplaceable and publishes normally — the wedge at internal/service/reload.go:721-725 disappears.
cmd wiring (cmd/mcp-bridge/serve.go runServe, between the Open error check at :100-102 and NewLoop at :213): unless MCP_SNAPSHOT_QUARANTINE=off, call store.RecoverRejected(time.Now); on fatal error return stateDirectoryFailure(store.Dir()) after logging the underlying cause on stderr; for each Recovery emit one structured warn record per R4 via observe.NewEnvelope + observe.WriteJSONLine (same mechanism as writeStartupFailure, cmd/mcp-bridge/startup_failure.go:118-133) with the fixed AD13 error object and Resource{Path: recovery.QuarantinePath}. Prune warnings use the existing internal_warning warn/failure/internal_error record. docs/logging-contract.md gains one optional event-specific addition row (startup_snapshot_rejected: failure_reason, finite five-value vocabulary) and the AD13 note that resource.path may carry the quarantined path; no field is removed, renamed, or retyped; schema_version stays 1.
Compatibility: W09E walk — Lifecycle: sole writer is the flock-holding process; recovery is a one-shot pre-admission transition rejected-file→quarantine; restart after quarantine loads a valid or absent file (idempotent). Shared state: no read-modify-commit across processes; rename is atomic within the locked directory; competing-operation schedule (quarantine then admission persist then second-restart Load) traced in §5 schedules. Contract: every R maps to ≥1 AC (R1→AC2-1, R2→AC2-1/AC1-4, R3→AC2-4/AC2-5, R4→AC2-2, R5→AC2-3/AC1-3, R6→AC1-1, R7→AC1-4, R8→AC2-6, R9→AC1-2); oracles distinct. Authority: no owner stop touched; R8 default is OWNER-CONFIRMED (§2, §3 Q4). Repair closure: ticket's required-behavior bullets map 1:1 to R1-R8.

8. RELEASE AND RECOVERY
Deployment: single-binary rollout, no migration; recovery activates on first restart with a rejected snapshot. Rollback: revert the commit; quarantined files are additive and never read by older code. Partial-failure recovery: if the process still fails after quarantine, the operator inspects the quarantine path named in resource.path and deletes/moves it manually — the incident's lost-bytes failure mode cannot recur for quarantinable classes. Irreversible step: retention prune permanently deletes quarantine files beyond the 5 newest per family (documented consequence; R8 off retains files indefinitely but wedges startup, the pre-change tradeoff). No data migration, no schema change (snapshot schema_version untouched).
