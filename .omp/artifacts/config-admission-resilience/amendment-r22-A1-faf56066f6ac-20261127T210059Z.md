# Amendment r21-A1 — feature `config-admission-resilience`, ticket 02 (#11), remedy A

## 1. STATUS

Amendment ID `config-admission-resilience/A1`, candidate revision r22 (delta against r21). State: **DRAFT — planning only**. Objective: a configured server whose durable binding is `retired:true` is a deliberate operator re-add — startup admission reinstates it unbound (no restored cache) with exactly one bounded warn record, instead of crash-looping on `ErrRebindTombstoned`; unconfigured tombstones keep current semantics.

## 2. REQUIREMENTS

**R9 (NEW, ticket 02 / #11, owner decision 2026-11-27).** On startup admission (and reload reconciliation), a server that is **present in the current configuration** and whose retained durable binding is retired MUST be reinstated: the tombstone is cleared, the binding adopts the **current configured endpoint fingerprint only**, the server is admitted **unbound** — no tools, embeddings, health success, or prompt rows of the retired era survive — and exactly **one** bounded warn record naming the server is emitted per admission. **Tombstones for servers no longer configured keep their current semantics** (retained, never rebound, `BindingAllowed` false). Non-goals: no change to `Binding.Retired` JSON, `Snapshot.Validate`, `BindingAllowed`, `ErrEndpointChanged` rebind, or schema-1 decode; no cmd classifier change (the T1/T3 diagnostic work is separate); no new metric.

`[AUTO-DECISION]` entries (for the coordinator's decisions ledger):
- **AD-R1 — dedicated event `binding_reinstated`, not `internal_warning`.** Rationale: the contract pins `internal_warning` to operation `reload` and defines it as a defect signal (logging-contract.md:549,:562); a deliberate reinstatement is neither. Consequence: one `eventMessage` case, one contract row, one required-string assertion — all in the widened set.
- **AD-R2 — reinstatement set computed in `service.build` by diffing `reconcileBase` vs the reconciled snapshot; `Reconcile`'s signature unchanged.** Rationale: keeps `Reconcile` pure and return-stable (all callers/tests intact); the diff (`previous binding retired` ∧ `next binding non-retired` ∧ `configured`) is exactly the rewritten branch's precondition, computed from exported fields. Consequence: no storage API change; a pure `reinstatedServers(base, next, configured) []string` helper is unit-testable.
- **AD-R3 — remove the now-unreachable `ErrRebindTombstoned` sentinel (reconcile.go:13) and its test references.** Rationale: clean cutover; verified no other reference. Consequence: historical checkpoint doc untouched; any future tombstone-rebind refusal would be a new owner decision.
- **AD-R4 — stale prompt rows are dropped in-memory at startup; `prompts.json` is not rewritten at startup.** Rationale: `PersistPrompts` is refresh-only (reload.go:728); after reinstatement the first successful refresh rewrite drops the rows durably. Consequence: a crash before the first refresh leaves the stale file on disk, but every subsequent startup re-drops the rows in memory (idempotent).
- **AD-R5 — the branch clears + purges unconditionally on fingerprint equality too** (operator re-adds the same endpoint): a no-op purge, one warn — simpler and stateless.

## 4. DESIGN

**Answer 1 — where:** rewrite the branch at `internal/storage/reconcile.go:80-81` to mirror the departure-purge path:
`case stillConfigured && binding.Retired:` → `purged[binding.ServerID] = true` and append `Binding{ServerID, EndpointFingerprint: server.EndpointFingerprint}` (non-retired). No pre-admission normalization step: the durable transform stays in the one pure function; `Reconcile`'s signature, purity, and previous-snapshot immutability are unchanged. `reconcile.go:88-99` (endpoint-change rebind; unconfigured tombstone retention) are untouched.

**Answer 2 — warn seam:** in `service.build` (`internal/service/reload.go`), hoist `base := in.reconcileBase(previous)` (currently inlined at :674), pass it to `Reconcile`, then after the `:680-682` error check compute `reinstated := reinstatedServers(base, snapshot, configured)` (new pure helper, same file). For each reinstated id, in order: (a) `next.prompts = replaceServerPrompts(next.prompts, id, nil)` (existing helper, :784-798 — order-preserving, so the sorted slice stays sorted); (b) if `in.deps.Logger != nil`, exactly one `observe.Entry{Level: "warn", Event: "binding_reinstated", Operation: "startup", Outcome: "degraded", Server: id}` — the mutex-serialized Entry lane (`log.go:121-124`); no `Fields`, no error text, no endpoint (secret-safe by construction: server id is the only payload, pattern-validated by `safeServer`). Refresh passes cannot hit the branch (published snapshots never hold retired bindings for configured servers), so the warn can never fire on a refresh; admission is serialized before the drivers start (`loop.go:172→180/195`).

**Answer 3 — purge proof (no stale state survives):** with `purged[id]` set by the rewritten branch — (i) health row reset to `StatusNone` + current fingerprint (reconcile.go:117-119) and then stamped `notProbed`/empty by the existing outcomes loop (reload.go:688-692, `restored=false`); (ii) tool rows dropped (:131-138); (iii) embeddings dropped via `keptIdentities` (:140-147); (iv) `definitionsFromSnapshot` restores nothing (tools absent; independent retired-binding guard at reload.go:813) ⇒ admitted unbound with a fresh dedicated client (reload.go:601-611); (v) stale prompt rows dropped in-memory (AD-R4); (vi) query cache is in-memory, empty at cold start; (vii) a stale health row is impossible: `Validate` rejects retired-binding+live-row (snapshot.go:313-315) and an invalid durable snapshot never reaches `Reconcile` (loop.go:140-146). AC24's test asserts (i)–(v) directly on the returned snapshot and assembly.

**Answer 4 — fingerprint:** the reinstated binding carries ONLY the current configured fingerprint (`server.EndpointFingerprint` from `input.Servers`); the retired fingerprint is discarded; `BindingAllowed(id, oldFingerprint)` is therefore false afterwards. The branch is unconditional on fingerprint equality (AD-R5).

**Answer 5 — interactions:** `ErrEndpointChanged`/live rebind (`reconcile.go:88-93`) unchanged; `Snapshot.Validate` unchanged (a *reconciled* snapshot satisfies it: non-retired binding + live row + matching fingerprints); schema-1 snapshots reinstate identically post-decode (test uses a `SchemaVersion: 1` fixture through `Validate`, which accepts `schemaVersionLegacy`).

**Answer 6 — nothing else becomes lenient:** exactly one switch case changes. Unconfigured retired bindings keep `reconcile.go:95-99` retention + `BindingAllowed` false (AC23); corrupt snapshots still fail closed (`previous.Validate`, reconcile.go:47-51); admission failures still reject (`loop.go:157-160`). Concurrency: all reinstatement reads are on immutable snapshots; the single warn write is mutex-serialized; `-race` fixtures cover the reload/refresh interleaving.

## 8. RELEASE AND RECOVERY

In-process behavior change; no schema/config/wire change; no migration. Deployment order: standard image rollout; on first start after upgrade, a configured retired binding reinstates (one warn) and the reconciled snapshot persists non-retired. Rollback: revert + redeploy the previous image — the previous binary then crash-loops again on the same state (pre-existing behavior, `startup_failed`); the durable snapshot written by the new binary is fully valid for the old binary to read and reject identically (no format change). Irreversible steps: none.
