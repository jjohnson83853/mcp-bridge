## 4. DESIGN

### 4.1 Selected representation and effective-value consumers (C1)

Use the native YAML node kind to distinguish literal strings from a strict env-only mapping. Preserve the raw public embedding map. Add a small **private per-Config load snapshot** for the two effective strings plus an initialized marker, populated only after resolution/validation succeeds. No package-global env cache, recursive walker, lazy getter lookup or second document parse. Create the snapshot once and treat it as immutable.

`Parse` (`config.go:79`) performs: existing document/shape checks → env shape/name checks for these two keys → `LookupEnv` with separate unset/empty failures → effective field validation → publish the completed Config. Move/split the embedding `base_url` branch of the existing URL-validation pass (`:246-270`) so it consumes the effective string; retain current ordering for unrelated fields and existing `api_key` resolution. A raw reference must not trigger the old scalar or URL error before resolution.

`Command`/`readSetting` (`command.go:143-208`) reads the private snapshot **only for `embedding.model` and `embedding.base_url`** on parsed Configs; all other settings remain unchanged. Existing directly constructed Configs with literal strings retain their current typed-read behavior. A directly constructed Config containing an unresolved map must return an attributed setting/type error, never look up environment lazily. Thus Config loading owns resolution; later calls on the same Config cannot observe env mutation.

Keep `Fingerprint`/`publicProjection` (`fingerprint.go:23-64`) on the raw map. Typed `settings.Embedding` feeds existing `newEmbeddingProvider`/identity construction (`wiring.go:282,296-298`, `serve.go:80-90`), and the existing digest includes both resolved model and resolved base URL (`search.go:201-204`). Audit these named consumers and migrate any affected reads during approved implementation; do not add a second source of truth or exported fallback API.

### 4.2 Runtime, restart and snapshot compatibility (C1, C2)

- A successfully loaded Config captures effective strings once. The public fingerprint depends on the raw reference identity; value-only rotation leaves it unchanged. Literal-to-reference conversion or reference-name changes may change it, as expected.
- Startup model/provider, embed closure and model digest are captured in `serve.go`. Preserve the existing candidate-versus-startup typed-settings guard: a candidate whose effective embedding settings differ emits `restart_required`, is not published/persisted, and leaves live assembly, provider, model/digest and vectors unchanged. Do not silently reuse startup settings while accepting a changed candidate, nor live-swap the provider.
- SIGHUP rereads the mounted document and resolves against the **existing process** environment. It cannot refresh that environment from a changed host `.env` or Compose file. In-process tests may change process env to prove the guard; that test mechanism is not a Docker operational instruction.
- After **container recreation** with changed environment, startup uses new resolved settings and a new digest. Existing snapshot matching must reject/rebuild stale embedding vectors before admitting them for search. Test changed model and changed base URL separately, including unchanged raw fingerprint. Matching settings/digest retain existing valid reuse behavior.
- Snapshot schema and fingerprint format remain 1: existing envelopes/keys are unchanged, and public projection still represents raw embedding settings. Old literal-config snapshots remain readable; digest/fingerprint mismatch follows existing rebuild semantics, not corruption or a migration shim.

### 4.3 Byte fidelity and independent field validation (C3, C4)

Read env with `LookupEnv`; distinguish `present=false` from `present=true && value==""`. Do not use secret-file newline handling, `TrimSpace`, `TrimSuffix`, YAML reparse or interpolation on either env value. Effective settings contain the exact returned bytes when accepted.

- **Model:** existing nonempty-string semantics; spaces, quotes, colons, `#`, `$`, `${...}`, braces, embedded/trailing LF and whitespace-only nonempty strings are not transformed or classified as missing/empty. Any downstream provider rejection retains existing handling; this increment adds no model naming policy.
- **Base URL:** require an absolute HTTP(S) URL using the existing URL-validation contract, applied to the effective string. Reject ASCII whitespace/control characters, including spaces, tabs, CR and LF, as `url_invalid` rather than trimming them into a different URL. Validate without rewriting the stored env string; any existing client-specific URL normalization remains at its existing consumer seam. Literal URL behavior remains unchanged. Tests distinguish URL-format rejection from unresolved-reference diagnostics.

### 4.4 Syntax/operator comparison (C6)

| Alternative | Quoting and operational behavior | Decision |
|---|---|---|
| Native `model: {env: EMBEDDING_MODEL}` / `base_url: {env: EMBEDDING_BASE_URL}` | YAML mapping is unquoted; env content is not YAML and needs no YAML quote escaping. Typed, field-local validation and diagnostic attribution. | **Recommended and selected**, consistent with existing refs. |
| Document `${NAME}` interpolation | YAML sees a literal string unless a new interpolator is added; text expansion complicates typing/escaping and whole-document leakage. | Not implemented. Compose may independently interpolate its own file. |
| Custom `!env NAME` tag | Requires new tag/decoder semantics and differs from existing reference syntax. | Not implemented. |
| Preprocess/template mounted YAML | External step must escape/serialize values correctly and manage generated sensitive documents. | Not the supported native solution; no new preprocessing dependency. |
| Autoquote apparent values | Heuristic rewriting cannot safely infer YAML intent and does not itself resolve process env. | Not implemented. |
| Literal YAML string | `model: example-model` and a legal plain URL need no quotes; quote only when YAML syntax requires it. | Existing literal behavior retained. `"{env: NAME}"` is always literal; for base_url it fails ordinary URL validation, not env lookup. |

Compose example for documentation (not a Compose-file change): pass `EMBEDDING_MODEL: ${EMBEDDING_MODEL:?set it in ./.env}` and `EMBEDDING_BASE_URL: ${EMBEDDING_BASE_URL:?set it in ./.env}` under the service's `environment:`; mounted YAML uses the native maps. Host `.env` alone does not populate arbitrary container env or document values. `:?` rejects unset/empty only. Apply changed Compose env by recreating the service container with the existing deployment procedure (for example `docker compose up -d --force-recreate <service>`); neither SIGHUP nor restarting the old container imports it. No Docker operation is authorized by this plan.

## 5. FAILURE HANDLING AND DIAGNOSTICS

Reuse attributed `Diagnostic` fields (`Path`, `Key`, `Server` where applicable, `Code`, `Property`, `Shape`, `Reason`) and existing safe reference-identity rendering. No new diagnostic transport. `Key` is the affected embedding key; document path is attributed as today. Safe env names may appear as reference identity; malformed/unsafe names must not.

| Condition | Code | Property | Shape | Static, value-free reason |
|---|---|---|---|---|
| Extra/other keys, `file:`, nested collections or nonstring ref value | `reference_shape` | `reference` | `mapping` / `string` (actual safe node category) | embedding value must be a literal string or an env reference |
| Invalid/empty/whitespace env name | `reference_env_name` | `name` | `invalid_identifier` | invalid environment variable name (name withheld) |
| Name containing interpolation/command syntax | `reference_literal_required` | `reference` | `literal` | environment references cannot contain interpolation or commands |
| Variable absent (`LookupEnv` false) | `reference_unresolved` | `reference` | `missing` | environment variable is not set |
| Variable present with exactly zero bytes | `reference_unresolved` | `reference` | `empty` | environment variable is empty |
| Effective base URL invalid, including whitespace/CR/LF | `url_invalid` | `absolute_http_url` | `invalid_url` | invalid absolute HTTP(S) URL |
| Valid candidate effective settings differ from captured startup settings | Existing `restart_required` vocabulary | Existing restart-only metadata | Existing restart-only metadata | Existing static restart-required reason; no values |

Unset and empty share a code but differ in static Shape and Reason, satisfying R-38 without value/length disclosures. Expression-name detection precedes generic invalid-name classification. Shape errors precede lookup. Resolution errors precede URL validation; do not emit a misleading URL error for unset/empty. Preserve existing aggregation/no-partial-admission behavior.

Never include raw YAML, rejected URL/value, preview, digest/hash, value length/offset or unsafe env name in errors, Config formatting, CLI output or reload logs. Do not log successful resolutions. Tests cover sentinel values and their JSON-escaped renderings; existing values-only/error-format regressions remain unchanged.
